## 하지 않기로 한 것 (2026-08-15 사용자 결정)

목록에 다시 올라와 같은 논의를 반복하지 않도록 **이유까지** 적어 둔다.

| 항목 | 왜 하지 않나 |
|---|---|
| **C5 — 청크 업로드 새로고침 후 이어받기** | 브라우저는 새로고침 뒤 **그 파일을 다시 읽을 수 없다**(`File` 핸들이 새로고침을 넘기지 못한다). 그래서 "자동 이어받기"가 아니라 **사용자가 같은 파일을 다시 골라 주면 남은 조각만 올리는** 것이 된다. 이미 조각 재시도가 붙어 있어 실효가 좁다 — 서버 쪽(상태 조회·멱등 PUT·24시간 세션)은 이미 다 되어 있으므로, 필요해지면 프런트만 붙이면 된다 |
| **캔버스 전역 드롭 — 빈 캔버스에 떨어뜨리면 새 노드** | 필요 없다고 판단(2026-08-15 사용자) |
| **되돌리기 스택 IndexedDB 영구 보관** | ⑴ **2026-07-31 결정과 어긋난다** — 되돌리기는 "이 편집 세션 한정"으로 정했다([12-history-undo-redo.md](../03-editor-core/history/12-history-undo-redo.md)) ⑵ 그 용도는 **저장 버전 이력**이 이미 덮는다 — 둘 다 두면 사용자가 어느 쪽을 써야 할지 알 수 없다 ⑶ 지금 99단계가 싼 이유는 스냅샷이 **메모리에서 구조를 공유**하기 때문인데 **직렬화하면 그 공유가 깨져** 전체 문서 99벌이 된다. 문서에는 이미지가 data URL 로 들어 있어 브라우저 저장소를 금방 밀어낸다 |
