### 0. 결론 — 지금의 저장 모델 (2026-08-06 확정)

> §7 은 여기까지 온 **경위**를 시간순으로 남긴 기록이다. **지금 어떻게
> 동작하는지**만 알고 싶으면 이 절만 읽으면 된다.

#### 0.1 두 겹으로 나눠 생각한다

| | 무엇을 하나 | 언제 |
| --- | --- | --- |
| **① 로컬 초안** (IndexedDB) | **유실 방어를 전담한다** | 노드 추가·삭제 = **즉시** · 타이핑 = 1초 · 화면 이탈 = **즉시** |
| **② 서버 저장** | 다른 기기에서 열기 · 영구 보관 | 아래 0.2 |

**핵심**: ①이 안전을 맡기 때문에, ②의 타이밍은 더 이상 안전 문제가
아니라 **트래픽·반영 속도 문제**다. 그래서 실시간 저장을 없앨 수 있었다.

> **"서버가 뒤처지면 다른 기기에서 문제되지 않나"** — 되지 않는다.
> **단일 세션 편집 잠금**(§5.3) 때문에 한 맵은 한 세션만 편집할 수 있고,
> 다른 기기는 **읽기 전용**으로 열린다. 편집 중인 세션이 정상적으로
> 끝나면(맵 닫기·창 닫기) 그 직전 안전 시점에 서버로 나가므로 다음
> 기기는 최신을 본다. 뒤처짐이 실제로 보이는 경우는 **첫 세션이 비정상
> 종료돼 잠금 TTL(60초)이 만료된 뒤**뿐이다 (§0.5 2번).

#### 0.2 서버에 언제 쓰나 (네 가지)

| 시점 | 히스토리 버전 |
| --- | --- |
| **☁ 저장 · 맵 닫기 · 다른 이름으로 저장** | **남긴다** |
| **주기 자동저장** — 맵 설정 ▸ 저장 (3·5·10분, 기본 5분) | 안 남김 |
| **미저장 편집 50개**가 쌓이면 (주기 전이라도) | 안 남김 |
| **탭 전환 · 창 닫기 · 오프라인→복귀** 순간 | 안 남김 |

* **디바운스(1.5초)·maxWait(5초)는 없다** — 2026-08-06 폐지.
* 마지막 줄은 주기가 아니라 **사건**이라 트래픽이 사실상 0인데 유실
  방어 효과가 가장 크다.
* 자동저장은 **`keepVersion: false`** — 히스토리는 사용자가 매듭지은
  시점에만 생긴다.

#### 0.3 "편집"의 경계

**"다시 만들어야 하는 것"은 포함, "다시 보면 되는 것"은 제외.**

| 편집이다 (되돌리기 ○ · 저장 ○) | 편집이 아니다 |
| --- | --- |
| 노드 추가·삭제·이동·복사/붙여넣기·텍스트 | 노드 선택 |
| 노트(모든 블록) · 첨부 · 링크 · 사진 | 확대/축소 · 이동(Pan) |
| 스타일(색·굵기·기울임·테두리·도형·글자 크기) | 패널 열기/접기 · 검색어 |
| 아이콘 · 태그 · 정렬(노드 안 텍스트) · 노드 크기 | 아웃라인/칸반 보기 전환 |
| **좌우**(`side` — 방사형·양쪽의 배치) | **접기 · 펴기** |
| 레이아웃 · 간격 · 맵 설정 · 맵 이름 | |

* **좌우는 포함, 접힘은 제외** — 좌우는 사용자가 드래그로 정한 배치라
  잃으면 다시 만들어야 하고, 접힘은 다시 보면 되는 화면 상태다.
* 접힘 값 자체는 문서에 남는다(다른 편집이 저장될 때 함께). 접기/펴기
  **만** 해서는 저장도 되돌리기도 일어나지 않는다.

#### 0.4 배지가 말하는 것

| 배지 | 뜻 |
| --- | --- |
| `저장됨 · 3분 전` | 서버에 있는 시점 |
| `미저장 편집 12개` | 아직 서버에 없는 편집 수 (툴팁에 상세 안내) |
| `저장 중…` | PUT 진행 중 |
| `저장 실패 — 재시도 중…` | 1·3초 재시도 |
| `저장 실패 — ☁ 저장을 눌러 주세요` | 계속 실패 (뒤에서 30초마다 재시도는 이어진다) |
| `저장 안 됨 — ☁ 저장을 눌러 주세요` | 서버에 연결되지 않은 문서 (미저장 새 맵·Local 파일·편집권 상실) |

#### 0.5 유실 위험 — 최종

| # | 위험 | 상태 |
| --- | --- | --- |
| R1 | 저장 직전 크래시·전원 차단 | **해결** — 구조 변경 즉시 · 이탈 즉시 초안 → 다음 실행에 복구 배너 |
| R2 | 오프라인·서버 장애 지속 | **해결** — 1·3·10·30초 **무기한** 재시도 + `online` 즉시 재개 |
| R3 | 편집권 상실 후 계속 편집 | **해결** — 초안 기록 → 연결 해제 → ☁ 저장이 새 이름의 새 맵으로 |
| R4 | 자동저장으로 지운 내용 | 히스토리는 명시 저장에서만(사용자 결정) + 세션 되돌리기 99단계 |
| R5 | 로컬 첨부 `blob:` | **의도된 제약** — 원본이 사용자 PC 에 있다 |
| R6 | 모바일 백그라운드 정지 | **해결** — hidden 시점 즉시 발사 |
| R7 | 시크릿 모드(IndexedDB 차단) | **감지·안내** — 앱이 할 수 있는 것이 없으므로 숨기지 않는다 |
| R8 | 저장소가 **도중에** 꽉 참 | **감지·안내**(§7.11) — 예전에는 조용히 실패했다 |

**남는 노출은 두 가지뿐이고, 둘 다 사용자가 알 수 있다.**

1. **타이핑 도중의 예고 없는 전원 차단** — 한 노드의 미완성 문장 일부.
2. **첫 세션이 비정상 종료된 뒤 다른 기기에서 열면 최대 주기(기본 5분)
   만큼 뒤처짐.** 조건이 좁다 —
   * 첫 세션이 **살아 있으면** 다른 기기는 **읽기 전용**으로 열린다
     (단일 세션 편집 잠금 §5.3) → 뒤처진 내용을 고칠 일 자체가 없다.
   * 첫 세션이 **맵 닫기·창 닫기로 정상 종료**하면 그 직전 안전 시점에
     서버로 나가므로 뒤처짐이 **없다**.
   * 크래시·전원 차단·뚜껑 덮기·네트워크 끊김으로 **하트비트가 끊긴 뒤
     TTL 60초가 지나야** 다른 기기가 편집 모드로 열 수 있고, 그때만
     최대 주기만큼 뒤처진다. 원래 기기를 열면 복구 배너로 되살릴 수
     있고, 복구본은 ☁ 저장 시 **새 맵**으로 가므로 다른 기기가 저장한
     것을 덮어쓰지 않는다.

> **"100%"라고는 말하지 않는다.** 논리가 아니라 경험 때문이다 — 지금까지
> 유실 4건이 모두 *예상하지 못한 경로*였다. 알려진 경로는 각각 재현
> 테스트(e2e105~e2e112)로 막았고, 모르는 경로가 나오면 그때도 추측이
> 아니라 **재현부터** 한다.

### 1. 기능 목적

* 사용자 편집 내용을 **전체 문서 스냅샷으로 자동 저장(Autosave)** 하는 기능
* 편집 중 브라우저 종료·네트워크 오류 발생 시 데이터 손실 최소화
* 프런트 문서 모델(이미지·노트·스타일을 통째로 담은 스냅샷) 그대로를 `PUT /maps/:id/document` 로 저장 — patch 분해 없이 단순·견고
* 주기 자동저장 + 안전 시점 + 로컬 초안(IndexedDB)으로 성능과 안전성을 동시에 확보

> 원안의 "Patch 기반 변경분 전송" 설계는 **미채택** — 스냅샷 방식이
> 프런트 모델과 1:1 이라 채택했다. patch 경로는 정규화 노드(협업용)
> 설계로만 남아 있다.

### 2. 기능 범위

* 포함:
  * 스냅샷 자동 저장 (주기 3·5·10분 + 편집 50개 + 탭 전환·창 닫기·온라인 복귀)

### 4. 기능 정의 (What)

#### 4.1 저장 전략

| 어디에            | 언제 (2026-08-06 개편 — §7.9) |
| -------------- | ------------- |
| **브라우저**(IndexedDB 초안) | 노드 추가·삭제 = **즉시** · 타이핑 = 1초 · 화면 이탈 = **즉시** |
| **서버** | ① 자동저장 주기(개인 설정 3·5·10분, 기본 5분) ② **미저장 편집 50개** ③ **탭 전환·창 닫기·온라인 복귀** ④ ☁ 저장·맵 닫기·다른 이름(= 히스토리 버전) |

> **디바운스는 없다.** 2026-08-05 까지는 "손을 멈춘 뒤 1500ms"(+ 최대
> 5초)마다 전체 스냅샷을 올렸는데, 사진이 든 맵은 수 MB 라 10분 편집이면
> 수백 번 × 수 MB 가 오갔다. §7.8 로 **로컬 초안이 유실을 전담**하게 된
> 뒤 실시간 저장을 없앴다 (§7.9).
>
> **"편집"의 정의** = *다시 만들어야 하는 것*을 바꾸는 변경 — 노드 구조·
> 텍스트·**노트**·**첨부**·링크·사진·**스타일**·아이콘·태그·정렬·크기·
> **좌우**·**레이아웃**·**간격**·맵 설정·맵 이름. *다시 보면 되는 것*
> (선택·줌·패널·검색어, 그리고 **접기/펴기**)은 세지 않는다 — 전체 표는
> §7.10.

#### 4.2 저장 요청 구조 (실제)

```typescript
// PUT /maps/{mapId}/document
interface SaveDocumentRequest {
  doc: SampleMap;          // buildSnapshot() 결과 — 전체 문서 스냅샷
  title?: string;          // 맵 제목
  keepVersion?: boolean;   // true = 명시적 저장 → map_document_versions 에 버전 생성
  editSession?: string;    // 편집 세션 키 — 편집 잠금(map_edit_locks) 식별자
}

// 응답
interface SaveDocumentResponse {
  unchanged?: boolean;     // 무변경 스킵 시 true (아무것도 쓰지 않았음)
  // ... 저장 결과 메타
}
```

#### 4.3 buildSnapshot 정규화 (신설)

저장 스냅샷과 로드 결과는 **같은 정규형**이어야 무변경 비교가 성립한다.

* 새 맵/불러온 맵은 `edgeType`·`children` 기본값이 빠진 채 저장돼, 다시
  열면(로드 정규화) 같은 내용인데 jsonb 가 달라 보이는 문제가 있었다
* → `buildSnapshot()` 이 로드와 같은 정규화
  (`normalizeMapForSnapshot` = cloneMap)를 거쳐 저장한다 (e2e90)
* 스냅샷 v2 에는 문서 외에 **editorUi 의 `layoutType`·`spacingX/Y`** 도
  포함된다 — 서버에서 다시 열 때 레이아웃 복원 (e2e85 [3])

> 원안의 patchId 생성 규칙(`p_{timestamp}_{counter}`)은 patch 경로 전용
> 설계로 미사용.

### 5. 동작 방식 (How)

#### 5.1 사용자 동작

* 편집 발생 시 자동 저장 (별도 동작 불필요)
* 툴바 배지에서 저장 상태 실시간 확인
* ☁ 저장 / 맵 닫기 / 다른 이름으로 저장 = 명시적 저장 (버전 생성)
* 저장 오류 시 배지가 error 로 — 다음 편집/저장 시 다시 시도

---

#### 5.2 시스템 처리 흐름

```
사용자 편집
    │
    ▼
documentStore 즉시 메모리 반영 (+ past 스택 push)
    │
    ▼
saveState = 'dirty' (미저장 편집 N개)
    │
    ▼
주기 도달 · 편집 50개 · 탭 전환/창 닫기/온라인 복귀 중 하나
    │
    ▼
buildSnapshot() (normalizeMapForSnapshot 정규화)
    │
    ▼
PUT /maps/{mapId}/document { doc, title, editSession }   ← 자동저장은 keepVersion 없음
    ├─ 소유권·편집 잠금 확인
    ├─ jsonb 등가 비교 → 같으면 unchanged (쓰기 없음)
    └─ map_documents upsert
    │
    ▼
saveState = 'saved' (실패 시 'error')
```

---

#### 5.3 충돌 차단 — 단일 세션 편집 잠금

> 원안의 "baseVersion 3단계 해소(rebase → 사용자 선택 → localStorage
> 백업)"는 미채택. 충돌을 **사후 해소가 아니라 사전 차단**한다.

* 저장 시 `map_edit_locks` 에 편집 세션 잠금 1행 (TTL **60초**, 하트비트 **25초** 갱신)
* 다른 세션(브라우저)이 같은 맵을 열면: 🔒 **읽기 전용** (배너 상시 + 토스트, 서버 링크 없음 → 다른 이름 저장만 유도)
* 다른 세션 키로 직접 PUT: **409** "다른 세션(브라우저)에서 편집 중"
* 잠금 세션이 맵을 닫으면 잠금 해제 → 다른 세션이 편집권 획득 (e2e93)
* **모든 저장 요청은 자기 세션 키(`editSessionKey()`)를 실어야 한다.**
  키 없이 보낸 PUT 은 서버가 "다른 세션이 편집 중"으로 보고 409 로
  거절한다 — 자기 잠금에 자기 저장이 막힌다 (§7.3)

---

#### 5.4 재시도 전략 — **포기하지 않는다** (2026-08-06 개정)

* 자동저장 실패 시 **1초 → 3초 → 10초 → 30초(무기한 반복)** 로 재시도한다
  (`useCloudAutosave.RETRY_DELAYS`)
* **`online` 이벤트가 오면 기다리지 않고 즉시** 한 번 더 보낸다 — 와이파이가
  돌아온 순간 반영된다
* 배지는 처음 2회 동안 `retrying`(= "저장 실패 — 재시도 중…"), 그 뒤에는
  사실대로 `error`(= "저장 실패 — ☁ 저장을 눌러 주세요") **를 유지한 채**
  조용히 재시도를 계속한다 — 재시도한다고 해서 성공을 약속하지는 않는다
* 그동안 편집분은 **로컬 초안**에 남아 있으므로 잃지 않는다 (§7.7·§7.8)
* 맵을 닫거나 다른 맵으로 전환하면(`suppressCloudAutosave`) 예약된
  재시도는 취소한다 — 이전 맵의 재시도가 새 문서를 덮어쓰지 않도록

> 처음에는 재시도가 **없는데도** 배지가 "재시도 중"이라고 말했다(→ 2회
> 재시도 추가). 그다음에는 2회를 다 쓰면 **멈춰** 버려서, 노트북을 덮었다
> 연 뒤 배지를 못 본 사용자는 그대로 유실이었다(2026-08-06 → 무기한).

---

#### 5.5 저장 상태 배지 (실제 6종)

| 상태 (`autosaveStore.saveState`) | 의미                    |
| ---------- | --------------------- |
| `saved`       | 저장 완료 (기본)  |
| `saving`      | PUT 진행 중             |
| `dirty`      | **미저장 편집 N개** — 다음 저장 시점을 기다리는 중 (배지에 숫자를 그대로 보여 준다) |
| `unsaved`      | **서버에 연결되지 않은 문서를 편집함** — 어디에도 저장돼 있지 않다 |
| `retrying`      | 실패 — **재시도 예약됨** (첫 2회: 1초/3초)  |
| `error`      | 계속 실패 — 손으로 ☁ 저장 권장 (뒤에서 30초마다 재시도는 이어진다) |

* 표시는 툴바 배지 하나 — `autosaveStore` 는 이 배지용 `saveState` 1개만 관리한다
* 실패 배지에는 서버가 준 실제 사유를 `title`(툴팁)로 붙인다 — 다음
  보고에서 "왜 실패했는지"를 바로 알 수 있게
* `unsaved` 배지에도 툴팁이 붙는다 — **편집권을 잃어** 연결이 끊긴
  경우(§7.8 ④)와 애초에 서버에 없는 문서를 구분할 수 있게

---

### 6. 규칙 (Rule)

#### 6.1 저장 타이밍 (2026-08-06 개편 — §7.9)
* 자동저장 = **주기**(개인 설정 3·5·10분, 기본 5분) · **미저장 편집 50개** ·
  **탭 전환·창 닫기·온라인 복귀**. `keepVersion` 없음 → **히스토리 버전을 남기지 않는다**
* 명시적 저장(☁·맵 닫기·다른 이름 저장)은 즉시 + `keepVersion: true` →
  **히스토리는 여기서만 생긴다**
* 그 사이 편집은 **로컬 초안**(IndexedDB)이 지킨다 (§7.7·§7.8)

#### 6.2 무변경 스킵
* 서버가 현재 문서와 새 문서를 **jsonb 등가**로 비교 (키 순서 무관)
* keepVersion 이면 **마지막 버전의 doc·title 과도** 비교
* 둘 다 같으면 아무것도 쓰지 않고 `unchanged: true` — 문서·버전·`maps.updated_at` 모두 그대로
* 명시적 저장 버튼은 이때 "변경된 내용이 없어 그대로 두었습니다" 안내 (e2e90)

#### 6.3 멱등성
* patchId/Redis 기반 멱등성은 미사용 — 스냅샷 PUT 은 그 자체로 멱등이고, 무변경 스킵이 중복 쓰기를 막는다

#### 6.4 권한 규칙

* 현재: **소유자 단독** — 소유자의 편집 세션만 저장 가능 (타 사용자 404, 타 세션 409/읽기 전용)
* (계획 — 협업 V1) editor/viewer 역할 구분

### 7. 예외 / 경계 (Edge Case)

* **다른 세션 동시 편집**: 편집 잠금으로 사전 차단 (§5.3) — 읽기 전용 세션의 ☁ 저장은 새 맵(사본) 저장 대화상자
* **저장 실패**: 1·3·10·30초(무기한) 자동 재시도 + `online` 즉시 재개. 2회 이후 배지 error (§5.4)
* **무변경 저장/닫기**: unchanged 스킵 (§6.2)
* **온라인 복귀 시 재전송**: 구현됨 (§5.4)
* **창 닫기·탭 전환 시 즉시 flush**: 구현됨 (§7.8·§7.9 안전 3시점)
* **로컬 임시 백업 + 복구**: 구현됨 — IndexedDB 초안 + 복구 배너 (§7.7·§7.8)

#### 7.1 자동저장 유실 가드 4중 (2026-08-04 실사용 보고)

증상: 저장해 둔 맵(예: AI 답변으로 만든 맵)이 재로그인 후 **'문서 없음'
/중심 주제만** 남는 유실. 재구성한 경로 — ① 편집으로 디바운스 타이머
예약 → ② 맵 닫기·웹AI 새 맵(detach)으로 문서 전환 → ③ 그 사이 진행
중이던 doSave 응답이 **무조건 link() 로 이전 맵 연결을 부활**시키고 →
④ 예약돼 있던 rerun 이 부활한 연결로 **전환 후의 문서(플레이스홀더)를
이전 맵에 저장**. `useCloudAutosave.ts` 에 4중 가드로 봉쇄:

1. **suppressCloudAutosave 가 예약도 취소** — skip 플래그만 세우던 것을
   `clearTimeout(timer)` + `rerun=false` 까지. 전환 직전 예약분이 전환
   후 문서를 쏘지 못한다.
2. **빈 문서·'문서 없음' 플레이스홀더는 자동저장 거부** (doSave 최후
   방어선). 맵을 정말 비우려면 수동 ☁ 저장.
3. **doSave 시작 시 mapId 캡처** — 응답 후 `cloudMapId === mapId` 일
   때만 link/에러 표시/rerun. 닫은 맵의 연결이 부활하지 않는다.
4. **subscribe 에서 skip 소모를 연결 검사보다 먼저** — 미연결 상태의
   변경이 skip 을 소모하지 않아 플래그가 남던 잔존 버그 제거.

검증: e2e96 [3] — 서버 맵 편집(타이머 예약) 직후 웹AI 새 맵 전환,
이전 맵의 `map_documents` 내용·updated_at 무변화 확인.

#### 7.2 서버 가드 — 자동저장은 내용을 지울 수 없다 (2026-08-05)

프런트 가드 4중을 넣은 뒤에도 같은 유실이 재발했다(맵이 1노드·287B로
남음). 클라이언트에서 막는 한 새로운 전환 경로가 생길 때마다 구멍이
날 수 있으므로, **서버가 마지막으로 막는다**:

```
PUT /maps/:id/document
  keepVersion=false(자동저장) AND 새 doc 의 map.branches 가 0개
  AND 기존 doc 의 map.branches 가 1개 이상
    → 쓰지 않고 { unchanged: true } 반환 + 경고 로그
```

**명시 저장(`keepVersion=true` — ☁ 저장·맵 닫기)은 통과시킨다.** 그건
사용자의 뜻이고 히스토리 버전이 남아 되돌릴 수 있다. 반면 자동저장은
버전을 남기지 않아 되돌릴 수단이 없다 — 그래서 "내용이 사라지는
방향"의 자동저장만 거부한다.

프런트도 같은 기준으로 강화했다: `useCloudAutosave` 가 **가지 0개
문서면 요청 자체를 보내지 않는다**(이전에는 제목이 '문서 없음'인
경우만 막아, 제목은 남고 가지만 빈 중간 상태가 통과했다).

검증: `guard5.mjs` — ①자동저장 빈 문서 → 4노드 294B 그대로 ②명시
저장 빈 문서 → 1노드 150B 반영 ③자동저장 내용 있음 → 정상 저장.

복구 안내: 자동저장은 히스토리 버전을 만들지 않으므로, 유실된 맵도
**명시 저장 시점의 버전이 히스토리에 남아 있을 가능성이 높다** —
히스토리 패널에서 해당 버전을 "새 탭으로" 열어 복구한다.

#### 7.11 마지막 사각지대 — 초안 쓰기 실패를 삼키지 않는다 (2026-08-06)

> **"사용자가 인식 못하는 유실은 없는 거지?"** (사용자)

그 질문에 답하려고 경로를 다시 훑다가 **하나 남아 있는 것**을 찾았다.

```
저장소가 꽉 참 (QuotaExceededError) 또는 도중에 차단
  → putDraft() 가 조용히 실패
  → 첫 열기는 성공하므로 §7.8 ⑥의 시작 시 검사(draft-storage-off)는 **통과**
  → 배지는 "미저장 편집 12개" (사실)
  → 사용자는 "브라우저에는 남아 있겠지" 라고 믿는다   ← 거짓
  → 크래시 → 전부 사라짐. **아무 경고도 없었다.**
```

`withStore` 가 모든 실패를 `null` 로 뭉개고 있었고, `putDraft` 는 반환값
자체가 없었다. 이것이 **사용자가 인식하지 못하는 유일한 유실 경로**였다.

##### 고친 것

* `withStore` 가 성공/실패를 구분해 돌려준다(`{ok:true,value} | {ok:false}`).
  **트랜잭션 중단(`onabort`)도 실패로 본다** — 쿼터 초과는 요청이 아니라
  트랜잭션 단계에서 나타나므로 `req.onerror` 만 봐서는 놓친다.
* `putDraft` 가 **성공 여부를 돌려준다**.
* 실패하면 `autosaveStore.draftWriteFailed` 를 세우고 화면에 알린다 —
  **"브라우저 임시 보관에 실패했습니다 · 지금 편집은 이 브라우저에도
  남지 않습니다 — ☁ 저장을 눌러 주세요"** (`draft-write-failed`).
  다시 성공하면 표시가 사라진다.

검증: e2e112 [1]~[3].

##### 그래서 지금 답할 수 있는 것

**"사용자가 모르게 사라지는 것"은 알려진 경로에 더 없다.** 남는 것은
전부 **사용자가 화면에서 보거나, 사건 자체를 겪어서 아는** 경우다.

| 남는 노출 | 사용자가 어떻게 아나 |
| --- | --- |
| 타이핑 중 예고 없는 전원 차단 — 마지막 글자 몇 개 | 전원이 나간 것을 겪고, 다음 실행에 복구 배너로 되살린 뒤 마지막 문장을 눈으로 확인 |
| 시크릿 모드 — 초안 보관 없음 | 첫 화면 `draft-storage-off` 안내 |
| 저장소 꽉 참 — 초안 안 적힘 | `draft-write-failed` 안내 (§7.11) |
| 오프라인 지속 — 서버 반영 지연 | 배지 `error` + 무기한 재시도 + 편집분은 초안에 |
| **다른 기기에서 열면 최대 자동저장 주기(기본 5분)만큼 뒤처짐** | 화면에서 바로 보인다. 원래 기기를 열면 복구 배너로 되살릴 수 있다 |

**여전히 "100%"라고는 말하지 않는다.** 논리가 아니라 경험 때문이다 —
지금까지의 유실 4건은 모두 *예상하지 못한 경로*였고, 그때마다 "이제
막았다"고 생각한 뒤에 다음 것이 나왔다. 알려진 경로는 각각 재현 테스트로
막았고, 모르는 경로가 또 나오면 그때도 재현부터 한다.

#### 7.10 "편집"의 경계 — 접기/펴기는 편집이 아니다 (2026-08-06 사용자 결정)

> **"내용이 중요하지, 맵의 접기·펴기 형태는 안 중요하다"** (사용자)

##### 기준 한 줄

**"다시 만들어야 하는 것"은 포함, "다시 보면 되는 것"은 제외.**

##### 규칙 (저장 · 되돌리기 · 히스토리 한 규칙)

| 행위 | 되돌리기 | 서버 저장 | 히스토리 |
| --- | --- | --- | --- |
| 노드 추가·삭제·이동·복사/붙여넣기·텍스트 | ○ | ○ | ○ |
| **노트**(모든 블록) · **첨부** · 링크 · 사진 | ○ | ○ | ○ |
| **스타일**(색·굵기·기울임·테두리·도형·글자 크기) | ○ | ○ | ○ |
| **아이콘**(`icon`·`iconSide`) · **태그**(`tag`·`tags`) | ○ | ○ | ○ |
| **정렬**(`textAlign` — 노드 박스 **안** 텍스트 좌/가운데/우) | ○ | ○ | ○ |
| **노드 크기**(`sizeW`·`sizeH` — 우하단 핸들로 수동 고정한 값) | ○ | ○ | ○ |
| **좌우**(`side` — 방사형·양쪽에서 중심의 왼쪽/오른쪽 배치) | ○ | ○ | ○ |
| 레이아웃(전역·노드별) · 간격 · 맵 설정 · 맵 이름 | ○ | ○ | ○ |
| **접기 · 펴기**(`collapsed`) | **✕** | **✕**(카운트 안 함) | ✕ |
| 노드 선택 · 확대/축소 · 이동(Pan) · 패널 · 검색어 · 보기 전환 | ✕ | ✕ | ✕ |

##### 왜 좌우(`side`)는 포함이고 접힘은 제외인가

* **좌우**는 사용자가 드래그로 **의도해서 정한 배치**다. 잃으면 맵 모양이
  달라지고 다시 만들어야 한다 → **내용 쪽**.
* **접힘**은 지금 무엇을 보고 있느냐일 뿐이다 → **화면 상태**.

##### 무엇이 고쳐졌나

접기/펴기는 `documentStore.map` 을 바꾸기 때문에 지금까지 **전부 편집으로
취급**됐다. 그래서

* 되돌리기 99단계가 **접기/펴기로 채워져** 정작 되돌리고 싶은 편집이
  밀려났다
* 큰 맵에서 접기/펴기 몇 번이면 미저장 편집이 차서 **불필요한 서버 저장**이
  일어났다

`documentStore` 에 **보기 전용 변경**(`asViewOnly` / `isViewOnlyChange`)을
두고, `toggleCollapse` · `setCollapsed` · `collapseAll` · `expandAll` ·
`expandAncestors` 를 여기로 넘겼다. 되돌리기 구독 · 자동저장 구독 · 로컬
초안 구독이 모두 이 표시를 보고 건너뛴다.

> **접힘 값 자체는 문서에 그대로 남는다** — 다른 편집이 있어 저장이 일어날
> 때 함께 올라가므로, 맵을 다시 열면 접어 둔 대로 보인다. 접기/펴기 **만**
> 해서는 저장이 일어나지 않는다.

##### 히스토리

히스토리 버전은 §7.9 이후 **☁ 저장 · 맵 닫기 · 다른 이름으로 저장**에서만
생긴다. 접기/펴기가 히스토리 버전을 만드는 일은 이미 없다.

##### 알려진 차이 (미구현)

되돌리기 스냅샷은 전역 **레이아웃**은 함께 복원하지만 **간격**(`spacingX`·
`spacingY`)은 복원하지 않는다. 저장·초안에는 둘 다 들어간다. 간격까지
되돌리려면 되돌리기 항목에 간격을 추가해야 한다 — [미구현].

검증: e2e111 [1]~[5].

#### 7.9 저장 모델 개편 — 실시간 저장을 없앤다 (2026-08-06 사용자 결정)

> **"노드 하나 만들 때마다 일일이 서버와 연결 안 해도 되지 않나"** (사용자)

맞는 지적이었다. 저장은 **전체 스냅샷 PUT** 이라 사진이 든 5MB 맵을
10분 집중 편집하면 수백 번 × 수 MB 가 오갔다. 실시간처럼 보이려고 치른
값이 너무 컸다. §7.8 로 **로컬 초안이 유실을 전담**하게 된 이상, 서버
저장 타이밍은 더 이상 안전 문제가 아니라 **트래픽·반영 속도 문제**다.

##### 없앤 것

* **디바운스 1.5초** — 삭제
* **maxWait 5초** — 삭제
* **자동저장의 주기 히스토리 버전**(§7.7 ③) — 삭제. 히스토리는 아래처럼
  **명시 저장에서만** 생긴다.

##### 지금의 저장 시점 (네 가지)

| 언제 | 히스토리 버전 |
| --- | --- |
| **☁ 저장 · 맵 닫기 · 다른 이름으로 저장** | **남긴다** |
| **주기 자동저장** — 개인 설정 3·5·10분 (기본 5분) | 안 남김 |
| **미저장 편집 50개**가 쌓이면 (주기 전이라도) | 안 남김 |
| **탭 전환 · 창 닫기 · 오프라인→복귀** 순간 | 안 남김 |

마지막 줄이 핵심이다 — **주기가 아니라 사건**이라 트래픽이 사실상 0인데
유실 방어 효과는 가장 크다.

##### "미저장 편집 50개" — 왜 용량이 아니라 횟수인가

사용자가 처음 제안한 것은 "변경 **용량** 차이"였는데, 용량은 중요도와
**반대로** 움직인다.

| 편집 | 용량 변화 | 잃으면 |
| --- | --- | --- |
| 문장 한 줄 수정 | 거의 0 | **아프다** |
| 사진 1장 붙여넣기 | +2MB | 원본이 PC 에 있어 다시 하면 된다 |

그래서 **횟수**를 쓴다. 계산도 공짜다(되돌리기 스택이 늘어나는 것과 같다).

##### "편집"의 정의 — 정확히 무엇이 포함되나

**서버에 올라가는 스냅샷을 바꾸는 모든 변경**이다.

| 포함 (센다) | 제외 (안 센다) |
| --- | --- |
| 노드 추가·삭제·이동·복사/붙여넣기 | 노드 **선택** |
| 노드 텍스트 | 화면 **확대/축소·이동(Pan)** |
| **노트**(모든 블록) | 패널 열기/접기 |
| **첨부**·링크·노드 사진 | 검색어 입력 |
| **스타일**(색·굵기·기울임·테두리·도형·글자 크기) | 아웃라인/칸반 **보기 전환** |
| 아이콘·태그·정렬·노드 크기·**좌우** | **접기·펴기** (§7.10) |
| **레이아웃**(전역·노드별)·**간격** | |
| 맵 설정·맵 이름 | |

> **개편 중 발견한 구멍** — 전역 레이아웃과 간격은 `documentStore.map` 이
> 아니라 `editorUiStore` 에 있는데 스냅샷의 `editor` 로 함께 저장된다.
> 여기를 구독하지 않으면 **간격 슬라이더만 만진 변경은 영영 서버에 가지
> 않는다**(주기 저장은 "대기 중인 편집이 있을 때"만 움직이므로).
> 자동저장과 로컬 초안 **양쪽**에 이 구독을 추가했다. 검증 e2e110 [9].

##### 고객에게 사실대로 알린다

배지가 추측을 남기지 않는다.

```
● 저장됨 · 3분 전                ← 서버에 있는 시점
◐ 미저장 편집 12개               ← 아직 서버에 없는 수 (툴팁에 상세 안내)
⚠ 저장 안 됨 — ☁ 저장을 눌러 주세요
```

`dirty` 배지 툴팁: *"아직 서버에 올라가지 않은 편집이 N개 있습니다.
자동저장 주기와 탭 전환·창 닫기 때 올라갑니다. 그 사이 편집은 이
브라우저에 보관되지만, **PC 가 강제 종료되면 서버에는 반영되지
않습니다**."* 맵 설정 ▸ 저장 에도 같은 설명을 적었다.

##### 되돌리기 — "이 상태를 최신(0)으로"

되돌리기로 -5 까지 간 뒤 **아무 편집이나 하면** 다시 실행 5단계가 버려지고
그 지점이 새 0 이 된다(표준 동작, `documentStore` 구독의 `future: []`).
그런데 **편집할 것은 없고 확정만 하고 싶을 때** 방법이 "맵을 닫았다 열기"
뿐이었다. 이제 **되돌리기 단계 배지(`-5`)를 누르면** 그 상태가 최신이 된다
(`commitCurrentAsLatest`). 검증 e2e110 [8].

검증: e2e110 [1]~[9].

#### 7.8 남은 구멍을 끝까지 막는다 — R3·R6·"마지막 1초" (2026-08-06)

§7.7 뒤에 남아 있던 것을 전부 처리했다. **"저장 안 되면 협업에서 더
꼬인다, 이번에 100% 정리하자"**(사용자)에 따른 마무리다.

##### 저장 타이머 4개 — 무엇이 무엇인지 *(이 절은 2026-08-06 §7.9 로 대체되었다 — 디바운스·maxWait 은 삭제)*

혼동이 잦아 여기에 정리해 둔다. **성격이 다른 4개**다.

| 타이머 | 어디에 쓰나 | 언제 |
| --- | --- | --- |
| **로컬 초안** | **이 브라우저**(IndexedDB) | 노드 추가·삭제 = **즉시** · 타이핑 = 1초 · 화면 이탈 = **즉시** |
| **디바운스 1.5초** | 서버 | 손을 멈춘 뒤 1.5초 *(§7.9 에서 삭제됨)* |
| **maxWait 5초** | 서버 | 손을 안 멈출 때의 **지연 상한** |
| **버전 간격 3·5·10분** | 서버(히스토리 **버전**) | 위 저장 중 그 간격에 1개만 버전으로 박제 |

**디바운스와 maxWait 을 둘 다 두는 이유**는 서로 반대 방향의 문제를
막기 때문이다 — 디바운스는 "글자마다 보내지 마"(브레이크), maxWait 은
"그렇다고 영원히 미루지도 마"(안전핀). 하나로 합치면(예: 3초 스로틀만)
평소 저장이 1.5초 → 3초로 느려지고, 타이핑 중 전송은 5초 → 3초로 잦아진다
(사진 내장 맵은 스냅샷이 수 MB). **그리고 이제 서버 저장 타이밍은 유실과
무관하다** — 유실 방어는 아래 로컬 초안이 전담한다.

##### ① "마지막 1초"를 없앴다

초안을 1초 디바운스로만 적으면 그 1초 안의 편집은 남지 않는다.

* **노드 수가 바뀌면 즉시 적는다** — 추가·삭제·붙여넣기·이동. 드물게
  일어나고 잃으면 가장 아프다. 타이핑만 1초 디바운스를 쓴다.
* **화면에서 벗어나는 순간 즉시 적는다** — `visibilitychange`(hidden)·
  `pagehide`. 탭 전환·앱 전환·창 닫기·모바일 백그라운드 진입이 모두 여기
  걸린다. 이 시점엔 페이지가 아직 살아 있어 IndexedDB 쓰기가 끝난다.
* **이미 서버에 다 들어간 문서는 적지 않는다** — 아니면 탭을 옮길 때마다
  "저장되지 않은 맵이 있습니다"가 떠서 진짜 경고와 구분이 안 된다.

##### ② R6 — 백그라운드 탭에서 저장이 밀리던 문제

백그라운드 탭에서는 브라우저가 타이머를 1분 이상 늦추거나 멈춘다.
`visibilitychange`(hidden)에서 **예약을 기다리지 않고 즉시 보낸다**
(`flushCloudAutosave`).

##### ③ R2 — 이제 포기하지 않는다

예전에는 2회 실패하면 멈추고 "손으로 ☁ 저장하세요"로 넘겼다. 노트북을
덮었다 열거나 와이파이가 잠깐 끊긴 흔한 상황에서, 배지를 못 보면 그대로
유실이었다.

* 재시도 간격 `1초 → 3초 → 10초 → 30초(무기한 반복)`
* `online` 이벤트가 오면 기다리지 않고 **즉시** 한 번 더
* 배지는 2회 실패 이후 사실대로 `error`("저장 실패") 유지 — 조용히
  재시도한다고 해서 성공을 약속하지는 않는다

##### ④ R3 — 편집권을 잃었을 때 실제로 구제한다

예전에는 안내만 하고 연결을 남겨 뒀다. 자동저장은 409 로 계속 튕기고,
사용자는 계속 편집했고, 그 편집분이 사라졌다. 이제 하트비트가
`held=false` 를 받으면:

1. **지금 내용을 먼저 초안에 적고**
2. `detachFromServer()` 로 그 맵과의 연결을 끊고
3. 배지를 `unsaved`("저장 안 됨")로, 사유를 배지 툴팁에 남긴다

이후 편집은 초안에 계속 쌓이고, ☁ 저장을 누르면 **새 이름의 새 맵**으로
간다. 잃는 편집이 없다.

##### ⑤ 복구 배너 — 여러 건·복구 후 재보관

* 초안이 여러 건이면 **한 건씩 차례로** 묻는다("외 N건"). 예전에는 가장
  최근 1건만 보여 주고 나머지는 영영 남았다.
* **복구한 내용은 다시 초안으로 남는다** — 복구 직후 창을 닫아도 잃지
  않는다. 배지는 `unsaved` 로 세운다(아직 어디에도 저장돼 있지 않으므로).

##### ⑥ IndexedDB 를 못 쓰는 브라우저를 알린다

사생활 보호(시크릿) 모드·저장소 차단이면 초안 보관이 **통째로 없다.**
조용히 넘어가면 사용자는 보호받고 있다고 오해한다 — 첫 화면에 알린다
(`data-testid="draft-storage-off"`).

검증: e2e109 [1]~[7].

#### 7.7 로컬 초안 백업 + 무한 미뤄짐 방지 + 주기적 버전 (2026-08-05)

§7.6 의 R1·R2·R4 를 실제로 막는 3종.

##### ① 디바운스에 **최대 대기 한도**가 없었다 (새로 찾음)

디바운스는 "손을 멈춘 뒤 1.5초"다. 그런데 편집이 이어지면 타이머가
**매번 리셋**돼 저장이 **무한정 미뤄진다**.

```
0.0초 편집 → 1.5초 뒤 저장 예약
1.0초 편집 → 예약 취소, 다시 1.5초 뒤로
2.0초 편집 → 예약 취소, 다시 1.5초 뒤로
   … 이런 편집이 이어지는 동안 서버에는 아무것도 가지 않는다
```

간격 슬라이더를 30초 드래그하거나 노드를 1초 간격으로 계속 추가하면
그 시간 내내 미저장이다. 그 순간 크래시가 나면 **전부** 사라진다.
→ **첫 변경으로부터 5초**가 지나면 편집 중이어도 한 번 저장한다
(`MAX_WAIT_MS`). 최악의 미저장 구간이 "무제한"에서 "5초"로 바뀐다.

##### ② 로컬 초안 백업 (IndexedDB, 1초)

편집 1초 뒤마다 문서 전체를 브라우저에 적어 둔다(`utils/localDraft.ts`).
다음에 앱을 열면 **"저장되지 않은 맵이 있습니다 — 복구할까요?"** 배너로
되살린다. 크래시·전원 차단·오프라인·미저장 새 맵을 한 번에 덮는다.

* **왜 IndexedDB 인가** — localStorage 는 **동기**라 쓰는 동안 화면이
  멈추고, 도메인당 **약 5MB** 상한이라 사진이 내장된 맵은 곧 넘친다
  (백업 자체가 실패). IndexedDB 는 비동기 + 대용량이라 이 용도에 맞다.
* **왜 0.3초가 아니라 1초인가** — 맵 스냅샷은 사진이 있으면 수 MB다.
  0.3초 간격 직렬화는 타이핑 중 프레임을 갉아먹는다. 1초면 최악의
  유실이 "마지막 1초"로 제한되고 체감 차이가 없다.
* 서버 저장에 성공하면 그 맵의 초안은 **지운다**(중복 안내 방지).
* 복구한 문서는 **서버와 연결하지 않는다** — 어느 맵에 넣을지는 사용자가
  ☁ 저장에서 정한다(엉뚱한 맵을 덮어쓰지 않도록).

##### ③ 자동저장도 주기적으로 **버전**을 남긴다 (개인 설정 3·5·10분)

자동저장은 히스토리 버전을 남기지 않아, 자동저장으로 지워진 내용은
세션 되돌리기 말고 복구 수단이 없었다(R4). 이제 개인 설정 간격마다
한 번은 `keepVersion: true` 로 보낸다 — 기본 **5분**, 맵 설정 패널의
**저장 (개인 설정)** 에서 3·5·10분 중 고른다.

검증: e2e108 [1]~[5].

#### 7.6 남은 유실 위험 — **"100% 안전"이라고 말하지 않는다** (2026-08-05)

방어선을 여러 겹 쌓았지만 **유실 확률이 0 이 되지는 않았다.** 남아 있는
경우를 숨기지 않고 적는다.

**먼저 두 가지를 구분한다.**

| 종류 | 내용 | 지금 |
| --- | --- | --- |
| **(가) 이미 서버에 저장된 것이 앱의 실수로 지워지거나 남의 맵에 덮어써짐** | §7.1~§7.5 (9겹 방어) | **막았다. 각각 재현 테스트가 있다** |
| **(나) 아직 서버에 못 간 편집** | 마지막 몇 초 · 오프라인 · 미저장 새 맵 | 아래 표 |

**(나) 남은 위험 — §7.8·§7.9 반영 후 상태 (2026-08-06)**

| # | 위험 | 언제 일어나나 | 지금 상태 | 실제로 잃는 것 |
| --- | --- | --- | --- | --- |
| **R1** | 저장 직전에 브라우저·PC 가 강제 종료 | 크래시 · 전원 차단 (`beforeunload` 는 정상 종료에서만 뜬다) | **해결됨** — 구조 변경 즉시 · 타이핑 1초 · 화면 이탈 즉시 IndexedDB 초안 | **타이핑 중이었다면 마지막 글자 몇 개** |
| **R2** | 저장 실패가 계속됨 | 오프라인 · 서버 장애 · 쿼터 초과 | **해결됨** — 무기한 재시도(최대 30초 간격) + `online` 즉시 재시도. 그동안 편집분은 초안에 남는다 | 없음 |
| **R3** | 편집권을 잃은 채 계속 편집 | 같은 맵을 **다른 창/기기**가 가져감 | **해결됨** — 초안 기록 → 연결 해제 → 배지 `unsaved`. ☁ 저장이 **새 이름의 새 맵**으로 간다 | 없음 (그 맵에는 반영되지 않는 것이 정상) |
| **R4** | 자동저장으로 **지운** 내용을 되살리고 싶다 | 노드 삭제 후 시간이 지나 세션 undo 로 못 감 | **부분** — 히스토리는 ☁ 저장·맵 닫기에서만 남긴다(§7.9 사용자 결정). 그 사이는 세션 되돌리기 99단계 | **마지막 명시 저장 이후**의 중간 상태 |
| **R5** | 로컬 첨부(`blob:`)가 세션 종료 후 깨짐 | 파일을 서버에 올리지 않고 링크만 잡은 맵 | **의도된 제약** (2026-08-05 사용자 결정) — 원본 파일은 사용자 PC 에 있다 | 맵 내 미리보기 링크만 |
| **R6** | 탭이 백그라운드에서 정지 | 모바일 등에서 앱 전환 | **해결됨** — `visibilitychange`(hidden) 에서 초안·자동저장을 **즉시** 보낸다 (§7.9 의 안전 3시점 중 하나) | 없음 |
| **R7** | 브라우저가 IndexedDB 를 막음 | 사생활 보호(시크릿) 모드 · 저장소 차단 | **감지·안내** — 첫 화면에 "임시 보관을 쓸 수 없습니다" | 초안 보호가 통째로 없다 (서버 저장만 남는다) |
| **R8** | 저장소가 **도중에** 꽉 참 | 디스크·쿼터 초과 — 시작 시 검사는 통과한다 | **감지·안내** (§7.11) — 예전에는 조용히 실패했다 | 알린 뒤부터는 없다 |

**남은 실제 노출은 두 가지뿐이다.**

1. **타이핑 도중의 예고 없는 전원 차단** — 마지막 글자 몇 개. 완료된
   편집(노드 추가·삭제·이동·붙여넣기)과 화면을 벗어나는 모든 경로는
   즉시 기록되므로, 여기서 잃는 것은 **한 노드의 미완성 문장 일부**다.
   이보다 줄이려면 글자마다 수 MB 스냅샷을 써야 해 타이핑이 끊긴다.
2. **R7 — 시크릿 모드** — 브라우저가 저장소를 막으면 앱이 할 수 있는 것이
   없다. 그래서 **숨기지 않고 화면에 알린다.**

**서버 반영 지연**은 §7.9 개편 이후 **최대 자동저장 주기(기본 5분)**
이며, 탭 전환·창 닫기에서는 즉시다. 이 값은 **유실과 무관하다** — 안전은
로컬 초안이 맡고, 주기는 서버 반영 속도와 트래픽을 조절하는 손잡이다.
디바운스 1.5초·maxWait 5초는 **없어졌다**.

##### 이번에 함께 고친 것 — "저장 안 됨"을 정직하게 말한다

감사 중 실측한 구멍: **서버에 연결되지 않은 문서**(미저장 새 맵 · Local
파일로 불러온 맵 · 읽기 전용으로 연 맵)를 편집하면 자동저장 대상이
아닌데도 배지가 계속 `saved`("저장됨")였다. 5회 편집 후에도 그랬다.
사용자는 저장된 줄 알고 탭을 닫고, 편집은 통째로 사라진다.

* 배지에 `unsaved` 상태 추가 — "저장 안 됨 — ☁ 저장을 눌러 주세요"
* 잃을 것이 없는 빈 문서는 그대로 `saved` (첫 화면 거짓 경고 없음)
* 편집 이력이 있는 `unsaved` 상태에서 창을 닫으려 하면 **브라우저가 묻는다**
* 하트비트가 `held=false`(편집권 상실)를 받으면 **조용히 넘어가지 않고**
  배지 `error` + 안내 (예전에는 응답을 아무도 보지 않았다)

검증: e2e107 [1]~[4].

#### 7.5 저장 경로 전수 감사 — "출처가 다르면 저장하지 않는다" (2026-08-05)

세 번째 유실 뒤 **서버에 쓰는 경로와 문서를 통째로 바꾸는 경로를 모두
훑었다.** 그 결과 유실 경로가 **하나 더** 나왔고, 재현했다.

**② 엉뚱한 맵에 다른 문서가 저장된다**

```
서버 맵('통계B-중간') 열기
  → AI 새 맵 생성 (AITab, API 키 모드)
      = loadMap 만 하고 detachFromServer 를 부르지 않았다
  → 1.5초 뒤 자동저장
      = '통계B-중간' 문서가 **AI 맵으로 통째로 바뀐다**   ← 실측
```

웹 AI 경로(WebAiPanel)는 처음부터 detach 를 부르고 있었는데, API 키
경로만 빠져 있었다. **호출부를 하나씩 고치는 방식의 한계**가 그대로
드러난 사고다 — 새 경로가 생길 때마다 같은 실수가 가능하다.

**그래서 구조로 막는다 — 문서에 "출처"를 적는다.**

| 무엇 | 어떻게 |
| --- | --- |
| `documentStore.docOrigin` | 이 문서가 **어느 서버 맵에서 온 것인가**. 기본값 `null`(출처 없음) |
| 설정되는 곳 | 서버 맵 열기(`openMapHere`) · 서버 저장 성공(`saveCurrentMap`·`saveNewMap`) |
| 지워지는 곳 | `loadMap`(기본) · `newMap` · `closeMap` · `setSample` · `detachFromServer` |
| 유지되는 곳 | 템플릿 적용 — `loadMap(map, { keepOrigin: true })` (같은 문서에 스타일만) |
| 검사 | 자동저장이 `docOrigin !== cloudMapId` 면 **아예 보내지 않는다** |

기본값이 "출처 없음"이므로, **앞으로 새 경로가 생겨도 그 문서가 남의
맵에 저장되는 일은 없다**(저장하려면 명시적으로 출처를 세워야 한다).
AITab 의 빠진 `detachFromServer()` 도 함께 고쳤다.

**③ 창을 닫을 때 마지막 1.5초** — 자동저장은 1500ms 디바운스라 그
사이에 탭을 닫으면 마지막 편집이 사라진다. 지금까지 아무 경고도 없었다.
이제 저장 대기(`dirty`/`saving`/`retrying`/`error`) 상태에서 창을 닫으려
하면 **브라우저가 한 번 묻는다**(`beforeunload`). beforeunload 에서
비동기 저장은 취소되므로, 저장을 대신 하는 대신 사용자에게 결정권을 준다.

검증: e2e106 [1][2] · e2e105(3중 방어 회귀).

#### 7.4 맵이 통째로 비워진 세 번째 유실 — 3중 방어 (2026-08-05)

증상은 "또 맵이 저장 안 된다" — 열어 보면 이름은 그대로인데 캔버스에
'문서 없음' 한 노드만 남아 있었다.

**재현 경로 (실측)**

```
서버 맵 열기 (가지 3)
  → Ctrl+Z 를 "연 시점보다 더 뒤로" 여러 번
      = 열기 이전 문서('문서 없음' 자리표시)가 현재 문서가 된다
        (서버 맵과는 여전히 연결된 채!)
  → ☁ 저장
      = 그 빈 문서가 서버 맵을 덮어쓴다   ← DB 가지 3 → 0
```

자동저장은 §7.2 가드가 막고 있었지만, **명시 저장은 "사용자의 뜻"이라며
통과**시키고 있었다 — 사용자는 비울 뜻이 없었다.

**막는 곳을 셋으로 늘렸다.**

| 층 | 무엇을 |
| --- | --- |
| ① 되돌리기 | `loadMap(map, { resetHistory: true })` — **문서를 여는 것은 경계**다. 서버 맵 열기·파일 불러오기에서 undo 히스토리를 끊어, Ctrl+Z 가 '열기 이전' 문서로 넘어가지 못한다 (템플릿 적용처럼 같은 문서를 바꾸는 경우는 그대로 되돌아간다) |
| ② 저장 직전 확인 | 가지가 0개인 문서를 저장하려 하면 **먼저 묻는다** — "되돌리기를 너무 많이 눌렀다면 [취소] 후 Ctrl+Y" 안내 포함. ☁ 저장·맵 닫기 모두 같은 경로(`saveCurrentMap`) |
| ③ 서버 | 빈 문서가 내용 있는 맵을 덮어쓰는 저장은 **자동·명시 구분 없이 거부**. 프런트가 사용자의 확인을 받아 `allowEmpty: true` 를 실을 때만 통과 |

즉 **"맵을 비우는 저장"은 사용자가 그렇게 답한 경우에만 일어난다.**

검증: e2e105 [1]~[4] · guard5.mjs ②/②b.

> 복구: 명시 저장은 히스토리 버전을 남기므로, 이미 비워진 맵도
> **히스토리 패널에서 직전 버전을 새 탭으로 열어** 되살릴 수 있다.

#### 7.3 자동저장이 자기 잠금에 막혀 전부 409 (2026-08-05, 수정)

증상은 "되돌리기(Ctrl+Z) 중 우상단에 **저장 실패** 배지가 뜬다"였다.
재현해 보니 되돌리기와는 무관했고, **자동저장 PUT 이 예외 없이 409**
로 거절되고 있었다.

원인: 맵을 열면 그 탭이 편집 잠금을 획득한다(§5.3). 그런데
`useCloudAutosave.doSave()` 만 `cloudApi.saveDocument()` 에 **편집 세션
키를 넘기지 않았다**. 서버는 키 없는 요청을 "잠금을 쥔 세션과 다른
세션"으로 판정해 409 로 막았다 — 자기가 쥔 잠금에 자기 저장이 막힌
꼴이다. 명시 저장(`saveCurrentMap`·`saveNewMap`)은 처음부터 키를 싣고
있었기 때문에 **☁ 저장만은 잘 되는** 것이 증상을 오래 가렸다.

수정: 세션 키 함수를 `services/cloud/editSession.ts` 로 분리하고
(mapSession → useCloudAutosave 방향의 import 순환을 피하려고),
자동저장도 `saveDocument(mapId, snapshot(), title, false, editSessionKey())`
로 키를 싣는다.

검증: e2e102 [5] — 편집·되돌리기 뒤 배지가 `saved` 로 끝나고
`/document` 409 가 0건.

> 참고: 되돌리기를 **문서를 연 시점보다 더 뒤로** 밀면 가지 0개
> 상태가 되고, 그때는 §7.2 가드가 자동저장을 보내지 않아 배지가
> `dirty` 로 남는다 — 의도된 동작이다(내용을 지우는 방향의 자동저장
> 금지). 그 상태를 서버에도 반영하려면 명시 ☁ 저장을 쓴다.

### 12. 서버 저장 처리 세부 단계 (실제)

`PUT /maps/{mapId}/document` 수신 시 서버는 아래 7단계를 수행한다.

```
PUT /maps/{mapId}/document { doc, title, keepVersion, editSession, allowEmpty }
        │
        ▼
1. 소유권 확인 — 소유자가 아니면 404
        │
        ▼
2. 편집 잠금 확인 (map_edit_locks)
   다른 세션이 유효 잠금 보유 → 409 "다른 세션(브라우저)에서 편집 중"
   내 세션이면 잠금 생성/하트비트 갱신 (TTL 60초)
        │
        ▼
2-1. **빈 문서 덮어쓰기 거부** — 새 doc 의 가지 0개 + 기존 doc 가지 ≥1
   이면 `allowEmpty` 없이는 쓰지 않고 { unchanged: true } (§7.4)
        │
        ▼
3. jsonb 등가 비교 (키 순서 무관)
   현재 문서와 동일 + (keepVersion 이면) 마지막 버전과도 동일
   → 아무것도 쓰지 않고 { unchanged: true } 반환
        │
        ▼
4. 저장 쿼터 확인 — 초과 시 거부 (413 계열 안내)
        │
        ▼
5. map_documents upsert (전체 스냅샷)
        │
        ▼
6. maps.title / updated_at 갱신
        │
        ▼
7. keepVersion: true 이면 map_document_versions INSERT
   (version = MAX(version)+1, layout_type·node_count·attach_bytes·attach_count 기록)
```

> 원안의 서버 단계(Redis SET NX 멱등성 → baseVersion 409 → patch 적용 →
> orderIndex 재정규화 → Redis 스냅샷 캐시 무효화 → WebSocket 협업
> 브로드캐스트)는 정규화 노드/협업 경로 설계로, 문서 저장 경로에서는
> 쓰지 않는다. 협업 V1 설계 시 재검토한다.

### 13. 저장 상태 전체 표시 목록 (실제)

| 상태         | 표시                          |
| ---------- | --------------------------- |
| `saved`       | 저장 완료 배지      |
| `saving`      | 저장 중 배지               |
| `dirty`      | 변경 있음 (디바운스 대기) 배지        |
| `retrying`      | "저장 실패 — 재시도 중…" 배지 (실패 사유 툴팁) |
| `error`      | "저장 실패 — ☁ 저장을 눌러 주세요" 배지 (실패 사유 툴팁) |

> 원안의 Offline / Conflict 표시는 해당 기능(오프라인 큐·충돌 해소)이
> 미채택/미구현이라 존재하지 않는다. 충돌은 읽기 전용 배너(🔒)로
> 사전에 안내된다. Retrying 은 2026-08-05 에 실제 재시도와 함께 생겼다
> (그 전에는 재시도가 없는데 `error` 배지가 "재시도 중"이라고 말했다).
