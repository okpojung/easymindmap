## 1. 어디에 있나 — `/admin`

`https://dev.mindmap.ai.kr/admin`.

**라우터를 들이지 않았다.** 이 앱에는 라우터가 없었고(에디터 하나뿐),
관리자 화면 하나 때문에 넣으면 에디터의 `?map=` 처리와 규칙이 둘로
갈린다. `main.tsx` 가 경로 하나만 본다.

```ts
const isAdmin = window.location.pathname.replace(/\/+$/, '') === '/admin';
```

프런트엔드 nginx 가 이미 SPA 폴백(`try_files $uri $uri/ /index.html`)을
하므로 **서버 설정을 바꾸지 않아도** 이 파일까지 온다.

### 운영 전환 때 분리한다 (사용자 결정)

| | 지금 (개발) | 운영 전환 시 |
|---|---|---|
| 주소 | `dev.mindmap.ai.kr/admin` | **`admin.easymindmap.org`** |
| 인프라 | 없음 | DNS + Coolify 앱 + 인증서 + CORS |
| 프록시 IP 제한 | 어렵다(같은 호스트) | **가능** — 사무실 IP 만 허용 |

분리를 쉽게 하려고 **관리자 코드는 에디터와 아무것도 공유하지 않는다.**
`pages/admin/` 과 `services/cloud/adminApi.ts` 만 옮기면 되도록,
에디터 스토어·테마 설정을 건드리지 않고 자기 상태만 쓴다.

> **"코드가 번들에 실린다"가 곧 취약점은 아니다.** 화면을 열어도 API 가
> 관리자 표를 요구하면 아무것도 못 한다. 실제 방어선은 서버에 있다.
> 별도 도메인의 실질적 이점은 **IP 제한**이다.

## 2. 로그인 — 2단계 ★

```
① 이메일 + 비밀번호 → **프런트가 GoTrue 로 직접** 로그인
                      (비밀번호가 우리 API 를 지나가지 않는다)
② POST /v1/admin/login/start   → 관리자인지 확인하고 인증번호 발송
③ POST /v1/admin/login/verify  → 맞으면 **관리자 표**(8시간)
```

- **①만으로는 아무것도 못 한다.** 관리자 API 는 전부 ③의 표를 요구한다.
- 관리자가 아닌 계정은 ②에서 `403 관리자 계정이 아닙니다` 로 끊긴다 —
  **인증번호도 보내지 않는다**(남의 메일함을 두드리는 데 쓰이지 않게).
- 인증번호 발송·확인은 **가입 쪽을 그대로 재사용**한다
  (`account.service.ts`). 재발송 60초·시간당 5회·시도 5회 제한이 이미
  붙어 있고, 두 벌로 나누면 규칙이 갈린다.

### 관리자 표

형식은 계정 인증표와 같다 — `<이메일 base64url>.<만료>.<HMAC>`.
헤더는 **`X-Admin-Token`** 이다. `Authorization` 은 GoTrue 토큰이 이미
쓰고 있어서, 한 헤더에 둘을 섞으면 어느 쪽이 검증됐는지 헷갈린다.

브라우저에는 **sessionStorage** 에 둔다(localStorage 가 아니다) —
공용 PC 에서 탭을 닫으면 끝나야 한다.

### 누가 관리자인가 — `ADMIN_EMAILS`

```
ADMIN_EMAILS=ok@baro.pro
```

**DB 컬럼이 아니다.** 컬럼이면 DB 를 건드릴 수 있는 사람이 스스로를
관리자로 올릴 수 있다. 환경변수는 배포 권한이 있어야 바꾼다.

> 여기서 이메일을 지우면 **그 사람의 표가 즉시 무효**가 된다 — 표를
> 회수할 방법이 따로 없으므로, 명단에서 빼는 것이 곧 회수여야 한다.
> (`readAdminToken` 이 서명·만료를 통과한 뒤 명단을 다시 본다.)

⚠️ **`AUTH_MODE=dev` 에서는 관리자 콘솔을 쓸 수 없다.** dev 가드는 토큰을
보지 않아 세션에 이메일이 없고, 그러면 관리자를 가릴 수가 없다. 이것은
제약이 아니라 의도다 — 인증이 꺼진 서버에 관리자 문을 열어 둘 수 없다.

## 3. 메뉴

| 메뉴 | 1차(2026-08-13) | 다음 |
|---|---|---|
| **회원관리** | 현황·요금제 변경·사용용량·활동 | 계정 정지, 상세 보기 |
| **결제관리** | **자리만** (준비 중) | PG 연동 뒤 구독·결제 이력 |
| **설정관리** | **조회 전용** | 바꿀 수 있는 값부터 편집 |

### 3.1 회원관리

목록 한 줄에: 이메일(+미인증 배지) · 성명 · **요금제(드롭다운)** ·
사용량/한도(문서·첨부 나눠서) · 맵 수 · 첨부 수 · 최근 30일 저장 ·
마지막 활동(플랫폼·브라우저·IP) · 가입일. 위에는 요약 카드
(전체·최근 7일·30일 가입·요금제별 인원).

**요금제 변경은 드롭다운 하나다.** 남의 계정이라 한 번 묻고, 바꾸면
`quota_bytes` 는 DB 트리거가 따라온다. 그 사람은 **재로그인·재배포 없이**
아바타 메뉴를 다시 열면 바뀐 한도가 보인다.

> ⚠️ **'로그인 정보'라고 부르지 않는다.** GoTrue 는 별도 DB 라 우리에게
> 로그인 기록이 없다. 우리가 아는 것은 **저장할 때 남는 기록**뿐이다
> (`map_document_versions` 의 시각·플랫폼·브라우저·IP). 그래서 화면도
> '마지막 활동'·'최근 30일 저장'으로 적는다 — 없는 것을 있는 것처럼
> 보이게 하지 않는다.

### 3.2 결제관리 — 지금은 자리만

결제 시스템이 없어 **보여 줄 데이터가 없다.** 만들어 두면 빈 껍데기가
되므로 무엇이 필요한지만 적어 둔다: 결제 수단 등록 · 구독 상태 ·
결제 이력 · 실패 시 유예와 강등 정책(attachment-storage.md §8.2).
그때까지 요금제는 회원관리에서 직접 바꾼다.

### 3.3 설정관리 — 조사 결과

"개발하면서 정한 값들이 어떤 것이 있는지 조사하고 관리" 요청의 앞부분.
**목록 없이 바꾸는 기능부터 만들면 무엇을 바꾸는지 모른 채 바꾸게 된다.**
그래서 1차는 **한 화면에 모으는 것**까지다.

**값을 베껴 적지 않는다 — 살아 있는 값을 가져온다.**

| 갈래 | 어디서 | 어떻게 |
|---|---|---|
| `env` | 서버 환경변수 | ConfigService 에서 **실제 값**을 읽는다 |
| `db` | DB | `plan_quota_bytes()` 에 **물어본다** |
| `code` | 코드 상수 | 화면이 그 상수를 **import** 한다 |

베껴 적으면 원본이 바뀔 때 관리 화면이 조용히 거짓말을 한다.

담는 묶음 (11개):

- 서버 — 요금제·저장 용량 / 첨부 파일 / 레이트 리밋 / 가입 이메일 인증 /
  세션·잠금 / 메일 발송 / 인증·관리자
- 화면 — 저장·자동저장 / 첨부·이미지 / 에디터 한계 / 기능 스위치

> **레이아웃 치수(노드 간격 같은 픽셀)는 일부러 담지 않았다.** 디자인이라
> 코드가 주인이고, 목록에 섞이면 정작 봐야 할 정책 값이 묻힌다.
>
> **비밀번호는 값이 아니라 유무만 보여 준다** (`SMTP_PASS` → `설정됨`).

## 4. API

| | | |
|---|---|---|
| `POST` | `/v1/admin/login/start` | GoTrue 토큰 필요 → 관리자면 인증번호 발송 |
| `POST` | `/v1/admin/login/verify` | `{code}` → `{adminToken, email, expiresAt}` |
| `GET` | `/v1/admin/me` | 표가 살아 있는지 (새로고침 대비) |
| `GET` | `/v1/admin/summary` | 요금제별 인원·최근 가입 |
| `GET` | `/v1/admin/users?q=` | 회원 목록(사용량·활동 포함) |
| `PATCH` | `/v1/admin/users/:id/plan` | `{plan}` → 요금제 변경 |
| `GET` | `/v1/admin/settings` | 서버 쪽 설정값(실제 값) |

`login/*` 두 개만 `AuthGuard`(GoTrue 토큰), 나머지는 전부
`AdminGuard`(관리자 표). **가드를 겹쳐 쓰지 않는다** — 문을 따로 두면
"이 엔드포인트는 관리자 전용인가"를 잊을 수가 없다.
