## 1. 어디에 있나 — 개발은 경로, 운영은 도메인 ★

**2026-08-14 사용자 결정.** 개발은 지금 쓰던 주소를 그대로 두고,
운영만 도메인을 따로 쓴다.

| | 개발 | 운영 |
|---|---|---|
| 주소 | `dev.mindmap.ai.kr/admin` | **`admin.easymindmap.org`** |
| 가르는 기준 | **경로** | **도메인 전체** |
| 프록시 IP 제한 | 어렵다(에디터와 같은 호스트) | **가능** — 사무실 IP 만 허용 |

**라우터는 여전히 들이지 않았다.** 이 앱에는 라우터가 없었고(에디터
하나뿐), 관리자 화면 하나 때문에 넣으면 에디터의 `?map=` 처리와 규칙이
둘로 갈린다. `main.tsx` 가 주소만 본다.

```ts
const host = window.location.hostname;
const isAdminHost = host === 'admin' || host.startsWith('admin.');
const isAdminPath = window.location.pathname.replace(/\/+$/, '') === '/admin';
const isAdmin = isAdminHost || isAdminPath;
```

프런트엔드 nginx 가 이미 SPA 폴백(`try_files $uri $uri/ /index.html`)을
하므로 **서버 설정을 바꾸지 않아도** 두 경우 모두 이 파일까지 온다.

> **관리자 도메인에서는 경로와 무관하게 콘솔만 뜬다.** `admin.…/`,
> `admin.…/아무거나`, `admin.…/?map=xxx` 가 전부 콘솔이다. 에디터로 새어
> 나갈 길을 두지 않는다 — 그 도메인에 IP 제한을 걸었는데 에디터가
> 열린다면 제한을 우회하는 통로가 된다.
>
> 반대로 **`/administrator` 나 `web.` 로 시작하는 호스트는 관리자가
> 아니다.** 앞자리만 같은 주소를 관리자로 착각하지 않는지 확인했다
> (e2e145).

**왜 도메인을 나누나.** 코드가 번들에 실리는 것이 취약점이어서가
아니다 — 화면을 열어도 API 가 관리자 표를 요구하면 아무것도 못 하고,
실제 방어선은 서버에 있다. **실질적 이점은 IP 제한 하나다.** 경로로만
갈려 있으면 에디터까지 같이 막히므로 걸 수가 없다.

분리를 쉽게 하려고 **관리자 코드는 에디터와 아무것도 공유하지 않는다.**
`pages/admin/` 과 `services/cloud/adminApi.ts` 만 옮기면 되도록,
에디터 스토어·테마 설정을 건드리지 않고 자기 상태만 쓴다.

### 개발 콘솔과 운영 콘솔은 화면이 똑같다 — 배지로 가른다

같은 코드이므로 **한눈에 구분되지 않는다.** 개발인 줄 알고 운영 회원의
요금제를 바꾸면 되돌릴 수는 있어도 그 사람에게는 이미 한도가 바뀐 뒤다.
그래서 제목 옆에 **`로컬` / `개발` / `운영`** 배지를 붙인다.

| 판정 | 근거 |
|---|---|
| `로컬` | API 가 `localhost` · `127.0.0.1` |
| `개발` | API 호스트에 `dev.` 또는 `-dev.` (예: `api-dev.mindmap.ai.kr`) |
| **`운영`** | **그 밖의 전부** |

- **프런트 주소가 아니라 API 주소로 판정한다** — 실제로 건드리는
  데이터가 거기 있다. 마우스를 올리면 어느 API 인지 그대로 보여 준다.
- **모르면 `운영`으로 본다.** 개발을 운영으로 잘못 부르면 조심하게 될
  뿐이지만, 반대는 사고가 된다.
- **로그인 화면에도 붙인다.** 들어간 뒤에 아는 것보다 비밀번호를 넣기
  전에 아는 편이 낫다.

### 콘솔은 **자기 안에서 구른다** (2026-08-14 사용자 지적)

설정관리 아래쪽이 잘려 보이지 않았다. 원인은 관리자 코드가 아니라
**에디터를 위한 전역 규칙**이다.

```css
/* global.css */
html, body { height: 100%; overflow: hidden; }   /* 캔버스가 페이지째 구르면 안 된다 */
#root { height: 100%; }
```

관리자 화면은 `minHeight: 100vh` 짜리 긴 문서라 `#root` 밖으로 넘쳤고,
넘친 만큼 `body` 가 잘라냈다. **휠을 굴려도 내려가지 않는다.**

전역 규칙을 푸는 것은 답이 아니다 — 그러면 에디터 쪽이 깨진다. 그래서
**관리자 화면만** 자기 스크롤 그릇이 된다.

| | |
|---|---|
| 콘솔 바깥 | `height: 100vh` + `overflow-y: auto` |
| 머리글(탭) | `position: sticky` — 긴 목록 아래에서 탭을 찾아 되올라오지 않게 |
| 로그인 카드 | 같은 방식. 낮은 창에서 **`align-items: center` 는 위쪽을 잘라먹으므로** 쓰지 않고 `margin: auto 0` 으로 가운데 둔다 |

> 확인: e2e147 — 되돌려 깨뜨려 **휠을 굴려도 마지막 묶음이 화면 밖
> (y=3150 / 화면 800px)** 인 것을 재현하고, 고친 뒤 같은 휠 동작으로
> 화면 안(y=514)에 들어오는 것을 봤다. 에디터 쪽 `body` 가 여전히
> `overflow:hidden` 인 것도 함께 확인했다.

## 2. 로그인 — 2단계 ★

```
① 이메일 + 비밀번호 → **프런트가 GoTrue 로 직접** 로그인
                      (비밀번호가 우리 API 를 지나가지 않는다)
② POST /v1/admin/login/start   → 관리자인지 확인하고 인증번호 발송
③ POST /v1/admin/login/verify  → 맞으면 **관리자 표**(8시간)
```

- **①만으로는 아무것도 못 한다.** 관리자 API 는 전부 ③의 표를 요구한다.
- 관리자가 아닌 계정은 ②에서 `403 관리자 계정이 아닙니다` 로 끊긴다 —
  **인증번호도 보내지 않는다**(남의 메일함을 두드리는 데 쓰이지 않게).
- 인증번호 발송·확인은 **가입 쪽을 그대로 재사용**한다
  (`account.service.ts`). 재발송 60초·시간당 5회·시도 5회 제한이 이미
  붙어 있고, 두 벌로 나누면 규칙이 갈린다.

### 메일 문구는 갈라 놓는다 (2026-08-13 사용자 지적)

규칙은 공유하되 **받는 사람이 읽는 문구는 다르다.** "가입 인증번호"라고
적힌 메일이 관리자 로그인에도 오면 **무엇 때문에 온 메일인지 알 수 없다.**

| | 제목 | 본문 첫 줄 |
|---|---|---|
| 가입 | `[EasyMindMap] 가입 인증번호 NNNNNN` | `EasyMindMap 가입 인증번호입니다.` |
| **관리자 로그인** | `[EasyMindMap] Admin 로그인 인증번호 NNNNNN` | `EasyMindMap Admin 로그인 인증번호입니다.` |

문구는 `mail.service.ts` 의 **`CODE_PURPOSE` 한 곳**에 모아 둔다 —
새 쓰임새(비밀번호 재설정 등)가 생기면 여기에 한 줄만 더한다.

### 관리자 표

형식은 계정 인증표와 같다 — `<이메일 base64url>.<만료>.<HMAC>`.
헤더는 **`X-Admin-Token`** 이다. `Authorization` 은 GoTrue 토큰이 이미
쓰고 있어서, 한 헤더에 둘을 섞으면 어느 쪽이 검증됐는지 헷갈린다.

브라우저에는 **sessionStorage** 에 둔다(localStorage 가 아니다) —
공용 PC 에서 탭을 닫으면 끝나야 한다.

### 누가 관리자인가 — `ADMIN_EMAILS`

```
ADMIN_EMAILS=ok@baro.pro
```

**DB 컬럼이 아니다.** 컬럼이면 DB 를 건드릴 수 있는 사람이 스스로를
관리자로 올릴 수 있다. 환경변수는 배포 권한이 있어야 바꾼다.

> 여기서 이메일을 지우면 **그 사람의 표가 즉시 무효**가 된다 — 표를
> 회수할 방법이 따로 없으므로, 명단에서 빼는 것이 곧 회수여야 한다.
> (`readAdminToken` 이 서명·만료를 통과한 뒤 명단을 다시 본다.)

⚠️ **`AUTH_MODE=dev` 에서는 관리자 콘솔을 쓸 수 없다.** dev 가드는 토큰을
보지 않아 세션에 이메일이 없고, 그러면 관리자를 가릴 수가 없다. 이것은
제약이 아니라 의도다 — 인증이 꺼진 서버에 관리자 문을 열어 둘 수 없다.

### 3.1 회원관리

목록 한 줄에: 이메일(+미인증 배지) · 성명 · **요금제(드롭다운)** ·
사용량/한도(문서·첨부 나눠서) · 맵 수 · 첨부 수 · 최근 30일 저장 ·
마지막 활동(플랫폼·브라우저·IP) · 가입일. 위에는 요약 카드
(전체·최근 7일·30일 가입·요금제별 인원).

> **표가 가로로 넘치지 않게 한다** (2026-08-14 사용자 지적). 칸이 11개라
> 곁들이 정보(`문서 33KB · 첨부 0`, `Windows 11 · Chrome 136 · IP`)를
> **같은 줄에 붙이면** 표의 최소 너비가 1424px 이 되어 1242px 그릇을
> 넘는다. 아래 줄로 내리면 1242px 안에 들어온다 — **고친 대목은 폭이
> 아니라 줄바꿈이다.** (콘솔 폭도 1280 → 1560 으로 넓혔지만 그건 넓은
> 화면에서 덜 빽빽하게 보이려는 것이고, 좁은 창에서도 넘치지 않는 이유는
> 줄바꿈 쪽이다 — e2e148 에서 되돌려 확인했다.)

**요금제 변경은 드롭다운 하나다.** 남의 계정이라 한 번 묻고, 바꾸면
`quota_bytes` 는 DB 트리거가 따라온다. 그 사람은 **재로그인·재배포 없이**
아바타 메뉴를 다시 열면 바뀐 한도가 보인다.

#### 로그인과 저장을 **나눠서** 보여 준다 (2026-08-13)

| 칸 | 어디서 오나 | 무엇인가 |
|---|---|---|
| **마지막 로그인** | **GoTrue 관리자 API** | 진짜 로그인 시각(분까지) |
| 마지막 활동(저장) | 우리 DB `map_document_versions` | 저장한 시각 + 플랫폼·브라우저·IP |
| 최근 30일 저장 | 같은 표 | 저장 **횟수**(로그인 횟수가 아니다) |

**둘은 다르다.** 로그인만 하고 아무것도 저장하지 않을 수 있고, 반대로
오래 열어 둔 탭이 저장만 계속할 수도 있다. 하나로 합치면 어느 쪽인지
알 수 없어진다.

`GET {GOTRUE_URL}/admin/users?per_page=1000` 을 관리자 토큰으로 부른다 —
회원탈퇴·비밀번호 재설정이 쓰는 것과 **같은 길**이라 새 환경변수도,
서비스 키 보관도 필요 없다. 차단된 계정(`banned_until`)에는 배지가 붙는다.

> **못 가져와도 목록은 그대로 열린다.** 로그인 이력은 덤이지, 회원 목록이
> 열리지 않을 이유가 아니다. 대신 응답의 `loginHistoryAvailable: false` 를
> 보고 화면이 **왜 비어 있는지 밝힌다** — 없는 것을 있는 척하지 않는다.

#### 로그인 이력 전체 — 횟수·시각 (2026-08-14 사용자 요청)

회원 행의 **[로그인 이력]** 을 누르면 그 자리에서 펼쳐진다.
최근 30일 로그인 횟수 · 전체 횟수 · 마지막 로그인 + **최근 50건 목록**
(시각·사건·IP).

기록의 주인은 **GoTrue 의 감사 로그**(`auth.audit_log_entries`)다.
관리자 API 는 마지막 시각만 주므로, 이력은 **그 DB 를 직접 읽는다** —
그래서 환경변수가 하나 더 필요하다.

```
GOTRUE_DATABASE_URL=postgres://postgres:<pw>@<host>:5432/gotrue
```

**읽기만 한다.** 쓰기는 GoTrue 의 몫이다.

- **목록에 함께 싣지 않는다** — 회원 200명이면 감사 로그를 200번 뒤지게
  된다. **누른 사람 것만** 그때 가져온다.
- **자동 토큰 갱신(`token_refreshed`)은 뺐다** — 하루에도 수십 건씩 쌓여
  섞으면 **사람이 한 일이 묻힌다.** 보여 주는 것은 로그인·로그아웃·가입·
  계정 변경·비밀번호 재설정 요청·비밀번호 변경.
- **설정이 없으면 빈 목록이 아니라 "볼 수 없다"고 말한다.** 빈 목록은
  "로그인한 적이 없다"로 읽힌다.
- **몇 건까지 보이나 — 최근 50건이다** (2026-08-14 사용자 질문). 화면이
  규칙을 그대로 밝힌다: 50건에 닿으면 `이 목록은 최근 50건까지만 보여
  줍니다 (전체 로그인 141회)`, 그보다 적으면 `기록 전체 8건입니다`.
  "최근 N건입니다"라고만 쓰면 **그것이 전부인지 잘린 것인지 알 수 없다.**

#### ⚠️ IP 는 보여 줄 수 없다 — GoTrue 가 기록하지 않는다 (2026-08-14)

사용자 지적: "로그인 이력에 IP 값이 없다". **우리 쿼리 문제가 아니다.**

`auth.audit_log_entries.ip_address` 컬럼은 있지만, supabase/auth
**v2.194.0 이 그 자리에 빈 문자열을 넣는다.** 소스에서 확인했다.

| 파일 | 호출 |
|---|---|
| `internal/api/token.go` | `NewAuditLogEntry(…, LoginAction, "", …)` |
| `internal/api/logout.go` | `NewAuditLogEntry(…, LogoutAction, "", …)` |

payload JSON 에도 IP 키가 없다(`actor_id`·`actor_username`·`action`·
`log_type` 뿐). **우리 코드로 채울 수 있는 값이 아니다.**

그래서 **IP 칸을 아예 만들지 않는다** — 값이 하나도 없을 때 이야기다.
줄줄이 `—` 를 보여 주는 것은 "기록이 없다"가 아니라 **"고장 났다"로
읽힌다.** 칸을 없애고 왜 없는지 한 줄로 말한다. 값이 있는 경우
(다른 GoTrue 판·다른 사건)에는 칸이 그대로 나오도록 읽기는 남겨 뒀다.

> **진짜 접속 IP 가 필요하면 우리가 직접 기록해야 한다** — 로그인 직후
> 프런트가 우리 API 를 부르고, 서버가 그때의 IP 를 남기는 방식이다.
> 우리는 이미 `TRUST_PROXY` 가 맞춰져 있고 `/v1/health/ip` 로 그것을
> 눈으로 확인할 수 있다. **아직 만들지 않았다** — 별도 작업이다.

사용자도 **자기 것만** 같은 화면으로 본다 — 앱 우상단 아바타 →
**🕘 로그인 기록** (`GET /v1/account/logins`). 경로에 id 를 받지 않는다.
토큰의 주인 것만 조회하므로 **남의 기록은 볼 수 없다.**

### 3.2 결제관리 — 지금은 자리만

결제 시스템이 없어 **보여 줄 데이터가 없다.** 만들어 두면 빈 껍데기가
되므로 무엇이 필요한지만 적어 둔다: 결제 수단 등록 · 구독 상태 ·
결제 이력 · 실패 시 유예와 강등 정책(attachment-storage.md §8.2).
그때까지 요금제는 회원관리에서 직접 바꾼다.

### 3.3 설정관리 — **DB 값만 편집, 나머지는 조회** ★

"개발하면서 정한 값들이 어떤 것이 있는지 조사하고 관리" 요청. 1차(08-13)는
**한 화면에 모으는 것**까지 했다 — 목록 없이 바꾸는 기능부터 만들면
무엇을 바꾸는지 모른 채 바꾸게 된다. 2차(08-14)에서 **바꿔도 되는 것만**
열었다 (사용자 결정).

**값을 베껴 적지 않는다 — 살아 있는 값을 가져온다.**

| 갈래 | 어디서 | 어떻게 | 콘솔에서 편집 |
|---|---|---|---|
| `db` | DB | `plan_quota_bytes()` 에 **물어본다** | **✅ 연다** |
| `env` | 서버 환경변수 | ConfigService 에서 **실제 값**을 읽는다 | ❌ |
| `code` | 코드 상수 | 화면이 그 상수를 **import** 한다 | ❌ (불가능) |

베껴 적으면 원본이 바뀔 때 관리 화면이 조용히 거짓말을 한다.

#### 왜 환경변수는 열지 않았나

**관리자 콘솔이 서버를 멈출 수 있는 도구가 되기 때문이다.**
`CORS_ORIGIN` 하나만 잘못 넣어도 전원이 로그인하지 못하고, **그 상태를
화면에서 되돌릴 수도 없다** — 콘솔도 같은 API 를 쓰므로 함께 막힌다.
바꾸는 자리는 Coolify 이고, 배포 권한이 있어야 손댈 수 있는 편이 맞다.

코드 상수(`code`)는 **빌드에 박혀 있어 애초에 못 바꾼다.** 목록에는
남겨 둔다 — "어디를 고치면 되는지"를 아는 것이 조회의 목적이다.

> **편집 가능 여부는 서버가 정한다** (`item.editable`). 화면이
> `source === 'db'` 로 짐작하면, 나중에 못 고치는 DB 값이 생겼을 때
> **입력칸이 먼저 생기고 저장에서 터진다.**

#### 요금제 한도 편집 — 함수에서 표로 옮겼다

용량 숫자가 **DB 함수 본문에 박혀 있어** 바꾸려면 배포가 필요했다.
표로 빼고 함수는 읽기만 하게 바꿨다.

```sql
CREATE TABLE public.plan_quotas (plan TEXT PRIMARY KEY, quota_bytes BIGINT …);

INSERT INTO public.plan_quotas … ON CONFLICT (plan) DO NOTHING;   -- ★
```

★ **`DO NOTHING` 이 핵심이다.** `DO UPDATE` 였다면 `schema.sql` 을 다시
적용할 때마다 **관리자가 콘솔에서 바꾼 값이 조용히 되돌아간다.**
씨앗은 처음 한 번만 심는다. (실제로 두 경우를 다 돌려 확인했다 — e2e146)

| | |
|---|---|
| 범위 | **1 MB ~ 1 TB.** 0 은 아무도 저장하지 못하게 만들고, 자릿수 오타는 디스크가 찰 때까지 아무도 모른다 |
| 기록 | `updated_at` · `updated_by`(관리자 이메일) |
| 확인 | 바꾸기 전에 **한 번 묻는다** — 남의 계정 한도가 함께 바뀐다 |

**어려운 부분은 표가 아니라 기존 회원이다.** `users.quota_bytes` 는
요금제가 *바뀔 때만* 트리거가 따라오므로, 표만 고치면 **기존 회원은 옛
한도 그대로**다 — 바꿨는데 아무 일도 일어나지 않는다.

그렇다고 그 요금제 전원을 덮으면 **특별 계약(`quota_bytes` 를 직접 올려
둔 계정)이 조용히 깎인다.** 그래서 **옛 한도와 정확히 같은 사람만**
옮기고, 손대지 않은 인원수를 화면이 함께 밝힌다.

```
10 GB → 20 GB · 회원 2명 반영 · 1명은 특별 계약이라 그대로
```

담는 묶음 (11개):

- 서버 — 요금제·저장 용량 / 첨부 파일 / 레이트 리밋 / 가입 이메일 인증 /
  세션·잠금 / 메일 발송 / 인증·관리자
- 화면 — 저장·자동저장 / 첨부·이미지 / 에디터 한계 / 기능 스위치

> **레이아웃 치수(노드 간격 같은 픽셀)는 일부러 담지 않았다.** 디자인이라
> 코드가 주인이고, 목록에 섞이면 정작 봐야 할 정책 값이 묻힌다.
>
> **비밀번호는 값이 아니라 유무만 보여 준다** (`SMTP_PASS` → `설정됨`).

### 3.4 비밀번호 변경 (2026-08-13 사용자 요청)

⚠️ **관리자 콘솔에 초기 비밀번호는 없다.** 1단계는 그 사람의 **앱
계정(GoTrue)** 으로 로그인하므로, 관리자 비밀번호 = 그 계정의 앱
비밀번호다. 우리가 발급한 값이 따로 없다.

바꾸는 곳은 **두 군데이고 같은 폼**을 쓴다
(`components/auth/ChangePasswordForm.tsx`).

| 어디 | 가는 길 |
|---|---|
| 일반 앱 | 우상단 **아바타 → 🔑 비밀번호 변경** (개인 설정 바로 아래) |
| 관리자 | 관리자 콘솔 → **비밀번호 변경** 탭 |

한 벌로 두는 이유: 최소 길이·확인 입력·오류 문구가 두 곳에서 갈리면
어느 쪽이 맞는지 알 수 없게 된다.

- **지금 로그인한 사람의 것만** 바뀐다 — GoTrue `PUT /user` 가 액세스
  토큰의 주인을 본다.
- **남의 비밀번호를 관리자가 바꾸는 기능은 일부러 만들지 않았다** —
  계정 탈취 통로가 되고, 필요하면 사용자가 스스로 **재설정 메일**로
  바꾸는 쪽이 맞다.
- 옛 비밀번호를 묻지 않는 것은 GoTrue 가 받지 않아서다. 대신 관리자
  콘솔은 **이미 2단계 인증을 지난 상태**다.

> **비밀번호를 잊었다면** 로그인 화면의 **[비밀번호를 잊으셨나요?]** 로
> 재설정한다 (2026-08-13 추가 · `auth-session-ui.md` §11-B).
> 그 길도 막혔을 때만 서버에서 GoTrue 관리자 API 로 바꾼다 —
> `dev-server-runbook.md` **§1.5-0-D**.

## 4. API

| | | |
|---|---|---|
| `POST` | `/v1/admin/login/start` | GoTrue 토큰 필요 → 관리자면 인증번호 발송 |
| `POST` | `/v1/admin/login/verify` | `{code}` → `{adminToken, email, expiresAt}` |
| `GET` | `/v1/admin/me` | 표가 살아 있는지 (새로고침 대비) |
| `GET` | `/v1/admin/summary` | 요금제별 인원·최근 가입 |
| `GET` | `/v1/admin/users?q=` | 회원 목록(사용량·활동 + **마지막 로그인**) → `{users, loginHistoryAvailable}` |
| `PATCH` | `/v1/admin/users/:id/plan` | `{plan}` → 요금제 변경 |
| `GET` | `/v1/admin/users/:id/logins` | 그 회원의 **로그인 이력** — 횟수·시각·IP |
| `GET` | `/v1/admin/settings` | 서버 쪽 설정값(실제 값) + 편집 가능 여부 |
| `PATCH` | `/v1/admin/settings/plan-quota` | `{plan, mb}` → 요금제 한도 변경 (**콘솔에서 고칠 수 있는 유일한 설정**) |

`login/*` 두 개만 `AuthGuard`(GoTrue 토큰), 나머지는 전부
`AdminGuard`(관리자 표). **가드를 겹쳐 쓰지 않는다** — 문을 따로 두면
"이 엔드포인트는 관리자 전용인가"를 잊을 수가 없다.

## 5. 설정 (Coolify → api)

```
ADMIN_EMAILS=ok@baro.pro
GOTRUE_DATABASE_URL=postgres://postgres:<pw>@<host>:5432/gotrue
```

`ADMIN_EMAILS` 가 없으면 **아무도 들어갈 수 없고**, `GOTRUE_DATABASE_URL`

## 7. 운영 콘솔 구축 — `admin.easymindmap.org` ★

> **아직 하지 않았다.** 운영 VM 과 `easymindmap-prod` 프로젝트가 없어서다
> (`dev-server-coolify.md` §7). 코드는 준비돼 있으니, 운영 서버가 생기면
> 아래 순서대로 하면 된다. **개발 콘솔은 손대지 않는다** —
> `dev.mindmap.ai.kr/admin` 은 지금 그대로 계속 쓴다.

### 7.1 순서

**① DNS** — `admin.easymindmap.org` A 레코드를 운영 VM 공인 IP 로.

**② Coolify 앱을 하나 더 만든다** (프런트엔드와 **별도 앱**).

같은 저장소·같은 Dockerfile·같은 브랜치를 쓰고 도메인만 다르다.

| 설정 | 값 |
|---|---|
| Domain | `https://admin.easymindmap.org` |
| `VITE_API_URL` | `https://api.easymindmap.org` |
| 나머지 빌드 변수 | 운영 프런트엔드와 동일 |

> **왜 도메인만 하나 더 붙이지 않고 앱을 나누나.** 한 앱에 도메인 둘을
> 매달면 Traefik 설정을 공유하게 되어 **관리자 쪽에만 IP 제한을 걸 수
> 없다.** IP 제한이 도메인을 나누는 유일한 이유인데 그걸 못 하면 나눈
> 뜻이 없다. 빌드가 한 번 더 도는 비용은 그보다 싸다.

**③ 운영 api 의 `CORS_ORIGIN` 에 추가한다** — 콤마로 여러 개를 받는다.

```
CORS_ORIGIN=https://web.easymindmap.org,https://admin.easymindmap.org
```

빠뜨리면 화면은 뜨는데 **모든 요청이 CORS 로 막힌다.** 로그인 1단계부터
안 된다.

**④ 운영 api 환경변수** — 개발과 **값이 다르다**. 복사해 오지 않는다.

```
ADMIN_EMAILS=ok@baro.pro
GOTRUE_DATABASE_URL=postgres://postgres:<운영 pw>@<운영 host>:5432/gotrue
```

**⑤ `ok@baro.pro` 로 운영 GoTrue 에 가입한다.**
1단계 로그인은 **그 환경의 GoTrue** 로 간다 — 개발 계정은 넘어오지
않는다. 운영 앱에서 정상적으로 회원가입한 뒤 콘솔에 들어간다.

**⑥ IP 제한** (선택이지만 권장) — Coolify 의 관리자 앱에 Traefik
미들웨어를 붙여 사무실 IP 만 허용한다. **이것이 도메인을 나눈 이유다.**

### 7.2 다 되면 확인할 것

1. `https://admin.easymindmap.org` 를 연다 → 제목 옆 배지가 **빨간 `운영`**
2. 배지에 마우스를 올리면 `API: api.easymindmap.org`
3. `ok@baro.pro` 로 2단계 로그인 → 회원관리에 **운영 회원**이 보인다
4. `https://dev.mindmap.ai.kr/admin` 을 열면 배지가 **파란 `개발`** 이고
   **회원 목록이 서로 다르다**

배지 색이 예상과 다르면 **`VITE_API_URL` 을 잘못 넣은 것**이다 — 판정은
API 주소로 한다.
