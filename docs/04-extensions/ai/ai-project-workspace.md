## 1. 목적 — "맵 = AI 프로젝트, 노드 = 질문"

현행 AI 생성(`18-ai.md`)은 **질문 1개 → 맵 전체를 새로 생성(교체)**하는
1회성 방식이다. 이 문서의 기능은 다르다:

- **맵 하나를 하나의 AI "프로젝트"**로 쓴다.
- **자식 노드 하나 = 그 프로젝트 안의 질문 하나**로 관리한다.
- 질문 노드에서 "AI에게 묻기"를 실행하면, **프로젝트 공유 맥락 + 그
  질문**을 보내 답을 받아 **그 노드 아래에 채운다** — 나머지 맵은 그대로.

ChatGPT의 "프로젝트"를 마인드맵으로 옮긴 개념이되, **API는 무상태**라
프로젝트 문맥을 서버가 기억하지 않는다는 근본 차이가 있다(§4).

## 2. 개념 매핑

| 맵 요소 | 역할 |
|---|---|
| **중심 주제(루트)** | 프로젝트. 루트에 **프로젝트 지침**(공유 지시)을 저장 |
| **@소스 노드** | 프로젝트 전반에 항상 딸려 갈 **참고 소스**(텍스트) |
| **질문 노드** (임의 깊이) | 프로젝트 안의 개별 질문. AI가 만든 노드든 사용자가 만든 노드든 **무관** |
| **질문 노드의 하위** | AI 답변이 채워지는 자리 |

> 노드의 "출처(AI/사용자)"는 저장·관여하지 않는다. 맥락은 **질문 시점의
> 트리 위치(조상)**로만 조립한다.

## 3. 맥락 조립 레시피

질문 호출 한 번에 아래를 담아 보낸다.

| 구성 | 내용 | 적용 |
|---|---|---|
| ① 프로젝트 지침 | 루트(중심 주제)의 **텍스트 + 노트** | 항상 |
| ② 프로젝트 소스 | 2레벨 **`@소스` 노드**의 텍스트·노트 + 하위 노드(있으면) | 항상 · **캐싱 대상** |
| ③ 경로 맥락 | 질문 노드의 **직계 조상 체인** 전체 내용 (루트→…→부모) | 위치 따라 자동 |
| ④ 질문 | 이 노드의 텍스트/노트 | — |

> **전달되는 것은 텍스트(제목·노트)뿐**이다. 노드의 하이퍼링크(URL)와
> PDF·이미지 첨부는 맥락에 넣지 않는다 — API가 URL을 열거나 파일을
> 읽지 못하므로(웹 열람 없음), 소스로 쓸 내용은 **글로 적어야** 한다.
> 프로젝트 지침은 **중심 주제의 노트**에, 소스는 2레벨 `@소스` 노드의
> 텍스트·노트·하위 노드에 둔다. (AI 탭 "선택 노드 자세히 확장"에 같은
> 안내가 접이식 도움말로 들어 있다.)

### 3.1 핵심 — ③ "경로(직계 조상)"만 보낸다 (MVP)

질문 노드가 몇 레벨이든, **부모를 타고 루트까지 올라간 경로**만 맥락에
넣는다. 옆 가지(형제의 부모들)는 넣지 않는다.

예시:

```
웹서비스 구축              ← 1레벨(루트)  ✅ 포함(프로젝트 지침)
├─ 웹서버용 OS (Ubuntu)    ← 2레벨        ❌ 옆가지 (조상 아님)
├─ 웹서버(Apache) 설치     ← 2레벨        ❌ 옆가지
└─ DB 설치                 ← 2레벨        ✅ 포함(직계 부모)
   └─ DB 보안설정          ← 3레벨 ★질문   → 맥락 = 루트 + DB 설치 + 이 질문
```

즉 `DB 보안설정`을 물으면 **루트 + 직계 부모(DB 설치) + 질문**만 간다.
Ubuntu·Apache는 이 질문과 직접 관계가 없고 토큰만 늘리므로 제외한다.
(5레벨이면 루트→…→부모까지의 경로 전체가 그대로 들어간다.)

### 3.2 답변 위치

- **기본(권장)**: 답변 EMM을 **질문 노드의 하위 노드로 삽입**(구조화).
- 대안: 노트 한 덩어리로. (구현 시 옵션으로 둘 수 있음)

## 4. API 무상태와 프롬프트 캐싱 (비용 현실)

API는 무상태 → 프로젝트 지침·소스·경로를 **매 호출 요청에 다시 담아
보내야** AI가 본다. 다만 **프롬프트 캐싱**으로 반복 호출 비용이 급감한다
(3사 모두 지원, 2026):

| 제공사 | 방식 | 반복 호출 시 공유맥락 요금 |
|---|---|---|
| Anthropic | `cache_control` 명시 마킹 (TTL 5분/1시간) | 캐시 히트 = 정상 입력의 **0.1×** (90%↓), 첫 쓰기 1.25×/2× |
| OpenAI | 1024토큰↑ 접두사 **자동 캐싱** | 캐시 읽기 50%(최신 10%) |
| Gemini | 유료 프로젝트 암묵 캐싱 자동 + 명시 캐싱 | 캐시 읽기 10% + 시간당 저장료 |

**설계 함의**:
- ①②③를 요청의 **앞쪽 고정 접두사**로 배치하고 Anthropic은
  `cache_control`로 마킹한다 → 같은 프로젝트의 여러 질문을 몰아서 하면
  두 번째부터 공유 맥락 요금 ~90% 절감.
- 캐시 TTL(수 분~1시간) 밖으로 벌어지면 다시 전액. 질문을 몰아서 하는
  워크플로에 유리.
- 캐싱해도 공유 맥락은 **모델 맥락창 안에 들어가야** 한다 → 프로젝트
  소스가 아주 크면 캐싱만으론 한계(§6 RAG).

## 5. 앱 제약 (브라우저 직접 호출)

EasyMindMap은 백엔드 없이 **브라우저에서 3사 API를 직접 호출**한다.

- ✅ 프롬프트 캐싱은 그대로 사용 가능(요청에 소스 포함 + 캐시 마킹).
  **소스가 크지 않으면 이 방식이 가장 현실적.**
- ⚠️ 벡터스토어/파일검색(RAG)은 파일을 제공사에 업로드·관리해야 하고
  CORS·프라이버시(제공사 저장) 이슈가 있어 큰 확장. 자체 RAG 서버는
  백엔드가 없어 불가.
- 첨부 소스가 PDF·이미지면 **텍스트 추출**이 선행되어야 한다(현재 앱은
  이미지를 data URL로 내장만 함).

## 6. MVP 범위 vs 향후 확장

### 6.1 MVP (구현 완료) — 맥락 "경로만"

> 루트에 **프로젝트 지침** 저장 + (선택) **프로젝트 소스** 노드. 임의
> 질문 노드에서 AI 탭 **"선택 노드 자세히 확장"** → **(①지침 + ②소스
> + ③직계 조상 경로 + ④질문)** 을 프롬프트 캐싱으로 호출 → 답변을
> **하위 노드로** 삽입. 나머지 맵은 그대로.

- 맥락 범위 = **경로(직계 조상)만** — 사용자 선택 1번.
- 프롬프트 캐싱 적용: ①②(프로젝트 지침·소스)를 **system 블록**에 두고
  Anthropic `cache_control:ephemeral` 마킹 → 같은 프로젝트의 여러
  확장을 몰아서 하면 두 번째부터 그 부분 요금 ~90% 절감.
- **UI**: AI 생성 탭 하단 "선택 노드 자세히 확장" 섹션 — 맵에서 노드를
  선택하면 대상이 표시되고, 버튼을 누르면 확장이 하위 노드로 붙는다
  (확인 대화상자 → Ctrl+Z로 되돌리기). AI/사용자 생성 노드 무관.
- **용도**: AI 생성으로 만든 맵의 특정 노드를 더 깊게 파고들 때, 또는
  직접 만든 골격의 노드를 상세화할 때 모두 사용.
- **답변 파싱**: 확장 답변은 `##` 하위 구조만 오도록 지시(`# 중심주제`
  금지). 혹시 온 `#` 줄을 제거하고 타깃 제목으로 감싸 parseEmm →
  그 branches를 새 ID로 재부여(reassignIds)해 삽입.
- 검증: E2E e2e52 (맥락에 루트+조상 포함·옆가지 제외·cache_control
  마킹·하위 삽입).
- 웹 AI 모드(키 불필요)도 같은 맥락 조립기(`buildExpandContext`)로
  확장 프롬프트를 복사하고 답변을 선택 노드 하위로 삽입한다.

### 6.2 향후 확장 (문서에만 기록, 미구현)

1. **② 맵 개요 포함** (사용자 선택 2번): 경로 + **나머지 노드는 제목만**
   목록으로 얹어 프로젝트 전체 그림을 값싸게 제공. MVP 이후 옵션 추가.
2. **대화형 형제 답변 포함**: 같은 프로젝트의 다른 질문·답변까지 맥락에
   넣어 "이어지는 대화"처럼. 토큰 비용 증가.
3. **대용량 소스 RAG**: 소스를 인덱싱해 질문마다 관련 조각만 전송.
   벡터스토어/파일검색 또는 클라이언트 RAG — **백엔드 도입 단계**에서.
4. **답변 위치 옵션**: 하위 노드 구조화 ↔ 노트 한 덩어리 토글.
