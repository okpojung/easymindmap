## 1. 배경과 목표

현행 AI 생성(18-ai.md)은 **API 키 등록이 전제**다. 그러나 많은 사용자는
API 키 없이 Claude Pro · ChatGPT Plus · Gemini 같은 **웹 구독**만 쓴다.
이들이 키 발급 없이 AI로 맵을 만들 수 있는 통로를 연다.

**전자동은 불가능하다** — 웹페이지는 브라우저 보안(동일 출처 정책) 때문에
다른 사이트(claude.ai 등) 탭을 읽거나 조작할 수 없고, 브라우저 확장으로
소비자 웹 UI를 자동화하는 것은 각 사의 이용약관 위반이다. 그래서 목표를
"**복사 2번으로 끝나는 반자동**"으로 정한다:

```
[EasyMindMap]  ①프롬프트 복사  →  [AI 웹]  붙여넣기·실행
[EasyMindMap]  ③맵 생성        ←  [AI 웹]  ②답변 복사
```

- 사용자 손이 가는 일: **Ctrl+V(AI 창) → 답변 복사 → Ctrl+V(EasyMindMap)**
- API 키·백엔드 변경·외부 서비스 연동 전부 불필요 (프런트 단독)
- 어떤 AI든 동작 — Claude·ChatGPT·Gemini·Perplexity·국산 AI 모두

> 완전 통합(Claude 대화에서 "맵으로 저장해줘" 한 마디)은 **방법 C —
> Claude 커스텀 커넥터(원격 MCP 서버)**로 백로그에 둔다. OAuth 계정
> 연동 + MCP 엔드포인트가 필요한 중기 과제다.

## 2. 작동 원리

### 2-1. 나가는 길 — 프롬프트 복사

`[① 프롬프트 복사]` 버튼이 아래를 이어 붙여 클립보드에 넣는다
(`navigator.clipboard.writeText` — 버튼 클릭이 사용자 제스처라 권한
프롬프트 없이 동작):

```
EMM_SYSTEM_PROMPT            ← emmSystemPrompt.ts 내장본 그대로
+ 생성 유형 지시              ← GENERATION_TYPES 중 선택 (기존 재사용)
+ 사용자 주제                 ← 입력창 내용
+ 마무리 지시: "답변 전체를 ~~~ 물결 펜스 코드블록 하나 안에 출력"
```

> 마무리 지시가 **~~~ 물결 펜스**인 이유 (2026-08-04 실사용 보고):
> "코드블록 하나로만"만으로는 ChatGPT 가 마크다운을 그대로 렌더해
> 여러 블록+텍스트로 표시했고, 렌더 화면을 드래그 복사하면 ##·>·표
> 문법이 사라져 뒷부분이 뭉개졌다. ~~~ 를 명시하면 답변 전체가 복사
> 버튼 달린 코드블록 하나로 나온다 (백틱이면 EMM 안의 ``` 코드 펜스가
> 바깥 블록을 조기에 닫는다). 커스텀 GPT 규칙 B 와 동일.

기존 API 모드가 시스템/유저 메시지로 나눠 보내던 것을 **한 덩어리
텍스트**로 합치는 것만 다르다 — 웹 채팅창은 메시지가 하나뿐이므로.

### 2-2. 들어오는 길 — 답변 붙여넣기 → 맵

답변 입력칸의 `onPaste` 이벤트로 받는다 (**`clipboard.readText()`를
쓰지 않는다** — 읽기는 권한 팝업이 떠서 UX가 나쁘다. 사용자가 Ctrl+V
하는 것 자체가 명시적 제공이다).

붙여넣은 텍스트에서 맵을 뽑는 순서:

1. **코드펜스 추출** — 백틱(```)·물결(~~~) **3개 이상** 펜스를 모두
   인식해(닫는 줄은 같은 문자·같은 길이 이상) 그 안쪽만 취한다 (AI가
   앞뒤에 "네, 만들어 드릴게요" 같은 잡담을 붙이는 경우가 대부분이라
   이 단계가 핵심). 블록이 여러 개면 가장 긴 것.
2. 코드펜스가 없으면 전체 텍스트를 그대로 후보로.
3. 후보를 **기존 변환기**(`parseEmm` → 실패 시 `parseMarkdownMapFile`
   폴백 — API 모드와 동일 경로)로 맵 변환.
4. 성공 → 미리보기(노드 수·중심 주제) + `[맵으로 열기]`.
   실패 → "맵 구조(# 견출·- 리스트)를 찾지 못했습니다. AI에게
   **'방금 답변을 EMM Markdown 코드블록 하나로만 다시 출력해줘'**라고
   요청한 뒤 다시 붙여넣으세요." 안내 (이 요청 문구도 ⧉ 복사 버튼).

**자동 생성 옵션** — "붙여넣는 즉시 맵 생성" 체크(기본 켬, 기억됨).
켜져 있으면 붙여넣기 → 파싱 성공 시 확인 없이 바로 맵으로 연다
(새 맵 확인 게이트는 그대로 거친다).

### 2-3. 맵으로 여는 규칙 (기존과 동일)

- **새 맵 생성**: 현행 API 모드와 같은 경로 — 편집 중인 맵이 있으면
  "현재 맵을 닫고 진행할까요?" 확인 게이트, 서버 연결 해제
  (`detachFromServer`), 레이아웃은 EMM 메타 or 기본.
- **선택 노드 확장**: 노드를 선택한 상태면 "선택 노드에 하위로 삽입"
  선택지 제공 — 확장 프롬프트(`EMM_EXPAND_DIRECTIVE` + 경로 맥락)를
  복사해 주고, 답변은 선택 노드의 하위 트리로 삽입 (기존 AI 프로젝트
  워크스페이스 삽입 로직 재사용).

## 3. 화면 설계

### 3-1. 위치 — 우측 'AI 생성' 탭 안 모드 전환

새 화면을 만들지 않고 **기존 AITab 상단에 모드 스위치**를 둔다:

```
┌─ AI 생성 ────────────────────────────────┐
│ [ 🌐 웹 AI (키 불필요) ] [ 🔑 API 키 ]   │  ← 세그먼트 토글
│ ─────────────────────────────────────── │
│  (선택된 모드의 패널)                     │
└─────────────────────────────────────────┘
```

- **API 키 미등록 사용자는 '웹 AI'가 기본** — 지금은 키가 없으면
  버튼이 죽어 있는데, 그 자리가 곧바로 쓸 수 있는 통로로 바뀐다.
- 키 등록 사용자는 마지막으로 쓴 모드를 기억(localStorage).

### 3-2. 웹 AI 모드 패널 — 3단계 스텝

```
┌─ 🌐 웹 AI로 만들기 ──────────────────────┐
│ 사용 중인 AI 웹 구독(Claude·ChatGPT·      │
│ Gemini…)으로 맵을 만듭니다. 복사 2번.     │
│                                          │
│ ① 무엇을 만들까요?                        │
│ ┌──────────────────────────────────┐    │
│ │ 예: 신제품 출시 계획을 마인드맵으로│    │
│ └──────────────────────────────────┘    │
│ 유형: [기본 ▾] (기본/기술 절차형/회의록형 │
│        /WBS·계획형/문서·기사 요약형)      │
│ ┌──────────────────────────────────┐    │
│ │      📋 ① 프롬프트 복사           │    │
│ └──────────────────────────────────┘    │
│ AI 열기: [Claude] [ChatGPT] [Gemini]     │  ← 새 탭 바로가기
│                                          │
│ ② AI 창에 붙여넣고(Ctrl+V) 실행한 뒤,     │
│    답변을 복사해 오세요.                  │
│                                          │
│ ③ 답변 붙여넣기                           │
│ ┌──────────────────────────────────┐    │
│ │ (여기에 Ctrl+V)                   │    │
│ └──────────────────────────────────┘    │
│ ☑ 붙여넣는 즉시 맵 생성                   │
│ ┌──────────────────────────────────┐    │
│ │      🗺 ③ 맵 생성                 │    │
│ └──────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

상태 표현:

| 시점 | 표시 |
|---|---|
| 프롬프트 복사 직후 | ① 버튼이 2.5초간 "✓ 복사됨 — AI 창에 붙여넣으세요" |
| 답변 파싱 성공 | ③ 위에 초록 미리보기: "'중심 주제' · N노드 — 맵 생성 준비 완료" |
| 파싱 실패 | ③ 위에 빨간 안내 + [재요청 문구 복사] 버튼 |
| 노드 선택 중 | ③ 버튼이 분할: [새 맵으로] [선택 노드에 삽입] |

- **AI 바로가기 버튼**: `window.open('https://claude.ai/new')` 등
  단순 새 탭 — 자동 입력은 하지 않는다(불가능·불필요). 목록:
  Claude · ChatGPT · Gemini (아이콘 없는 텍스트 버튼, 순서 고정 —
  `AI_SHORTCUTS`). **ChatGPT 는 EasyMindMap Copilot 커스텀 GPT 로
  연결**되어 ① 프롬프트 복사 단계를 생략할 수 있다.
- 입력·답변창, 유형 선택, 복사됨 플래시 등 시각 언어는 기존 AITab
  구성요소를 그대로 재사용해 이질감을 없앤다.

### 3-3. 진입 유도 (구현 완료)

- 새 맵 패널의 템플릿 선택 카드에 **"🌐 AI로 초안 만들기"** 진입 버튼
  (클릭 = 우측 AI 탭 열림 + 웹 AI 모드). — 구현 완료.

## 5. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 답변에 잡담+코드블록 혼재 | 코드펜스 추출이 흡수 (§2-2 1단계) |

## 6. 검증 계획 (e2e91)

클립보드는 Playwright 권한 부여(`clipboard-read/write`)로 실측:

1. 웹 AI 모드 기본 표시(키 미등록) + 모드 전환
2. `[① 프롬프트 복사]` → 클립보드에 EMM_SYSTEM_PROMPT·주제·출력 지시 포함
3. 모의 AI 답변(잡담 + ```emm 코드블록```)을 답변창에 paste 이벤트로
   주입 → 미리보기 노드 수 일치 → 맵 생성 → 캔버스 노드 수 검증
4. 코드블록 없는 잡담 paste → 실패 안내 + 재요청 문구 복사 동작
5. 노드 선택 상태에서 [선택 노드에 삽입] → 하위 트리 삽입 검증
6. 기존 API 모드 회귀 (모드 스위치 후 기존 흐름 그대로)

## 8. 참고 사례 — ChatGPT 'Mind map Copilot'의 방식

WiseMapping 제작자가 올린 **커스텀 GPT**다. 구조는 두 겹:

1. **지침(Instructions)** = 우리의 EMM_SYSTEM_PROMPT 에 해당하는
   시스템 프롬프트를 GPT 안에 미리 심어 둔 것. 사용자는 주제만 치면
   되고, 맵 구조 출력 규칙은 GPT가 이미 알고 있다.
2. **Actions** = GPT 가 WiseMapping **API 를 직접 호출**(OpenAPI 선언
   기반)해 맵 파일을 만들고 열람/편집 링크를 돌려주는 부분. 즉
   "AI 플랫폼이 맵 서비스 쪽으로 호출해 들어오는" 구조 — 우리
   **방법 C(Claude MCP 커넥터)의 ChatGPT 판**이다.

우리에게 주는 시사점 (두 단계로 흡수):

- **지금 (방법 A 보완, 공짜)**: 'EasyMindMap Copilot' 커스텀 GPT 를
  우리가 만들어 공개한다 — 지침에 EMM_SYSTEM_PROMPT 를 심으면
  ChatGPT 사용자는 **① 프롬프트 복사 단계가 아예 사라진다**
  (GPT 에 주제만 입력 → 답변 복사 → EasyMindMap 에 붙여넣기).
  코드 0줄, GPT 등록만 하면 된다. Claude 쪽도 동일하게 '프로젝트/
  스타일 지침'으로 배포 가능. §3-2 의 [ChatGPT] 바로가기 버튼을
  이 GPT 주소로 연결한다.
- **중기 (방법 C)**: Actions/MCP 로 저장까지 자동화 — 아래 §9.

### 8-1. ChatGPT '플러그인' 목록의 마인드맵 3종 (MindMap · getMindmap · MockFlow)

플러그인(현 ChatGPT Apps) 탭에 노출되는 제품들은 커스텀 GPT 보다
한 단계 깊은 통합이다:

- **동작 방식**: 제작사가 자기 서버를 ChatGPT 에 **앱으로 등록**
  (MCP 기반 Apps SDK — 예전 플러그인의 후신). 사용자가 대화 중
  "마인드맵으로 그려줘" 하면 ChatGPT 가 **그 회사 서버의 API 를
  호출**해 맵을 만들고, 결과(이미지·인터랙티브 위젯·편집 링크)를
  대화 안에 바로 렌더링한다.
- 커스텀 GPT(§8)와의 차이: GPT 는 "그 GPT 를 골라 들어가야" 쓰지만,
  앱/플러그인은 **아무 대화에서나 호출**되고 스토어 검색에 노출되며
  대화 안에 자체 UI 를 띄울 수 있다.
- 본질은 방법 C 와 같다 — **AI 플랫폼이 우리 서버를 호출해 들어오는
  구조**. MCP 서버 하나를 잘 만들면 Claude 커넥터와 ChatGPT 앱을
  같은 코드로 서비스할 수 있다.

## 적용 대상 선택과 자동 실행 (2026-08-04)

③ 답변 붙여넣기 위에 **적용 대상** 토글이 있다 — `새 맵으로` /
`'노드명' 하위에 삽입`(노드 선택 시에만 활성). 자동 실행 체크
("붙여넣는 즉시 실행")과 실행 버튼의 주황 강조가 모두 이 선택을
따른다. 이전에는 자동 실행이 항상 새 맵으로만 갔고 새 맵 버튼만
강조돼, 삽입을 원한 사용자가 혼란을 겪었다(실사용 보고).

② 단계에는 **드래그 복사 경고**가 있다 — 렌더된 답변을 화면에서
드래그해 복사하면 코드 펜스 마커가 소실되어, 코드·도식 블록이
일반 문단으로 붙어 깨진다. 반드시 답변 끝의 ⧉ 복사 버튼을 쓰도록
안내한다. (같은 이유로 EMM 템플릿 v4.1은 ASCII 아트 도식 자체를
금지한다 — 한글 폭 문제로 코드 패널에서도 어긋난다.)
