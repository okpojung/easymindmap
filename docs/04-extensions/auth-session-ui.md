## 0. 무엇이 문제였나

로그인 전에도 에디터가 그대로 열렸고, 맵을 여는 통로가 **상단 ☁ 클라우드
드롭다운**과 **좌측 새 맵 > ☁ 서버 맵 불러오기** 두 곳이었으며, 히스토리
복원은 지금 보던 맵을 화면에서 밀어냈다. 로그아웃은 클라우드 메뉴 안에
숨어 있었다.

## 1. 로그인 게이트 — 로그인 전에는 에디터를 열지 않는다

**정책(사용자 결정): 완전 차단.** 인증이 켜진 배포에서 로그인하지 않은
방문자에게는 **소개(슬로건 + 핵심 가치 3가지) + 로그인 카드**만 보인다.

- 근거: 맵은 계정에 저장된다. 로그인 없이 편집을 시작하면 "저장할 곳이
  없는 작업"이 되어 내용을 잃기 쉽다.
- 구현: `components/auth/WelcomeScreen.tsx` — `EditorPage` 가
  `authEnabled && !session` 이면 이 화면만 렌더한다.
- **개발 모드(`VITE_SUPABASE_URL` 미설정)에서는 게이트가 없다** —
  로컬 개발·E2E 흐름은 그대로 에디터가 열린다.
- 소개 문구는 [product-highlights.md](../01-product/product-highlights.md)
  의 "한 줄 소개"·"5가지 약속"에서 가져온다(문서와 화면이 어긋나지 않도록).

### 로그인 방식 확장 (SNS·SSO)

로그인 수단은 앞으로 늘어난다. 그래서 **제공자 목록을 데이터로** 둔다:

```ts
// components/auth/LoginForm.tsx
export const SOCIAL_PROVIDERS: SocialProvider[] = [
  { id: 'kakao',  label: '카카오로 계속하기', mark: 'K', color: '#FEE500', enabled: false },
  { id: 'naver',  label: '네이버로 계속하기', mark: 'N', color: '#03C75A', enabled: false },
  { id: 'google', label: 'Google로 계속하기', mark: 'G', color: '#4285F4', enabled: false },
];
```

목록은 **카카오 → 네이버 → Google** (Apple 제외 — 2026-08-04 사용자
결정, §9 와 동일). 새 방식이 준비되면 **항목을 추가하고 `enabled: true`
로 바꾸는 것**만으로 붙는다. 지금은 자리만 보이고 "준비 중" 배지가 붙는다.

> `mark` 는 브랜드 로고를 붙이기 전의 임시 글리프(K·N·G)다.

## 4. 탭 모델 — 다른 맵은 **브라우저 새 탭**(`?map=<id>`)

**결정(사용자): 앱 내부 탭이 아니라 브라우저 탭.**

| | 브라우저 새 탭 (채택) | 앱 내부 탭 |
|---|---|---|
| 스토어 구조 | 단일 문서 그대로 | 문서·undo 히스토리를 맵마다 다중화 |
| 메모리 격리 | 탭마다 완전 격리 | 한 프로세스에 누적(이미지 data URL 때문에 큼) |
| 동시 개수 제한 | 불필요(브라우저가 관리) | 정해야 함 |

- URL: `?map=<mapId>` — 부팅 시 `initialMapId` 로 1회 확정하고 그 문서를
  불러온다(`services/cloud/mapSession.ts`). 이때 샘플 맵 주입은 건너뛰고,
  불러오는 동안 빈 문서를 보여 준다(샘플이 잠깐 비치지 않도록).
- **이 탭에 그대로 여는 경우**: 잃을 것이 없을 때만 —
  서버 맵과 연결돼 있지 않고(`cloudMapId` 없음), 문서가 비었거나
  (맵 닫기 직후) 첫 화면 그대로 손대지 않았을 때(`past.length === 0`).
  이 판단이 `canReuseThisTab()`이다.
- **이미 이 탭에서 편집 중인 맵**을 다시 고르면 새 탭을 만들지 않고
  알린다 — 두 탭이 같은 맵을 자동저장하며 서로 덮어쓰는 것을 막는다.
- 히스토리 복원("새 탭으로")도 같다: 그 시점 내용을
  `제목_history_YYMMDD_HHMM` 새 맵으로 저장한 뒤 **새 탭**에서 연다.
  지금 편집 중인 맵은 건드리지 않는다.

> ⚠️ **`window.open(url, '_blank', 'noopener')` 은 항상 `null` 을 돌려준다**
> — 탭이 정상적으로 열려도 "팝업 차단"으로 오인하게 된다. 같은 출처의
> 우리 페이지를 여는 것이므로 `noopener` 없이 열고 `w.opener = null` 로
> 끊는다. (2026-08-02 실측)

## 5. 상단 툴바 — ☁ 저장 · ✕ 맵 닫기

| 버튼 | 하는 일 |
|---|---|
| **☁ 저장** | 지금 내용을 서버에 저장하고 **히스토리 버전으로 남긴다**(B8 — 자동저장은 버전을 남기지 않는다). 첫 저장은 폴더·이름을 묻는다([document-library.md](document-library.md) §3) |
| **✕ 맵 닫기** | 저장한 뒤 닫고 문서함을 연다. **아직 저장한 적 없는 맵은 경고**한다(같은 문서 §4) |

- 맵 닫기는 저장이 먼저다 — **저장에 실패하면 닫지 않는다**(내용 유실
  방지). 로그인하지 않아 저장할 수 없을 때만 "저장 없이 닫을까요?"를
  묻는다.
- 아직 서버에 없는 맵은 **"저장되지 않았습니다" 경고** 후 사용자가
  고른다 (2026-08-02 후속 지시로 갱신 — 처음에는 무조건 저장이었다).
- 실수로 닫아도 **Ctrl+Z** 로 문서가 되돌아온다.
- 저장·닫기·열기 로직은 `services/cloud/mapSession.ts` 한 곳에 모았다 —
  상단 툴바·좌측 패널·히스토리 패널이 같은 규칙을 따른다.

| 기능 | Guest |

| 서버 저장·불러오기·히스토리 | ❌ (☁ 저장 = "가입 후 가능" 안내) |
| 첨부파일 | ❌ (링크·첨부 탭 = 안내만) |
| AI — API 키 방식 | ❌ |
| 내 문서(문서함) | ❌ — 빈 목록 대신 **안내 화면**(GuestBrowserNotice: "Guest 체험 중… 가입하면 저장·첨부·히스토리" + [가입하고 시작하기]) |

목록은 버그로 오해되고, 안내는 가입 전환 통로가 된다 (사용자 승인).

## 10. 맵 단일 세션 편집 잠금 (2026-08-04)

같은 맵을 여러 브라우저·탭·PC 에서 동시에 편집해 서로 덮어쓰는 사고
방지. **한 세션만 편집하고, 나머지는 읽기 전용**으로 연다 (거부 대신
읽기 모드 — 사용자 결정).

- **세션 키**: 탭마다 고유(sessionStorage `emm.editSession`) — 같은
  브라우저의 다른 탭도 "다른 세션"이다.
- **잠금**: `map_edit_locks(map_id PK, session_key, heartbeat_at)`.
  문서 열기(GET document?editSession=)가 잠금을 시도해 `editLock:
  'acquired' | 'busy'` 를 돌려준다. 편집 탭은 25초마다 하트비트,
  **60초 TTL** 을 넘기면 죽은 잠금으로 보고 다른 세션이 가져간다
  (탭 강제 종료 대비 — beforeunload 해제는 불가하므로 TTL 이 정리).
- **busy = 읽기 전용 열기**: 서버 링크를 만들지 않아 자동저장·저장이
  그 맵에 쓰지 않는다. 상단에 **"🔒 읽기 전용 — 다른 세션에서 편집
  중" 배너** 상시 표시(사용자 요청) + 열 때 토스트. ☁ 저장을 누르면
  새 맵(사본) 저장 대화상자가 뜬다. 맵 닫기는 저장 없이 닫힌다.
- **저장 충돌 차단**: PUT document 는 editSession 을 싣고, 다른 살아
  있는 세션이 잠금을 쥐고 있으면 **409** "다른 세션(브라우저)에서
  편집 중인 맵입니다".
- **해제**: 맵 닫기·새 문서 전환(detach) 시 edit-release. 내 세션의
  저장은 하트비트를 겸한다.

Guest 메뉴 확정(2026-08-04 2차): 항목은 **로그아웃** 하나(동작 =
Guest 종료 → 로그인 화면), 개인 설정·계정 프로필·구독 상태는 Guest
에게 숨긴다.

## 11. 회원가입 — 이메일 인증 · 성명 · 휴대폰 (2026-08-09 사용자 요청)

> "로그인 화면에서 이메일과 비밀번호를 넣고 가입 버튼을 누르면 바로
> 가입이 되는 것 같은데, 이메일 인증·성명·휴대폰번호를 받아서 free
> 계정으로 가입시켜 달라."

예전에는 로그인 폼의 [가입] 이 곧바로 계정을 만들었다. 이제 **가입 화면
(`SignupForm`)** 으로 넘어가 아래를 받는다. 요금제는 **free** —
`users.plan` 기본값이라 프런트가 따로 보내지 않는다.

| 받는 것 | 필수 | 비고 |
|---|---|---|
| 이메일 주소 | ✅ | **인증번호 확인을 마쳐야** 가입 버튼이 열린다 |
| 성명 | ✅ | `users.full_name` |
| 휴대폰번호 | 선택 | **국가번호 + 번호**를 나눠 받는다 |
| 비밀번호 (+확인) | ✅ | 6자 이상 (GoTrue `GOTRUE_PASSWORD_MIN_LENGTH` 와 맞춤) |

### 11.1 흐름 — 왜 세 단계로 나뉘나

```
① [이메일 인증]  POST /v1/account/email-code         6자리 코드 메일
② 코드 확인      POST /v1/account/email-code/verify  → 인증표(emailToken)
③ [가입하기]     GoTrue signUp → 로그인 → PUT /v1/account/profile
                 (성명·휴대폰 + ②의 인증표)
```

**가입은 GoTrue 에서 일어난다.** 그래서 ②와 ③ 사이에 세션이 새로 생기고,
그 사이를 잇는 증거가 필요하다 — 그것이 **인증표**다. DB 를 다시 뒤지지
않고 서명만 검증하면 되는 값이라 단순하다.

* 형식 `<이메일 base64url>.<만료 epoch초>.<HMAC 서명>`, 유효 **30분**
* **표가 "어느 이메일을 확인했는지" 스스로 말한다** — 검증할 때 이메일을
  따로 받아야 하면, 세션에 이메일이 없는 경우(`AUTH_MODE=dev` 스텁은
  id 만 준다) 맞춰 볼 것이 없어 가입을 마칠 수 없다.
* 서버는 세션이 이메일을 알면 **같은지 확인**하고, 모르면 표를 믿는다
  (표는 우리 서명이다).
* ①과 ②는 **로그인 전**에 부르므로 무인증이다. 프런트도 그 두 호출만
  토큰을 붙이지 않는다(`apiClient.req(..., anon)`) — 이 표시가 없으면
  인증이 켜진 배포에서 401 이 나 **가입 자체가 막힌다**.

### 11.2 남용 방지 (`account.service.ts` 상단 상수)

| 항목 | 값 | 왜 |
|---|---|---|
| 코드 자릿수 | 6 | 앞자리 0 도 나오게 문자열로 다룬다 |
| 유효 시간 | 10분 | |
| 틀릴 수 있는 횟수 | 5회 | 넘으면 다시 받아야 한다 |
| 재발송 간격 | 60초 | 남의 메일함을 두드리는 데 쓰이지 않게 |
| 시간당 발송 | 5회 | |

코드는 **평문으로 두지 않는다** — `sha256` 해시만 담는다. 메일로 이미
보낸 값이라 DB 가 새어도 그것만으로는 못 쓴다.

### 11.3 휴대폰 — 왜 국가번호를 나누나

처음부터 **Global 서비스를 염두에 둔 결정**(사용자 지시)이다. 한 칸에
통째로 받으면 나라마다 표기가 달라(앞의 0 을 떼는 나라·붙이는 나라)
나중에 SMS 인증을 붙일 때 서버가 국가를 되짚어야 한다.

* 저장: `phone_country`(`+82`) · `phone_number`(숫자만)
* 국가 목록은 `utils/countryCodes.ts` — 31개국. 200여 개를 전부 나열하면
  고르기가 더 어려워서 추렸고, **이름·ISO·번호 어느 쪽으로도 찾힌다**
  (`한국` · `kr` · `82`).
* 보기 좋게 끊는 것은 **한국 번호만** 한다 — 나라마다 묶음이 달라
  어설프게 끊으면 잘못된 번호처럼 보인다.
* **휴대폰 인증은 아직 없다.** `phone_verified_at` 은 자리만 만들어 두고
  항상 NULL 이다. 화면에도 "휴대폰 인증은 준비 중"이라고 적는다.

### 11.4 메일 발송 — 우리 API 가 보낸다

인증번호는 **우리 API** 가 보낸다(`mail/mail.service.ts`). 앞으로 나갈
메일이 여럿이고(재설정·협업 초대·용량 알림) 문구·발신자·재발송 제한을
한 규칙으로 묶어야 하기 때문이다. GoTrue 에 맡기면 가입 메일만 그쪽
규칙을 따르는 이상한 구조가 된다.

**통로는 환경변수로 갈아 끼운다** — 첨부 저장소의 `STORAGE_DRIVER` 와
같은 방식이다.

```
SMTP_HOST=smtp.gmail.com     # Google Workspace (하루 약 2,000통,
SMTP_PORT=587                #   자기 도메인 발신 가능)
SMTP_USER=noreply@<도메인>    # 무료 Gmail 은 From 을 덮어써서 못 쓴다
SMTP_PASS=<앱 비밀번호 16자리>  # 2단계 인증이 켜져 있어야 만들 수 있다
SMTP_FROM=EasyMindMap <noreply@<도메인>>   # 생략 가능
```

나중에 발송량이 늘거나 "메일이 안 온다"는 문의가 쌓이면 **SES·Resend·
Postmark 로 호스트/계정만 교체**한다. 반송(bounce)·스팸신고를 알려 주므로
원인을 추적할 수 있다. **코드는 바뀌지 않는다.**

**설정이 없어도 앱은 죽지 않는다.**

* 운영: 인증번호 요청이 "메일 발송이 아직 설정되지 않았습니다"로 거절된다
* 개발(`AUTH_MODE=dev`): 코드를 **응답과 서버 로그에 남겨** 메일 없이도
  가입 흐름 전체를 시험할 수 있다. 화면은 그 사실을 함께 밝힌다 —
  "메일 발송이 설정되지 않아 화면에 표시합니다".
  운영 모드에서는 이 값이 절대 나가지 않는다.


### 11.5 가입 뒤

세션이 곧바로 오면(`GOTRUE_MAILER_AUTOCONFIRM=true`) **바로 로그인되어
앱이 열린다.** 가입 확인 메일을 요구하는 서버면 세션이 없으므로 로그인
화면으로 돌아가 "메일함에서 확인한 뒤 로그인해 주세요"를 안내한다.

### 11.6 발신 계정 만들기 — `noreply@easymindmap.org` (2026-08-09)

인증 메일은 **앱과 같은 도메인**에서 나가야 한다. 낯선 도메인에서 오면
사용자가 스팸으로 신고하고, 신고가 쌓이면 그 계정에서 나가는 **모든
메일**의 도달률이 떨어진다. 운영 도메인 계획은 `vision.md` 참조.

#### ① 도메인을 Workspace 에 넣는다 — **보조 도메인**으로

관리 콘솔(admin.google.com) → **계정 → 도메인 → 도메인 관리 →
도메인 추가** → `easymindmap.org` → **보조 도메인** 선택.

| 고르는 것 | 무엇이 되나 | `noreply@` 를 만들 수 있나 |
|---|---|---|
| **보조 도메인** ✅ | 이 도메인에 **원하는 이름의 주소**를 만들 수 있다. 나중에 **기본 도메인으로 승격**도 된다 | **된다** |
| 사용자 별칭 도메인 | 기존 계정의 **아이디를 그대로 복사**한다 (`ok@baro.pro` → `ok@easymindmap.org`) | **안 된다** |

> ⚠️ **별칭 도메인으로는 `noreply@` 를 만들 수 없다.** 아이디가 그대로
> 따라오는 구조라 다른 이름을 붙일 수 없다 (2026-08-09 — 처음에 별칭
> 도메인을 권했다가 실제 화면에서 확인하고 바로잡았다).
> `easymindmap.org` 가 앞으로 주도메인이 될 예정이라는 점에서도
> **승격이 가능한 보조 도메인**이 맞다.
>
> **보조 도메인 자체는 무료다.** 사용자를 새로 만들면 라이선스가 들지만,
> **별칭만 추가하면 돈이 들지 않는다**(②).

추가하면 소유 확인용 **TXT 레코드**를 준다 — 도메인 등록대행사 DNS 에
넣는다. 메일 수신도 하려면 **MX 레코드**를 함께 넣는다 (발송만 할
거라도 넣는 편이 낫다 — 안 넣으면 **반송 통지를 받지 못한다**).

#### ② 발신 주소를 만든다 — 별칭이 가장 싸다

| 방법 | 비용 | 하는 법 |
|---|---|---|
| **기존 계정에 별칭 추가** (권장) | **무료** | 관리 콘솔 → 디렉터리 → 사용자 → 해당 사용자 → **대체 이메일 주소(별칭)** 에 `noreply@easymindmap.org` 추가 |
| 전용 사용자 생성 | 라이선스 1개 | 사용자 추가 → `noreply@easymindmap.org` |

별칭은 Gmail 의 "다른 주소에서 메일 보내기"에 자동으로 등록되므로,
**그 계정의 앱 비밀번호로 로그인해 별칭 주소로 발송**할 수 있다.
반영에 몇 분에서 최대 24시간이 걸릴 수 있다.

#### ③ 앱 비밀번호를 발급한다

**기존 앱 비밀번호를 재사용하지 않는다** — 다른 서비스와 공유하면
하나를 폐기할 때 둘 다 멈추고, 어느 쪽이 보냈는지 추적도 안 된다.
(하루 발송 한도는 **계정 단위**라 새로 만들어도 한도는 함께 쓴다.)

1. 그 계정으로 로그인 → **Google 계정 → 보안 → 2단계 인증** 켜기
   (앱 비밀번호는 2단계 인증이 켜져 있어야 만들 수 있다)
2. 같은 화면 → **앱 비밀번호** → 이름 `easymindmap-dev` → 16자리 발급
3. 안 보이면 관리 콘솔에서 막아 둔 것이다 —
   **보안 → 액세스 및 데이터 제어 → 덜 안전한 앱** 정책을 확인한다

#### ④ 새 도메인의 메일 인증 레코드 (도달률) — **미루지 않는다**

도메인을 새로 붙였으면 **셋 다** 넣는다. 없으면 인증번호가 스팸함으로
간다. 도메인 설정 마침 화면의 **"발신 이메일 인증 → 인증"** 이 이 중
DKIM 을 안내한다 — "선택적 설정 단계"로 적혀 있지만 **거래 메일을 보낼
거라면 선택이 아니다.**

| 종류 | 이름 (호스트) | 값 |
|---|---|---|
| **SPF** | `@` (도메인 루트) TXT | `v=spf1 include:_spf.google.com ~all` |
| **DKIM** | `google._domainkey` TXT | 아래 절차로 생성된 값 |
| **DMARC** | `_dmarc` TXT | `v=DMARC1; p=none; rua=mailto:postmaster@easymindmap.org` |

**DKIM 생성 절차** (관리 콘솔 → 앱 → Google Workspace → **Gmail** →
**이메일 인증**):

1. 위쪽에서 **도메인을 `easymindmap.org` 로 바꾼다** — 기본값은 기본
   도메인이라, 그대로 두면 **엉뚱한 도메인의 키를 만든다**
2. **새 레코드 생성** → 키 길이는 **2048비트** (DNS 가 긴 TXT 를 못 받으면
   1024)
3. 나온 **호스트(`google._domainkey`)와 TXT 값**을 등록대행사 DNS 에 추가
4. DNS 가 퍼진 뒤(보통 몇 분, 최대 48시간) **"인증 시작"** 을 누른다 —
   **이 버튼을 누르지 않으면 상태가 "인증 안 됨"으로 남는다**

⚠️ **SPF 는 도메인당 한 줄만 둔다.** 이미 있으면 새로 추가하지 말고
기존 줄에 `include:_spf.google.com` 을 합친다. 두 줄이면 둘 다 무효다.

> DMARC 는 **`p=none` 으로 시작**한다. 처음부터 `reject` 로 두면 설정이
> 덜 됐을 때 정상 메일까지 버려진다. `rua` 로 오는 보고서를 며칠 보고
> `quarantine` → `reject` 로 올린다.

#### ⑤ 서버에 넣는다 (Coolify → api → 재배포)

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=<앱 비밀번호를 만든 계정 주소>       # 로그인할 계정
SMTP_PASS=<앱 비밀번호 16자리>
SMTP_FROM=EasyMindMap <noreply@easymindmap.org>  # 받는 사람에게 보이는 주소
```

`SMTP_USER` 와 `SMTP_FROM` 이 **다를 수 있다** — 로그인은 실제 계정으로
하고, 보이는 주소는 별칭으로 두는 구성이다. 별칭이 그 계정에 붙어 있지
않으면 Google 이 From 을 계정 주소로 덮어쓴다.

#### ⑥ 확인

가입 화면에서 [이메일 인증]을 눌러 메일이 오는지 본다. 안 오면 순서대로:

1. **api 로그의 오류 문구** — 인증 실패(535)면 앱 비밀번호 문제다
2. **스팸함** — 있으면 ④의 SPF/DKIM/DMARC 를 확인한다
3. **From 주소가 계정 주소로 바뀌었나** — ②의 별칭이 아직 반영되지 않은 것이다

검증: E2E e2e136
