## 0. 무엇이 문제였나

로그인 전에도 에디터가 그대로 열렸고, 맵을 여는 통로가 **상단 ☁ 클라우드
드롭다운**과 **좌측 새 맵 > ☁ 서버 맵 불러오기** 두 곳이었으며, 히스토리
복원은 지금 보던 맵을 화면에서 밀어냈다. 로그아웃은 클라우드 메뉴 안에
숨어 있었다.

## 1. 로그인 게이트 — 로그인 전에는 에디터를 열지 않는다

**정책(사용자 결정): 완전 차단.** 인증이 켜진 배포에서 로그인하지 않은
방문자에게는 **소개(슬로건 + 핵심 가치 3가지) + 로그인 카드**만 보인다.

- 근거: 맵은 계정에 저장된다. 로그인 없이 편집을 시작하면 "저장할 곳이
  없는 작업"이 되어 내용을 잃기 쉽다.
- 구현: `components/auth/WelcomeScreen.tsx` — `EditorPage` 가
  `authEnabled && !session` 이면 이 화면만 렌더한다.
- **개발 모드(`VITE_SUPABASE_URL` 미설정)에서는 게이트가 없다** —
  로컬 개발·E2E 흐름은 그대로 에디터가 열린다.
- 소개 문구는 [product-highlights.md](../01-product/product-highlights.md)
  의 "한 줄 소개"·"5가지 약속"에서 가져온다(문서와 화면이 어긋나지 않도록).

### 로그인 방식 확장 (SNS·SSO)

로그인 수단은 앞으로 늘어난다. 그래서 **제공자 목록을 데이터로** 둔다:

```ts
// components/auth/LoginForm.tsx
export const SOCIAL_PROVIDERS: SocialProvider[] = [
  { id: 'google', label: 'Google로 계속하기', mark: 'G', color: '#4285F4', enabled: false },
  { id: 'kakao',  label: '카카오로 계속하기', mark: 'K', color: '#FEE500', enabled: false },
  { id: 'apple',  label: 'Apple로 계속하기',  mark: 'A', color: '#111111', enabled: false },
];
```

새 방식이 준비되면 **항목을 추가하고 `enabled: true` 로 바꾸는 것**만으로
붙는다. 지금은 자리만 보이고 "준비 중" 배지가 붙는다.

> `mark` 는 브랜드 로고를 붙이기 전의 임시 글리프다. Apple 심볼()처럼
> 폰트에 없으면 빈칸으로 보이므로 영문 대문자를 쓴다.

## 2. 계정 메뉴 — 우상단 아바타

계정에 딸린 것은 모두 아바타 메뉴로 모은다 (`top-toolbar/UserMenu.tsx`).

| 항목 | 상태 | 담당 |
|---|---|---|
| 이메일 + 로그인 상태 | ✅ | — |
| ⚙ 개인 설정 | 준비 중 | B10 다국어(언어 선택) |
| 👤 계정 프로필 | 준비 중 | 계정 관리 |
| 💳 구독 상태 | 준비 중 | B9 첨부 저장소(요금제·용량) |
| 🚪 로그아웃 | ✅ | — |

**구현 전 항목도 자리를 미리 만든다** — 나중에 메뉴 구조가 흔들리지
않도록. 누르면 무엇이 들어올지 한 줄로 안내한다.

## 3. 맵을 여는 통로는 하나 — 좌측 '☁ 서버 맵 불러오기'

상단의 ☁ 클라우드 드롭다운에 있던 "클라우드에서 열기"를 없앴다.
목록 UI 는 2026-08-02 문서함 도입에서 팝업 모달(MapListModal)에서
**편집 영역의 문서함**(`components/cloud/MapBrowser.tsx`)으로 바뀌었다 —
[document-library.md](document-library.md) §5.

## 4. 탭 모델 — 다른 맵은 **브라우저 새 탭**(`?map=<id>`)

**결정(사용자): 앱 내부 탭이 아니라 브라우저 탭.**

| | 브라우저 새 탭 (채택) | 앱 내부 탭 |
|---|---|---|
| 스토어 구조 | 단일 문서 그대로 | 문서·undo 히스토리를 맵마다 다중화 |
| 메모리 격리 | 탭마다 완전 격리 | 한 프로세스에 누적(이미지 data URL 때문에 큼) |
| 동시 개수 제한 | 불필요(브라우저가 관리) | 정해야 함 |

- URL: `?map=<mapId>` — 부팅 시 `initialMapId` 로 1회 확정하고 그 문서를
  불러온다(`services/cloud/mapSession.ts`). 이때 샘플 맵 주입은 건너뛰고,
  불러오는 동안 빈 문서를 보여 준다(샘플이 잠깐 비치지 않도록).
- **이 탭에 그대로 여는 경우**: 잃을 것이 없을 때만 —
  서버 맵과 연결돼 있지 않고(`cloudMapId` 없음), 문서가 비었거나
  (맵 닫기 직후) 첫 화면 그대로 손대지 않았을 때(`past.length === 0`).
  이 판단이 `canReuseThisTab()`이다.
- **이미 이 탭에서 편집 중인 맵**을 다시 고르면 새 탭을 만들지 않고
  알린다 — 두 탭이 같은 맵을 자동저장하며 서로 덮어쓰는 것을 막는다.
- 히스토리 복원("새 탭으로")도 같다: 그 시점 내용을
  `제목_history_YYMMDD_HHMM` 새 맵으로 저장한 뒤 **새 탭**에서 연다.
  지금 편집 중인 맵은 건드리지 않는다.

> ⚠️ **`window.open(url, '_blank', 'noopener')` 은 항상 `null` 을 돌려준다**
> — 탭이 정상적으로 열려도 "팝업 차단"으로 오인하게 된다. 같은 출처의
> 우리 페이지를 여는 것이므로 `noopener` 없이 열고 `w.opener = null` 로
> 끊는다. (2026-08-02 실측)

## 5. 상단 툴바 — ☁ 저장 · ✕ 맵 닫기

| 버튼 | 하는 일 |
|---|---|
| **☁ 저장** | 지금 내용을 서버에 저장하고 **히스토리 버전으로 남긴다**(B8 — 자동저장은 버전을 남기지 않는다). 첫 저장은 폴더·이름을 묻는다([document-library.md](document-library.md) §3) |
| **✕ 맵 닫기** | 저장한 뒤 닫고 문서함을 연다. **아직 저장한 적 없는 맵은 경고**한다(같은 문서 §4) |

- 맵 닫기는 저장이 먼저다 — **저장에 실패하면 닫지 않는다**(내용 유실
  방지). 로그인하지 않아 저장할 수 없을 때만 "저장 없이 닫을까요?"를
  묻는다.
- 아직 서버에 없는 맵은 **"저장되지 않았습니다" 경고** 후 사용자가
  고른다 (2026-08-02 후속 지시로 갱신 — 처음에는 무조건 저장이었다).
- 실수로 닫아도 **Ctrl+Z** 로 문서가 되돌아온다.
- 저장·닫기·열기 로직은 `services/cloud/mapSession.ts` 한 곳에 모았다 —
  상단 툴바·좌측 패널·히스토리 패널이 같은 규칙을 따른다.

## 8. Guest 체험 모드 (2026-08-04)

가입 장벽을 낮추기 위한 로컬 전용 체험. 로그인 화면의 **"Guest로
체험하기 (가입 없이)"** 버튼으로 진입한다 (`authStore.guest` — 세션과
배타적, 로그인·가입하면 자동 해제).

| 기능 | Guest |
|---|---|
| 에디터 편집 (샘플 맵으로 시작) | ✅ |
| MD·HTML 내보내기 / 로컬 파일 불러오기 | ✅ |
| AI — 웹 AI(클립보드 왕복) | ✅ (모드 스위치·AI 설정 숨김) |
| 서버 저장·불러오기·히스토리 | ❌ (☁ 저장 = "가입 후 가능" 안내) |
| 첨부파일 | ❌ (링크·첨부 탭 = 안내만) |
| AI — API 키 방식 | ❌ |
| 내 문서(문서함) | ❌ — 빈 목록 대신 **안내 화면**(GuestBrowserNotice: "Guest 체험 중… 가입하면 저장·첨부·히스토리" + [가입하고 시작하기]) |

계정 메뉴 아바타는 'G', 헤더 "Guest 체험 중", [가입하고 시작하기] =
exitGuest → 로그인 화면. **빈 화면이 아니라 안내 화면**인 이유: 빈
목록은 버그로 오해되고, 안내는 가입 전환 통로가 된다 (사용자 승인).

## 9. 로그인 첫 화면 규칙 (2026-08-04)

로그인(또는 Guest 진입) 시 **좌측 패널 = 새 맵 메뉴**로 고정한다
(EditorPage 세션 전환 효과에서 `setNavTab('newMap')`). 시크릿창처럼
저장된 UI 상태가 없으면 기본값('스타일' 인스펙터)이 떠 어색했던 문제의
수정 — 문서함이 메인인 첫 화면에서 노드 속성 패널은 무의미하다.
SNS 로그인 버튼은 **카카오 → 네이버 → Google** 순(전부 준비 중,
Apple 제외 — 2026-08-04 사용자 결정).
