| # | 갈림길 | 결정 | 왜 |

**수락이 필요한 것은 소유권 이전 하나다.** 초대는 받는 쪽에 부담(용량·책임)이
없으므로 즉시이고, 소유권은 부담이 옮겨 가므로 제안→수락이다(13a §4.5.1 의
"왜 수락이 필요한가").

### 1.1 ★ 발견한 구멍 — 협업맵의 첨부는 **올린 사람** 소유다

`POST /attachments` 는 `owner_id = 올린 사람`, 저장 키 `u/<올린 사람>/<id>`,
용량도 올린 사람 몫으로 센다. 협업맵에서 **참가자**가 사진을 붙이면 그
첨부는 참가자 것이다. 그 참가자가 탈퇴하면 `attachments.owner_id` 의 CASCADE
로 행이 지워지고 `u/<참가자>` 접두사가 통째로 지워져 — **개설자의 맵에서
그림이 사라진다.** 13a §4.5 는 협업맵의 용량을 개설자 요금제로 보기로 했는데
실물이 아직 그렇지 않다.

소유권 이전은 이 구멍과 정면으로 만난다(첨부를 누구 것으로 옮길 것인가).
그래서 §3.4 에서 함께 정한다.

## 2. 초대

### 2.1 가입자 — 즉시 참여 (현행) + 알림 + 나가기

흐름은 지금 그대로다: 주인이 이메일·역할을 넣으면 `map_members` 에 행이
생기고 맵이 `kind='collab'` 으로 올라간다. 더하는 것 둘.

- **알림** — 메일 한 통("○○님이 '2027 사업계획'에 함께 편집으로 초대했습니다
  [열기]") + 문서함 상단 받은함(§4). 메일은 실패해도 초대는 성공이다 —
  참가자 행이 곧 초대다.
- **나가기** — 받은 사람이 `DELETE /collab/maps/:id/members/me` 로 자기 행을
  지운다. 주인의 **제외**와 같은 결과이고, 다시 초대받을 수 있다.
  공유받은 맵 행의 메뉴에 둔다.

### 2.2 미가입자 — 초대장

주인이 넣은 이메일에 계정이 없으면 **초대장을 만들고 메일을 보낸다.**
거절하지 않는다.

```
주인: 초대 (email, role)
  ├─ 계정 있음 → 2.1 (즉시 참가자)
  └─ 계정 없음 → collab_invites 행 + 메일 [가입하고 열기: /?invite=<token>]
                    ↓ 받은 사람이 가입 (이메일 인증 6자리 → 성명·휴대폰)
                    ↓ 로그인
                 자동 참여 — 인증된 이메일 == 초대장 이메일 이면 map_members 에 넣고
                            초대장을 accepted 로. 링크로 왔으면 그 맵을 연다
```

**자동 참여는 두 길로 일어난다** — 어느 쪽이 먼저든 결과는 같다.

1. **링크**: `/?invite=<token>` 으로 들어오면 프런트가 토큰을 붙들고
   가입·로그인을 지나, 로그인 뒤 `POST /collab/invites/accept {token}` 을
   부른다. 서버는 **로그인한 계정의 이메일**과 초대장 이메일이 같을 때만
   참가자로 넣는다. 토큰이 있어도 이메일이 다르면 거절한다 — 토큰은
   "어느 초대장인지" 이지 "누구인지" 가 아니다.
2. **이메일 매칭**: 링크 없이 그냥 가입해도 된다. 문서함을 열 때 받은함이
   `GET /collab/inbox` 를 부르고, 서버는 **내 이메일로 온 pending 초대장을
   전부 참가자로 바꾼다**(②의 "바로 문서함에" 규칙이 미가입자에게도 그대로
   적용된다). 그 뒤 "새로 공유된 맵 N개" 로 알린다.

만료 **14일**(소유권 이전 제안과 같은 값 — 값이 둘이면 설명이 둘이 된다).
만료된 초대장은 `expired` 로 두고 지우지 않는다(주인이 "보냈는데 왜 안
왔지" 를 확인할 수 있어야 한다). 주인은 ShareDialog 에서 **취소**·**재발송**
할 수 있고, 재발송은 새 토큰을 만들고 옛 토큰을 죽인다.

### 2.3 자동 참여의 근거 — 인증된 이메일

- 우리 가입은 이메일 인증번호 없이는 끝나지 않는다(auth-session-ui §11.1).
- SNS 로그인(카카오·네이버·Google)의 이메일은 제공자가 인증한 값이다.
- 그래서 `auth.users.email` 이 초대장 이메일과 같다는 것은 **그 사람이 그
  메일함의 주인**이라는 뜻이고, 초대장을 그 사람에게 이행해도 된다.

비교는 **소문자·앞뒤 공백 제거**로 한다(초대 API 가 이미 그렇게 저장한다).

### 2.4 pending 참가자를 `map_members` 에 넣지 않는다

참가자 표는 코어의 **권한 판정** 표다. 가입도 안 한 사람의 행이 거기 있으면
`GET /maps/shared`·참가자 수·탈퇴 차단 목록이 전부 "아직 없는 사람"을
센다. 초대장은 **유료 표(`collab_invites`)** 에 따로 두고, 사람이 생기는
순간에만 코어 표로 옮긴다. 코어는 초대장의 존재를 모른다 — 그래야 공개판이
예전과 똑같이 돈다.

## 3. 소유권 이전

### 3.1 제안 → 수락

- **제안자**: 맵의 주인. **대상**: 그 맵의 참가자 중 `role='editor'`(결정 ③).
- **한 맵에 열린 제안은 하나** — DB 의 부분 유니크 인덱스가 막는다(#380).
  두 번째 제안은 409 "이미 ○○님에게 제안 중입니다 — 취소하고 다시 하세요".
- **만료 14일**. 만료·거절된 제안은 남긴다(이력).
- 제안자는 언제든 **취소**할 수 있다(pending 일 때만). **취소는 행을 지운다**
  (2026-09-05 구현에서 정정) — 표의 `status` 는 pending·accepted·declined·expired
  넷뿐이고(코어 CHECK) 늘리려면 코어 스키마를 건드려야 한다. 제안자가 스스로
  거둔 것은 상대가 보기도 전일 수 있어 이력으로 남길 값어치가 낮다.
- 받는 사람은 **수락** 또는 **거절**. 거절에 이유는 받지 않는다.

### 3.2 용량 검사 — 두 번

```
받는 사람 사용량 + (맵 문서 + 그 맵의 버전 + 그 맵의 첨부) ≤ 받는 사람 한도
```

제안 때 계산해 **안내로 보여 주고**(받는 사람 화면 §8), 수락 순간 **다시
계산해 최종 판정**한다(그 사이 다른 파일을 올렸을 수 있다). 부족하면 409
"용량이 모자라 이전할 수 없습니다 — 필요 3.4 GB / 여유 2.1 GB" 로 답하고
제안은 pending 그대로 둔다(받는 사람이 정리하고 다시 수락한다).

용량 숫자는 코어 `attachments.service.ts` 의 사용량 식과 **같은 식**으로
센다(문서 + 버전 + 첨부, 전부 `owner_id` 기준). 다른 식을 만들면 화면의
사용량과 어긋난다.

### 3.3 수락 트랜잭션 — 이 순서로, 한 트랜잭션에서

```sql
BEGIN;
-- 0) 제안이 아직 pending 이고 만료 전인지 · 수락자가 to_user 인지 · 여전히 editor 인지
--    (SELECT … FOR UPDATE — 두 탭에서 동시에 수락해도 하나만 통과)
-- 1) 용량 검사 (§3.2) — 실패면 ROLLBACK, 409
-- 2) 맵의 주인 교체. 폴더는 옛 주인의 것이라 홈(NULL)으로
UPDATE public.maps SET owner_id = :to, folder_id = NULL, updated_at = NOW() WHERE id = :map;
-- 3) 이 맵에 달린 첨부 전부를 새 주인 것으로 (§3.4)
UPDATE public.attachments SET owner_id = :to WHERE map_id = :map;
-- 4) 참가자 표 — 새 주인은 뺀다(주인은 표에 없다), 옛 주인은 editor 로 남긴다
DELETE FROM public.map_members WHERE map_id = :map AND user_id = :to;
INSERT INTO public.map_members (map_id, user_id, role, invited_by)
     VALUES (:map, :from, 'editor', :to)
ON CONFLICT (map_id, user_id) DO UPDATE SET role = 'editor';
-- 5) 제안 마감
UPDATE public.map_ownership_transfers SET status = 'accepted', responded_at = NOW() WHERE id = :id;
COMMIT;
```

옮기지 않는 것: `kind`(협업맵 그대로), `map_document_versions`(맵에 붙어
있다 — §3.5), `published_maps`·`vault_files`·`map_edit_locks`(맵 단위),
유료 CRDT 저장소(맵 단위). **이름을 바꾸지 않는다** — 제목이 곧 정체성이다.

### 3.4 첨부 — 구멍을 메우는 결정 둘

**결정 A. 맵에 달린 첨부는 이전할 때 전부 새 주인 것이 된다** (§3.3 의 3).
누가 올렸든 `map_id` 가 이 맵이면 옮긴다. 용량 검사(§3.2)가 그 합을 이미
셌다. 저장 키(`u/<옛 주인>/…`)는 **그대로 둔다** — 키는 경로일 뿐이고, 읽기
판정은 `attachments.owner_id` 와 맵 권한으로 한다. 유료 모듈은 파일을 옮길
손(StorageService)이 없기도 하다.

**결정 B. 탈퇴가 파일을 지울 때 접두사가 아니라 행으로 지운다** — 코어 변경.
지금 `account.service.ts` 는 `u/<id>` 접두사를 통째로 지운다. 결정 A 뒤에는
그 접두사 아래에 **남의 맵 것이 된 파일**이 남아 있을 수 있다. 그래서 탈퇴는
`SELECT storage_key FROM attachments WHERE owner_id = 나` 로 **내 것만** 지우고,
`tmp/<id>` 접두사(업로드 조각)만 통째로 지운다. 이것이 없으면 이전받은 맵의
그림이 옛 주인 탈퇴와 함께 사라진다 — §1.1 의 구멍이 이전으로 재현되는 자리다.

**후속(별건, 코어)**: 협업맵에 **참가자가 올리는 첨부의 주인을 맵의 주인으로**
한다(`owner_id = maps.owner_id`, 용량도 주인 몫, 키도 `u/<주인>/…`). 13a §4.5
"협업맵의 기준은 개설자 요금제" 를 첨부에서 실제로 성립시키는 변경이고,
§1.1 의 구멍을 근본에서 막는다. 이 문서의 범위 밖이지만 **P1 다음에 바로**
한다 — 미루면 이전으로 옮긴 첨부와 그 뒤 올라온 첨부의 주인이 다시 갈린다.

### 3.5 자동 버전 — v1 결정: 맵과 함께 넘어간다

13a §4.5.2 는 "자동 버전은 넘어가지 않고 원 개설자 계정에 30일 남긴 뒤
ZIP 으로 내려받게 한다" 고 적었다. **v1 에서는 하지 않는다.**

- 버전 행은 `map_document_versions.map_id` 로 맵에 붙어 있어 사람에게 남길
  자리가 없다. 남기려면 복제 표가 필요하다.
- ZIP 내려받기는 `export` 큐를 전제로 하는데 그 큐가 아직 없다.
- 정리 워커(`version-prune`)도 아직 없어, 지금은 어느 요금제든 버전이 지워지지
  않는다. "넘어가면 새 요금제로 정리된다" 가 실제로 일어나는 날은 워커가 붙는
  날이고, 그때 13a §4.5.2 를 함께 붙이면 된다.

그래서 v1 은 **모든 버전(자동·영구보관)이 맵과 함께 새 주인에게 간다.**
받는 사람 화면(§8)에 "버전 N개도 함께 넘어옵니다" 를 적는다. 영구보관이
새 주인 상한을 넘으면 **유지하되 추가만 막는다**(13a §4.2 와 동일 — 워커
없이는 어차피 막을 것이 없다).

### 3.6 이전 뒤

- 원 개설자는 **editor 로 남는다**(13a). 나가는 것은 본인이 정한다(§2.1 나가기).
- 맵은 새 주인 문서함의 **홈**에 놓인다. 옛 주인에게는 '공유받은 맵' 구역으로
  옮겨 보인다.
- 참가자 전원에게 받은함 알림 "'2027 사업계획'의 개설자가 ○○님으로
  바뀌었습니다". 소켓 이벤트(`collab:ownership_transferred`)는 CRDT 게이트웨이가
  붙은 뒤 더한다 — 지금은 다음에 열 때 보이면 된다.
- 옛 주인의 탈퇴 차단 목록에서 그 맵이 빠진다(주인이 아니므로).

## 4. 알림 — 메일 + 받은함

| 사건 | 메일 | 받은함 |
|---|---|---|
| 가입자 초대 | ○ "함께 편집/읽기로 초대" [열기] | "새로 공유된 맵" |
| 미가입자 초대장 | ○ **필수** — 이것이 유일한 통로 [가입하고 열기] | (가입 뒤) "새로 공유된 맵" |
| 소유권 제안 | ○ [확인하기] | **"받은 제안"** — 수락/거절 버튼 |
| 수락·거절·취소·만료 | × | 제안자에게 결과 한 줄 |
| 주인 교체 | × | 참가자 전원에게 한 줄 |

**메일은 유료 모듈이 직접 보낸다.** 코어의 `MailService` 는 DI 로 넘어오지
않는다(유료 모듈은 자기 `Pool` 만 만든다). 같은 환경변수(`SMTP_HOST`·`SMTP_PORT`·
`SMTP_USER`·`SMTP_PASS`·`SMTP_FROM`)를 읽어 `nodemailer` 로 보낸다. 링크의 앱
주소는 `APP_URL`, 없으면 `CORS_ORIGIN` 의 첫 출처(그것이 곧 프런트 주소다) — 발신자·
서버가 같으므로 받는 사람에게는 같은 곳에서 온 메일이다. 메일이 실패해도
**초대·제안 자체는 성공**이다(행이 곧 사실이다). 실패는 로그와 ShareDialog
의 "메일을 보내지 못했습니다 — 링크를 직접 전해 주세요 [복사]" 로 드러낸다.

**받은함은 문서함 상단의 자리(`ProInbox`)** 다 — 코어가 자리를 두고 유료
모듈이 채운다(open-core-boundary §3.1 ③). 공개판은 아무것도 그리지 않는다.
받은함은 **저장하지 않는다** — 열 때마다 `GET /collab/inbox` 가 "아직
응답하지 않은 제안" 과 "최근 7일 안에 생긴 참가자 행/주인 교체" 를 그 자리에서
계산해 준다. 읽음 표시 표를 만들지 않는다: 지금 규모에서 표 하나 값어치가
없고, 제안은 응답이 곧 읽음이다.

## 5. 경계 — 어디에 무엇이 사는가

| | 코어 (`easymindmap`) | 유료 (`easymindmap-pro`) |
|---|---|---|
| 표 | `map_members` · `map_ownership_transfers` (있음) | `collab_invites` (새로) |
| 서버 | 권한 판정 · `GET /maps/shared` · 탈퇴 409 목록 (있음) · **탈퇴 파일 삭제를 행 기준으로**(§3.4 B, 새로) | 초대·초대장·나가기·제안·수락·거절·취소·받은함·메일 (전부) |
| 화면 자리 | 공유 버튼 · '공유받은 맵' 구역 · 탈퇴 대화상자 목록 (있음) · **`ProInbox` 자리** · 탈퇴 목록의 **[공유 설정]** 버튼 · 공유받은 맵 행의 **[나가기]** 자리 (새로) | ShareDialog 확장 · 받은함 · 제안 화면 · 나가기 (전부) |

코어에 새로 들어가는 것은 **자리 셋과 탈퇴의 파일 삭제 방식** 뿐이다.
공개판에서 자리는 비어 있고 탈퇴는 결과가 같다(내 것만 지운다 = 예전에도
내 것뿐이었다).

## 6. API — 유료 모듈 (`/v1/collab/…`)

| | 메서드·경로 | 누가 | 무엇 |
|---|---|---|---|
| 초대 | `POST /collab/maps/:id/members` `{email, role}` | 주인 | 계정 있으면 즉시 참가자(현행) + 메일. **없으면 초대장** → `{invited: true, pending: true, expiresAt}` |
| 초대장 목록 | `GET /collab/maps/:id/invites` | 주인 | pending·expired 목록(이메일·역할·보낸 때·만료) |
| 취소 | `DELETE /collab/maps/:id/invites/:inviteId` | 주인 | `revoked` |
| 재발송 | `POST /collab/maps/:id/invites/:inviteId/resend` | 주인 | 새 토큰 + 메일. 하루 3회 |
| 초대장 수락 | `POST /collab/invites/accept` `{token}` | 로그인 사용자 | 이메일이 같으면 참가자로 → `{mapId, role}`. 다르면 403 "이 초대장은 다른 이메일로 보내졌습니다" |
| 나가기 | `DELETE /collab/maps/:id/members/me` | 참가자 | 자기 행 삭제. 주인은 400 "주인은 나갈 수 없습니다 — 소유권을 넘기거나 맵을 지우세요" |
| 제안 | `POST /collab/maps/:id/transfer` `{toUserId}` | 주인 | editor 만. 용량 미리보기 포함 → `{transferId, expiresAt, preview:{needBytes, freeBytes, ok}}`. 열린 제안 있으면 409 |
| 제안 취소 | `DELETE /collab/transfers/:id` | 제안자 | pending 만 |
| 수락 | `POST /collab/transfers/:id/accept` | to_user | §3.3. 용량 부족 409 |
| 거절 | `POST /collab/transfers/:id/decline` | to_user | |
| 받은함 | `GET /collab/inbox` | 로그인 사용자 | §4. **pending 초대장의 이메일 매칭 자동 참여도 여기서** 일어난다 |
| 이력 | `GET /collab/maps/:id/transfers` | 주인·참가자 | 이 맵의 제안 이력 |

오류 문장은 **서버가 정하고 화면은 그대로 보여 준다**(ShareDialog 의 기존
규칙). 없는 맵과 권한 없는 맵은 404 로 구분하지 않는다(코어와 같은 규칙).

코어 쪽에 API 변경은 없다. `GET /account/delete-preview` 의 `collabMaps` 가
이미 [공유 설정] 버튼이 필요로 하는 `mapId·title` 을 준다.

## 7. DB

### 7.1 `collab_invites` — 유료 표 (새로, `easymindmap-pro/database/collab.sql`)

```sql
CREATE TABLE IF NOT EXISTS public.collab_invites (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    map_id      UUID NOT NULL REFERENCES public.maps(id)  ON DELETE CASCADE,
    email       VARCHAR(255) NOT NULL,          -- 소문자·trim. 아직 계정이 없는 주소
    role        VARCHAR(20)  NOT NULL DEFAULT 'editor'
                CHECK (role IN ('editor', 'viewer')),
    -- 링크 토큰은 원문을 두지 않고 sha256 만 (api_tokens 와 같은 이유)
    token_hash  CHAR(64) NOT NULL UNIQUE,
    invited_by  UUID REFERENCES public.users(id) ON DELETE SET NULL,
    status      VARCHAR(20)  NOT NULL DEFAULT 'pending'
                CHECK (status IN ('pending', 'accepted', 'revoked', 'expired')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at  TIMESTAMPTZ NOT NULL DEFAULT NOW() + INTERVAL '14 days',
    accepted_at TIMESTAMPTZ,
    accepted_by UUID REFERENCES public.users(id) ON DELETE SET NULL,
    resent_count INT NOT NULL DEFAULT 0
);
-- 같은 맵·같은 이메일에 열린 초대장은 하나
CREATE UNIQUE INDEX IF NOT EXISTS collab_invites_one_open
    ON public.collab_invites (map_id, email) WHERE status = 'pending';
-- 로그인한 사람의 이메일로 내 초대장 찾기 (받은함·자동 참여)
CREATE INDEX IF NOT EXISTS collab_invites_email
    ON public.collab_invites (email) WHERE status = 'pending';
```

코어 `REQUIRED_TABLES` 에 넣지 않는다(공개판이 영원히 degraded 가 된다 —
open-core-boundary §6.1). 유료 모듈이 기동 때 `to_regclass` 로 스스로 확인하고,
없으면 초대장 기능만 꺼진 채 "먼저 가입한 뒤 다시 초대해 주세요"(현행)로
물러난다.

### 7.2 `map_ownership_transfers` — 코어 표 (있음, #380)

그대로 쓴다. 컬럼을 더하지 않는다 — 제안의 용량 미리보기는 저장하지 않고
**볼 때마다 다시 센다**(저장하면 그 사이 바뀐 값을 보여 주게 된다).

  만료·취소·재발송 · 나가기 뒤 다시 초대.
