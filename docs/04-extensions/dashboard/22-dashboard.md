| 되돌리기 | **[일반맵으로 되돌리기]** — 다시 편집된다. 변수 칸 `[&amt]` 은 글자로 보인다 |

## 1. 요청 (사용자 원문)

2026-09-29:

> 대시보드맵을 개발하자. 일반맵을 대시보드맵으로 지정하면 퍼블리싱처럼 수정이
> 안 된다. 내 문서함에 대시보드 맵 구분을 추가한다.
> 대시보드 맵으로 전환된 맵을 열어서 맵 노드의 해당 노드 값을 DB 에 넣기 위한
> 정보를 어떻게 보여주고, 이 정보를 이용하여 간단하게 해당 DB 필드에 값을 넣거나
> 업데이트하는 프로그램을 작성하여 테스트해 보자. 설계안부터 작성해 줘.

2026-09-30 (v2 칩 방식에 대한 정정):

> 나는 노드의 내용을 바꾸는 것을 원하는 것이고, 필요하면 노드 추가·삭제도 가능하게
> 하고 싶다. 노드 내용을 업데이트 시
> 1) 노드 내용 전체 업데이트 — `"2026년 9월 매출 : 2,345,678,000원"` → 전체 업데이트
> 2) 노드 내용 중 일부 업데이트 — `2,345,678,000` 만 업데이트.
>    이를 위해 노드 작성 시 `"2026년 9월 매출 : [&amt]원"` — 업데이트할 값을 `[]` 안에
>    `&변수명` 을 적는 방식으로.

요구를 다섯으로 나눈다 — **R1** 전환하면 사람의 편집 잠금, **R2** 문서함 구분,
**R3** 노드마다 "값을 넣는 데 필요한 정보" 보여 주기, **R4** 노드 내용을 바꾸는
세 가지 길(통째로 · 변수 · 추가/삭제), **R5** 그것을 부르는 프로그램 + 시험.

## 2. 변수 문법 — `[&이름]`

```
2026년 9월 매출 : [&amt]원        ← 사람이 일반맵에서 이렇게 써 둔다
          amt = 2,345,678,000     ← 프로그램이 넣는다
2026년 9월 매출 : 2,345,678,000원  ← 대시보드맵 화면
```

| 규칙 | 내용 |
|---|---|
| 모양 | `[&` + 이름 + `]` |
| 이름 | 한글·영문·숫자·`_`·`.` — 첫 글자는 숫자가 아닐 것, 40자까지. 예: `amt`, `매출.오늘`, `cpu_1` |
| 대소문자 | 구분한다(`amt` 와 `AMT` 는 다르다) |
| 범위 | **맵 전체.** 같은 `[&amt]` 가 노드 셋에 있으면 한 번 넣어 셋이 함께 바뀐다 |
| 값 | 넣은 글자 **그대로** 들어간다(`2345678000` 을 넣으면 쉼표 없이). 쉼표는 프로그램이 붙여 보낸다 — 1단계. 서식 지정(`[&amt:#,###]`)은 2단계 |
| 아직 값이 없을 때 | `[&amt]` 를 **그대로** 보여 준다 — 빈칸이면 넣는 것을 잊은 변수를 찾을 수 없다 (§12 결정 5) |
| 어디서 바뀌나 | **노드 글자**. 코드 블록(```) 안은 바꾸지 않는다(예제 속 `[&x]` 보호 — `check_items` 와 같은 규칙). 노트는 2단계 |
| 일반맵일 때 | 그냥 글자다. 편집기에서 `[&amt]` 로 보이고, 내보내기(MD·HTML)에도 그대로 나간다 |

★ 이 문법은 **글자일 뿐**이라 mmd 포맷·파서를 바꾸지 않는다. 공개판에서 연 맵에서도
`[&amt]` 는 그냥 글자로 보인다 — 파일 호환이 깨지지 않는다(`open-core-boundary.md` §3.1 ②).

## 3. 구조 — 무엇이 어디에 저장되나

앱의 맵 원본은 `map_documents.doc` — 맵 하나가 JSONB **한 덩어리**다(v1 이 전제한
`nodes` 표는 원본이 아니다 — 부록 B). 세 가지 길을 저장 방식에 맞춰 나눈다.

| 길 | 저장 자리 | 왜 이 자리인가 |
|---|---|---|
| **② 변수** | 새 표 **`dashboard_vars`** — `(맵 ID, 변수 이름) → 값`. 문서는 `[&amt]` 를 그대로 품고, **읽을 때** 서버가 채워 준다 | 가장 자주 바뀌는 것(초·분 단위)이다. 값 하나에 문서 전체를 다시 쓰지 않는다. 그리고 **DB 한 칸**이라 요청의 "해당 DB 필드에 값을 넣는 프로그램"이 SQL 한 줄로도 된다 |
| **① 통째로 · ③ 추가/삭제** | **문서 자체**(`map_documents.doc`)를 서버가 고친다 | 구조가 바뀌는 일이다. 문서 밖에 두면 내보내기·AI(`get_map`)·검색이 모두 따로 알아야 한다 |

```
            사람 편집 ✕ (대시보드 잠금)
                    │
┌─ map_documents.doc ─────────────────────┐        ┌─ dashboard_vars ────────────┐
│ 매출 현황                                │        │ map_id  name  value          │
│ ├─ 2026년 9월 매출 : [&amt]원            │◀─채움──│ 3036…   amt   2,345,678,000  │
│ ├─ 목표 달성률 [&rate]%                  │◀─채움──│ 3036…   rate  78             │
│ └─ 비고 : 9/29 기준                      │        └──────────▲──────────────────┘
└────────────────▲────────────────────────┘                   │ ② 변수 넣기
                 │ ① 통째로 · ③ 추가/삭제                      │   (API · emm-dash · SQL)
                 │   (API · emm-dash)
```

**읽을 때 채우기** — 서버가 대시보드맵 문서를 내줄 때(`getDocument`) `dashboard_vars`
로 `[&…]` 를 채운 문서를 준다. 화면·AI `get_map`·내보내기가 모두 이 한 곳을 지나므로
**채워진 글자만 본다.** 채우는 함수는 하나다(`applyVars(doc, vars)`).

- 되돌리기 쉬운 이유: 문서에는 `[&amt]` 가 남아 있으므로 **일반맵으로 되돌리면** 곧바로
  작성 상태(`[&amt]`)로 보인다. 되살릴 것이 없다.
- 검색(문서함·지식창고)은 문서의 글자를 색인하므로 `[&amt]` 로 찾힌다 — 값으로는
  찾히지 않는다(1단계의 알려진 한계).

## 4. 사용자 흐름

### 4.1 작성 → 전환 — R1

1. **일반맵에서** 평소처럼 맵을 만들고, 바뀔 자리에 `[&변수]` 를 적는다.
2. 문서함 행 메뉴 또는 에디터 상단 맵 메뉴 → **[📊 대시보드맵으로 전환]**.
3. 확인창:

   ```
   대시보드맵으로 바꿀까요?
   · 사람은 노드·글자·구조를 고칠 수 없게 됩니다 (퍼블리싱과 같습니다)
   · 프로그램이 노드 글자를 바꾸고, 노드를 붙이고 지울 수 있습니다
   · 이 맵에서 찾은 변수: amt, rate  (2개)
   · 언제든 [일반맵으로 되돌리기] 로 다시 편집할 수 있습니다
                                          [취소] [대시보드맵으로 전환]
   ```

**전환할 수 없는 경우**(단추를 흐리게 + 이유 툴팁):

| 경우 | 이유 문구 |
|---|---|
| 지식창고에 진열했거나 유료로 파는 맵 | "지식창고에 올렸거나 유료로 파는 맵은 대시보드맵으로 바꿀 수 없습니다. 먼저 지식창고에서 내리거나 무료로 돌려 주세요(링크 공개는 그대로 둬도 됩니다)." — 반대로 대시보드맵은 진열·판매할 수 없다(§4.7). **링크(공개·보관)는 함께 선다** — v3.2 까지는 퍼블리싱 전체를 양쪽에서 막았으나 사용자 요청(사내 시스템 첨부·하위 페이지)으로 v3.3 에서 링크만 열었다 |
| 협업맵 | "협업맵은 아직 대시보드로 바꿀 수 없습니다" (§12 결정 6) |
| 내 맵이 아님 | 단추를 그리지 않는다 |
| pro 가 꺼진 서버 | "대시보드맵은 유료 기능입니다" (`/v1/features` 의 이유 그대로) |

전환할 때 서버는 **노드 ID 중복을 먼저 검사**한다. 중복이 있으면 거절한다("같은 ID 의
노드가 있어 프로그램이 가리킬 노드가 겹칩니다 — 맵을 한 번 열어 저장한 뒤 다시
시도하세요"). 앱은 불러올 때 중복 ID 를 새 ID 로 고치는데 읽기 전용 맵은 저장하지
않으므로, 화면과 서버의 노드 ID 가 어긋나는 것을 입구에서 막는다.

### 4.2 문서함 유형 — R2

(v3.3) 링크로 퍼블리싱한 대시보드맵은 `📊 대시보드맵 🔗`(공개) · `📊 대시보드맵 🔒`(보관) —
두 사실을 한 배지에 싣고, 누르면 링크를 복사한다. 줄에는 🌐 퍼블리싱 단추가 있고
지식창고 단추는 없다.

`MapBrowser.tsx` `mapType()` 이 이미 이 자리를 예약해 두었다("`kind === 'dashboard'` 가
생기면 ③ 옆에 한 줄"). 판정은 **`maps.view_mode`** 로 한다(칸이 이미 있다 — §6).

| 우선순위 | 유형 | 배지 |
|---|---|---|
| ① | 공유받은 맵 | 👁 읽기 전용 / 🤝 함께 편집 (그대로) |
| ② | 퍼블리싱맵 | 🌐 / 🔒 (그대로) |
| **③** | **대시보드맵** | **📊 대시보드맵** — 툴팁 "사람은 고칠 수 없고 프로그램이 내용을 바꾸는 맵" |
| ④ | 협업맵 / 단독맵 | 그대로 |

### 4.3 대시보드맵 열기

- 에디터는 **읽기 전용**으로 연다(퍼블리싱과 같은 길 — `getDocument` 가 `dashboard: true`
  를 주고 `mapSession` 이 `readOnlyInfo` 로 연다). 노드 글자에는 변수가 **채워진** 채로 보인다.
- 상단 배너: `📊 대시보드맵 — 프로그램이 내용을 바꿉니다 · 마지막 갱신 14:32:05 · [⟳] · [일반맵으로 되돌리기]`
- **자동 갱신**: 기본 10초(끄기 · 10초 · 30초 · 1분 · 5분). **보는 사람마다 그 브라우저에
  기억한다**(구현 결정 — 부록 C ①; `maps.refresh_interval_seconds` 는 쓰지 않는다). 가벼운 상태 물음(§7 `state`)으로 **바뀐 것이 있을 때만** 문서를 다시
  받는다. 탭이 안 보이면 멈추고, 돌아오면 바로 한 번 읽는다.
- **바뀐 노드는 2초 노란 깜빡임**(v1 DASH-03) — 새 문서와 옛 문서의 노드 글자를 비교한다.
  새로 붙은 노드도 깜빡인다.
- ★ **값이 바뀌면 노드 크기도 바뀐다** — 글자가 길어지면 노드가 넓어지고 레이아웃이 다시
  잡힌다. 노드 내용을 바꾸는 방식의 당연한 결과다(v2 가 칩을 밖에 둔 이유가 이것이었다).
  자주 바뀌는 숫자는 자릿수가 크게 달라지지 않게 보내는 것을 가이드에 적는다.

### 4.4 노드 클릭 → [데이터 연결] 패널 — R3

대시보드맵에서 노드를 고르면 **오른쪽에 카드로 뜬다**(2026-09-30 구현 — 인스펙터 탭 막대를 고치지 않고, 코어 도구줄의 `ProDashboardLive` 자리가 직접 그린다. 대시보드맵은 스타일·레이아웃 탭이 쓸모없어 탭으로 둘 이유가 없다).

```
┌ 📊 데이터 연결 ─────────────────────────────────────────────┐
│ 노드      매출 현황 > 2026년 9월 매출                        │
│ 노드 ID   node-k3f9a2                               [복사]   │
│ 맵 ID     303638b5-0374-4ca2-b0ac-4d5be2e3f0bc       [복사]  │
│ 원문      2026년 9월 매출 : [&amt]원                          │
│                                                               │
│ ── 이 노드의 변수 ────────────────────────────────────────  │
│ amt   = 2,345,678,000   14:32:05 · 열쇠 emd_a1b2 (ERP)       │
│                                                               │
│ ── ② 변수만 바꾸기 ───────────────────────────────────────  │
│ emm-dash var 3036… amt "2,345,678,000"               [복사]  │
│ curl -X PUT $EMM_API/v1/maps/3036…/dashboard/vars \          │
│   -H "Authorization: Bearer $EMM_DASH_KEY" \                  │
│   -d '{"vars":{"amt":"2,345,678,000"}}'              [복사]  │
│ SQL (서버 관리자)                                             │
│   INSERT INTO dashboard_vars (map_id,name,value,updated_by)   │
│   VALUES ('3036…','amt','2,345,678,000','sql')               │
│   ON CONFLICT (map_id,name) DO UPDATE SET value=EXCLUDED.value;│
│                                                      [복사]  │
│                                                               │
│ ── ① 글자 통째로 · ③ 추가/삭제 ──────────────────────────  │
│ emm-dash text 3036… node-k3f9a2 "2026년 9월 매출 : 23억원"    │
│ emm-dash add  3036… --parent node-k3f9a2 "10월 매출 : [&amt10]원" │   ← 하위
│ emm-dash add  3036… --after  node-k3f9a2 "10월 매출 : [&amt10]원" │   ← 형제 뒤
│ emm-dash add  3036… --before node-k3f9a2 "8월 매출 : [&amt08]원"  │   ← 형제 앞
│ emm-dash del  3036… node-k3f9a2                     [복사…]  │
│                                                               │
│ [맵 전체 노드·변수 목록 내려받기 (JSON)]                       │
│ [이 맵의 변수 전체 보기]  [이 맵의 열쇠 관리…]                  │
└───────────────────────────────────────────────────────────────┘
```

- **"DB 에 넣기 위한 정보"를 세 층으로 보여 준다** — 사람(노드 경로·원문), 프로그램
  (맵 ID·노드 ID·변수 이름·명령), DB(`dashboard_vars` 의 행). 요청의 "DB 필드"는 **변수
  하나 = `dashboard_vars` 한 행의 `value` 칸**이다.
- **[변수 전체 보기]** — 맵의 모든 변수를 한 표로: 이름 · 현재 값 · 쓰이는 노드 수 ·
  마지막 갱신. **아직 값이 없는 변수**와 **어느 노드에도 없는 변수**(값만 남은 것)를
  따로 표시한다.
- ★ **프로그램은 API 로 넣는 것이 기본이다.** DB 접속 정보를 외부 프로그램에 주면 그
  프로그램이 **모든 맵·모든 사용자 데이터**에 닿는다. SQL 은 서버 관리자가 확인·긴급
  수정할 때 쓰라고 보여 준다. 다만 변수는 **SQL 로 넣어도 동작하게** 만든다(§6 —
  `updated_at` 을 트리거가 채운다) — 요청이 "DB 필드에 넣는 프로그램" 이기 때문이다.

### 4.5 넣는 길과 인증 — R4 · R5

| 길 | 무엇을 | 인증 |
|---|---|---|
| `emm-dash` 시험 프로그램 | ① ② ③ 전부 | **맵별 열쇠** `emd_…` |
| 임의 프로그램 (ERP·모니터링·스프레드시트 매크로) | 〃 | 〃 |
| 서버에서 SQL | ② 변수만 | DB 계정 (서버 관리자) |
| 맵 주인이 앱에서 | 1단계는 없음 — 고치려면 일반맵으로 되돌린다 | — |

**맵별 열쇠** — [이 맵의 열쇠 관리…] 에서 이름을 붙여 만든다("ERP 연동"). 원문은 **만들 때
한 번만** 보여 주고 서버는 해시만 둔다(MCP 토큰 `api_tokens` 와 같은 규칙). 이 열쇠로는
**그 맵만** 바꿀 수 있다 — 다른 맵에 닿지 못한다. 폐기하면 바로 막힌다.

### 4.6 되돌리기

[일반맵으로 되돌리기] → 편집이 다시 된다. 노드 글자는 **원문(`[&amt]`)** 으로 보인다.
`dashboard_vars` 의 값은 지우지 않는다 — 다시 대시보드로 바꾸면 그대로 채워진다.
프로그램이 ① ③ 으로 바꾼 것은 문서에 이미 반영돼 있으므로 그대로 남는다.

### 4.7 사내 시스템에 붙이기 — 링크 퍼블리싱 (v3.3, 2026-09-30 사용자 요청)

> *"지식창고에 퍼블리싱은 아니고 사내시스템에서 첨부한다던지 기존 시스템에 하위 페이지로
> 달기 위해 퍼블리싱 URL을 만들어줘. 비공개 퍼블리싱으로 하는 방안이 더 간단할까?"*

**결정 — 기존 퍼블리싱을 그대로 쓴다(새 공유 링크를 만들지 않는다).**

- 퍼블리싱은 이미 "**링크를 아는 사람만**" 이 기본이다(`🔗 링크 공개` + 지식창고 미진열).
  사용자가 말한 "비공개 퍼블리싱" 은 이 상태다. 우리 말의 `🔒 비공개(보관)` 는 **남에게 404**
  라 붙여 둔 자리도 닫힌다 — 그 자리에 쓸 수 없다.
- 퍼블리싱은 스냅샷 파일이 아니라 **저장된 문서를 그대로** 내준다(`getPublished`). 그래서 대시보드
  에 붙이는 데 필요한 것은 둘뿐이다 — ① 내줄 때 **변수를 채우기**(에디터와 같은 `renderDashboardDoc`)
  ② 공개 화면이 **스스로 갱신**. 새 표·새 주소 체계·새 권한이 필요 없다.
- 따로 "대시보드 공유 링크" 를 만들면 주소 규칙·열림 조건·취소·미리보기를 **두 벌** 갖게 된다.
  하나만 느슨해도 새는 자리다(publish.service 의 `openWhere` 가 한 줄로 모인 이유).

**규칙**

| | 대시보드맵 |
|---|---|
| 퍼블리싱 등록 · 🔒 보관 · 🔗 링크 공개 | ✅ 된다 |
| 📚 지식창고 진열 | ❌ `409 DASHBOARD_NO_LISTING` — 불특정 다수에게 진열할 글이 아니다 |
| 💰 유료 판매 | ❌ `409 DASHBOARD_NO_PRICE` — 프로그램이 바꾸는 숫자는 파는 물건이 아니다 |
| 진열·판매 중인 맵을 대시보드로 | ❌ `409 DASHBOARD_PUBLISHED` (§4.1) — 양쪽을 다 막아 규칙이 닫힌다 |
| 사람의 편집 | 여전히 잠김 — 비공개로 돌려도 대시보드인 동안은 못 고친다(되돌리기가 먼저) |

**붙이는 법** — 퍼블리싱 창에 `📊 사내 시스템에 붙이기` 칸이 나온다.

- 첨부(게시판·메일): `https://…/p/{id}` 그대로.
- 하위 페이지(iframe): `<iframe src="https://…/p/{id}?embed=1" width="100%" height="600" style="border:0">` —
  `?embed=1` 은 돌아갈 막대(viewer bar)를 그리지 않는다. 뷰어 머리말(검색·확대)은 그대로 둔다.
- nginx 는 `X-Frame-Options`·`frame-ancestors` 를 걸지 않는다 — 어느 사내 도메인에서도 끼울 수 있다.
  (앞단 프록시가 그런 헤더를 더하면 막힌다 — 배포에서 확인할 자리.)

**스스로 갱신** — 공개 화면(`PublicMapPage`)은 `dashboard: true` 를 받으면 10초마다
`GET /v1/published/{id}/stamp` 를 묻는다. 표식은 `문서 시각 | 변수 마지막 갱신#개수` —
**값은 담지 않는다**(비인증 경로). 달라졌을 때만 문서를 다시 받는다. 탭이 숨으면 멈춘다.
비공개·취소로 404 가 오면 "링크가 닫혔습니다" 로 바꾼다 — 옛 숫자를 계속 띄우지 않는다.
다시 그리면 뷰어의 확대·위치가 처음으로 돌아간다(한눈에 보는 화면이라 받아들인다).
왼쪽 아래에 `🟢 📊 14:32:05`(마지막으로 새 내용을 받은 시각)를 둔다.

**보안** — 링크는 12자 무작위(31¹² ≈ 7.8×10¹⁷)라 찍어 맞힐 수 없지만, **링크를 받은 사람은 누구나
본다**(로그인 없음). 사내 전용이 꼭 필요하면 사내망 프록시 뒤에 두거나, 2단계의 "허용 도메인·서명 링크"
를 쓴다(§11). 노출이 걱정되면 [🔒 비공개(보관)] 한 번으로 즉시 닫힌다(주소는 그대로).

## 5. 규칙

| 규칙 | 내용 | 근거 |
|---|---|---|
| **사람의 편집은 서버가 막는다** | `view_mode='dashboard'` 면 `saveDocument` 가 403. 자동저장·옛 탭·MCP(`append_to_map`·`check_items`)·직접 호출 모두 같은 문 | 퍼블리싱 잠금과 같은 자리·같은 이유("막을 거면 문이 있는 모든 곳") |
| 프로그램의 변경은 **다른 문**으로 | ① ③ 은 pro 의 `ops` 경로만. 사람 저장 경로(`saveDocument`)를 열어 주지 않는다 | 잠금에 구멍을 내지 않는다 |
| 한 맵에 쓰는 사람은 **한 명씩** | `ops` 는 문서 행을 잠그고(`SELECT … FOR UPDATE`) 읽고-고치고-쓴다 | 프로그램 둘이 동시에 고쳐도 한쪽이 사라지지 않는다 |
| 한 번의 `ops` 는 **전부 되거나 전부 안 된다** | 하나라도 틀리면(없는 노드 등) 아무것도 바꾸지 않고 몇 번째가 왜 틀렸는지 돌려준다 | 반쯤 바뀐 대시보드가 제일 나쁘다 |
| 지우기는 **히스토리 버전**을 남긴다 | `delete` 가 든 `ops` 는 적용 전 문서를 히스토리 버전으로 남긴다. 글자·추가만 있는 `ops` 와 변수는 남기지 않는다 | 잘못 지운 것은 [히스토리] 에서 되살린다. 값 바꿀 때마다 버전이 쌓이면 히스토리가 쓸모없어진다 (§12 결정 7) |
| 중심 노드 | 지울 수 없다. 글자는 바꿀 수 있다. **형제(앞·뒤)도 붙일 수 없다** — 중심의 형제는 새 중심이 되는데, 그건 맵 모양을 바꾸는 일이라 사람이 일반맵에서 한다 | |
| **노드 추가의 자리 — 셋 중 하나** (2026-09-30 사용자 요청) | `parent`(그 노드의 **하위** — `index` 로 몇 번째인지, 없으면 맨 끝) · `before`(그 노드의 **형제로 바로 앞**) · `after`(**형제로 바로 뒤**). 셋 중 **정확히 하나**만 준다 — 둘 이상이거나 없으면 거절 | 형제로 붙이려고 부모를 찾고 순번을 세는 일을 프로그램에 맡기지 않는다. 기준 노드 하나만 알면 된다 |
| **① 통째로 = 노드 ID + 글자 그대로** | `{op:"text", node:"<노드 ID>", text:"…"}` 이면 그 노드의 내용을 **보낸 글자 그대로** 바꾼다 — 서버가 다듬거나 합치지 않는다. 글자 안에 `[&변수]` 를 넣으면 그 뒤로는 변수 노드가 된다 | **2026-09-30 사용자 확인** — "노드 ID 로 노드 전체 내용을 업데이트하면 그대로 반영하면 된다" |
| 노드 가리키기 | 기본은 **노드 ID**(`node-…`, [데이터 연결] 패널에서 복사). 사람이 짜는 짧은 스크립트를 위해 **경로**(`"매출 현황 > 9월"`, MCP `append_to_map` 과 같은 규칙)도 받되, 경로가 둘 이상에 맞으면 거절 | 오래 도는 연동은 ID 가 안전하다 — 노드 글자가 바뀌어도 ID 는 그대로다 |
| 새 노드 ID | 서버가 앱과 같은 모양(`node-…`)으로 만들어 **응답으로 돌려준다** | 프로그램이 이어서 그 노드를 가리킬 수 있게 |
| 크기 | 변수 값 500자 · 노드 글자 2,000자 · `ops` 한 번에 200개 · 변수 한 번에 500개 | |
| 값은 **글자로만** 그린다 | 변수 값에 든 `**`·`[x](y)`·HTML 은 해석하지 않고 그대로 보인다 | 외부 프로그램이 넣은 것이 화면에서 링크·서식으로 바뀌는 길을 막는다. (① 통째로 넣는 글자는 사람이 쓴 노드와 같게 해석한다 — 그건 "노드 내용"이다) |
| 쓰기 빈도 | 열쇠당 분당 120회 (기존 `@nestjs/throttler`) | 폭주하는 스크립트가 서버를 잡지 않게 |

## 6. 데이터 — **표를 더하기만 한다** (파괴 없음 · 멱등 델타)

`maps.view_mode`('edit' | 'dashboard')와 `maps.refresh_interval_seconds` 는 **이미 있다**
(지금은 아무도 쓰지 않는다 — 2026-09-29 코드 확인). 새로 더하는 것은 표 둘과 트리거 하나:

```sql
-- 변수: (맵, 이름) 한 칸에 현재 값 하나
CREATE TABLE IF NOT EXISTS public.dashboard_vars (
    map_id      UUID NOT NULL REFERENCES public.maps(id) ON DELETE CASCADE,
    name        VARCHAR(40) NOT NULL,
    value       TEXT NOT NULL CHECK (char_length(value) <= 500),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_by  VARCHAR(60) NOT NULL DEFAULT 'sql',   -- 'user:<uuid>' | 'key:<prefix>' | 'sql'
    PRIMARY KEY (map_id, name)
);

-- SQL 로 직접 UPDATE 해도 화면이 알아채게 — 갱신 시각은 DB 가 찍는다
CREATE OR REPLACE FUNCTION public.dashboard_vars_touch() RETURNS trigger AS $$
BEGIN NEW.updated_at := NOW(); RETURN NEW; END $$ LANGUAGE plpgsql;
DROP TRIGGER IF EXISTS dashboard_vars_touch ON public.dashboard_vars;
CREATE TRIGGER dashboard_vars_touch BEFORE INSERT OR UPDATE ON public.dashboard_vars
    FOR EACH ROW EXECUTE FUNCTION public.dashboard_vars_touch();

CREATE INDEX IF NOT EXISTS dashboard_vars_recent_idx
    ON public.dashboard_vars (map_id, updated_at DESC);

-- 맵별 열쇠: 원문은 두지 않는다 (api_tokens 와 같은 규칙)
CREATE TABLE IF NOT EXISTS public.dashboard_keys (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    map_id       UUID NOT NULL REFERENCES public.maps(id) ON DELETE CASCADE,
    name         VARCHAR(60) NOT NULL,
    token_hash   CHAR(64) NOT NULL UNIQUE,     -- sha256(원문)
    prefix       VARCHAR(20) NOT NULL,         -- 'emd_a1b2c3d4'
    created_by   UUID NOT NULL REFERENCES public.users(id) ON DELETE CASCADE,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_used_at TIMESTAMPTZ,                  -- 하루 한 번만 갱신
    revoked_at   TIMESTAMPTZ
);
CREATE INDEX IF NOT EXISTS dashboard_keys_map_idx ON public.dashboard_keys (map_id);
```

- 두 표는 **pro 의 델타**로 둔다(유료 기능의 표 — "자기 경로·자기 표까지", `pro.module.ts`).
  코어의 `schema.sql` 은 손대지 않는다.
- 맵을 지우면 변수·열쇠도 함께 지워진다(CASCADE) — 휴지통(soft-delete)에서는 남는다.
- 코드는 `tableReady('public.dashboard_vars')` 로 표 유무를 먼저 본다 — 델타를 적용하기
  전에 배포돼도 **앱이 죽지 않고** 대시보드 기능만 "준비 중"이 된다(이 저장소의 기존 규칙).
- ① ③ 은 표가 필요 없다 — `map_documents.doc` 를 고친다.

## 7. API

**코어가 갖는 것** (규칙 — 공개):

| 메서드 · 경로 | 무엇 |
|---|---|
| `PATCH /v1/maps/:id` `{viewMode:'dashboard'\|'edit'}` | **이미 있다.** 가드를 더한다 — 주인만. `dashboard` 로는 pro 의 `dashboard` 기능이 켜져 있을 때만, 공개 중 퍼블리싱·협업맵·중복 노드 ID 는 409 + `code`. `edit` 로 되돌리기는 pro 가 꺼져도 된다(사용자가 갇히지 않게) |
| `GET /v1/maps/:id/document` | 응답에 `dashboard: boolean`. 대시보드면 pro 계약의 `renderDashboardDoc?(mapId, doc)` 로 **변수를 채운 문서**를 준다(pro 가 없으면 원문 그대로) |
| `GET /v1/maps` (문서함) | 행에 `viewMode` 를 더한다 |
| `saveDocument` | `view_mode='dashboard'` 면 403 `DASHBOARD_LOCKED` |
| MCP `get_map` | 위 `getDocument` 를 지나므로 채워진 글자를 본다. `append_to_map`·`check_items` 는 403 문구를 그대로 돌려준다 |

**pro 가 갖는 것** (알맹이 — 비공개, pro 모듈이 자기 경로로 등록):

| 메서드 · 경로 | 인증 | 무엇 |
|---|---|---|
| `GET /v1/maps/:id/dashboard/state?since=<iso>` | 로그인(주인) · 그 맵의 열쇠 | `{viewMode, docUpdatedAt, vars:[{name,value,updated_at,updated_by}], varCount, serverTime}` — `since` 뒤에 바뀐 변수만. `serverTime` 은 **DB 시계**, `varCount` 는 지운 변수를 알아채는 칸(부록 C ②). 화면의 10초 물음 |
| `GET /v1/maps/:id/dashboard/nodes` | 〃 | 노드 ID · 경로 · 원문 · 쓰는 변수 목록 · 채워진 글자 (= [노드·변수 목록 내려받기]) |
| `PUT /v1/maps/:id/dashboard/vars` | 로그인(주인) · 열쇠 | `{vars:{amt:"2,345,678,000", rate:"78"}}` → `{updated, unused:[어느 노드에도 없는 이름]}`. **있으면 고치고 없으면 넣는다.** `unused` 는 거절하지 않고 알려만 준다(노드보다 값을 먼저 넣는 순서도 되게) |
| `DELETE /v1/maps/:id/dashboard/vars/:name` | 〃 | 변수 지우기 → 화면에 `[&name]` 이 다시 보인다 |
| `POST /v1/maps/:id/dashboard/ops` | 〃 | `{ops:[…]}` 아래 — 한 번에 전부 적용하거나 전부 거절 |
| `POST /v1/maps/:id/dashboard/keys` `{name}` | 로그인(주인) | `{id, key, prefix}` — `key` 는 이때 한 번만 |
| `GET /v1/maps/:id/dashboard/keys` | 〃 | 목록(원문 없음) |
| `DELETE /v1/maps/:id/dashboard/keys/:keyId` | 〃 | 폐기(`revoked_at`) |
| `GET /v1/dashboard/emm-dash.mjs` | 없음(기능이 켜진 서버만, 아니면 404) | 시험 프로그램 파일 — `curl -O` 한 줄로 받는다(부록 C ③) |

**`ops` 의 모양** (① ③):

```jsonc
{ "ops": [
  { "op": "text",   "node": "node-k3f9a2",           "text": "2026년 9월 매출 : 23억원" },   // ① 통째로
  { "op": "add",    "parent": "매출 현황",             "text": "10월 매출 : [&amt10]원",
                    "index": 1, "ref": "oct" },                                          // ③ 하위로 추가 (index 없으면 맨 끝)
  { "op": "add",    "after":  "node-k3f9a2",          "text": "10월 매출 : [&amt10]원" },  // ③ 형제로 바로 뒤
  { "op": "add",    "before": "node-k3f9a2",          "text": "8월 매출 : [&amt08]원" },   // ③ 형제로 바로 앞
  { "op": "text",   "node": "@oct",                   "text": "10월 매출 : 집계 중" },     // 같은 호출에서 방금 붙인 노드
  { "op": "delete", "node": "매출 현황 > 비고" }                                          // ③ 삭제 (하위째)
]}
```

응답: `{applied: 4, added: [{ref:"oct", nodeId:"node-7c1e04"}], version: <히스토리 버전 번호 — delete 가 있을 때>, updatedAt}`.
틀리면 409 `{code:"OP_FAILED", message:"3번째 변경이 틀렸습니다 — 맵에 없는 노드: 매출 현황 > 비고"}` 이고
**아무것도 바뀌지 않는다.**

열쇠 인증: `Authorization: Bearer emd_…`. `emd_`(dashboard)는 MCP 의 `emm_` 과 머리가 달라
**한눈에 구분**되고, 서버도 머리로 갈라 다른 표에서 찾는다.

## 9. 시험 프로그램 `emm-dash` — R5

Node 18+ 하나로 도는 명령줄 도구, 의존성 없음(`fetch` 만). pro 저장소 `scripts/emm-dash.mjs` —
**서버가 그대로 내려 준다**(`curl -O $EMM_API/v1/dashboard/emm-dash.mjs`).

```bash
export EMM_API=https://api-dev.mindmap.ai.kr
export EMM_DASH_KEY=emd_xxxxxxxxxxxxxxxx          # [이 맵의 열쇠 관리…] 에서 만든 것

node emm-dash.mjs nodes <mapId>                     # 노드 ID · 경로 · 원문 · 변수 · 채워진 글자
node emm-dash.mjs vars  <mapId>                     # 변수 이름 · 현재 값 · 갱신 시각

# ② 변수만
node emm-dash.mjs var   <mapId> amt "2,345,678,000"
node emm-dash.mjs var   <mapId> amt "…" rate "78"    # 여러 개는 이름·값 짝으로
node emm-dash.mjs unvar <mapId> amt                   # 변수 지우기

# ① 통째로 · ③ 추가/삭제
node emm-dash.mjs text  <mapId> <노드ID|경로> "2026년 9월 매출 : 23억원"
node emm-dash.mjs add   <mapId> --parent <노드ID|경로> "10월 매출 : [&amt10]원"   # 하위(맨 끝) · --index N 으로 자리
node emm-dash.mjs add   <mapId> --after  <노드ID|경로> "10월 매출 : [&amt10]원"   # 형제로 바로 뒤
node emm-dash.mjs add   <mapId> --before <노드ID|경로> "8월 매출 : [&amt08]원"    # 형제로 바로 앞
node emm-dash.mjs del   <mapId> <노드ID|경로>
node emm-dash.mjs ops   <mapId> ops.json             # §7 ops 그대로 (- 이면 표준입력)

node emm-dash.mjs demo  <mapId> amt --count 5 --every 3   # 변수 하나를 3초마다 5번 — 깜빡임 시험용
```

성공하면 `✅ 바뀜 1 · 같은 값 0 · 노드 1개에 반영`, 실패하면 `✖ 409 [OP_FAILED] 1번째 변경이
틀렸습니다 — …` 와 종료코드 1 — 스크립트·cron 이 실패를 알 수 있게.

## 부록 C. 구현하며 정한 것 (v3.2, 2026-09-30)

① **자동 갱신 간격은 보는 사람의 브라우저에** 둔다(`localStorage`). `maps.refresh_interval_seconds`
   는 기본값이 `0`(끔)이라 "기본 10초" 와 뜻이 반대이고, 간격은 **보는 사람의 편의**라 맵에 박을
   이유가 없다(한 사람이 1분으로 바꾸면 모두가 1분이 되는 것은 이상하다).

② **10초 물음이 놓치지 않게** — 변수의 `updated_at` 은 DB 트리거가 찍으므로 `since` 의 기준도
   **DB 시계**(`serverTime`)로 준다(API 컨테이너 시계와 어긋나면 그만큼 놓친다). 트랜잭션 시작
   시각이 찍히므로 화면은 **5초 겹쳐** 묻고, 받은 값을 이전 값과 비교해 헛갱신을 거른다.
   `since` 로는 **지운 행이 안 보여서** `varCount` 를 함께 준다(개수가 바뀌면 다시 받는다).

③ **`emm-dash` 는 서버가 내려 준다** — 사용자는 비공개 저장소를 받을 수 없다. 패키지 `files`
   에 실어 `GET /v1/dashboard/emm-dash.mjs` 로 준다(기능이 꺼진 서버는 404).

④ **전환할 때 열린 맵은 먼저 저장한다** — 서버는 **저장된** 문서로 중복 ID 를 판정하고, 전환
   뒤에는 저장이 막힌다. 저장하지 않으면 마지막 몇 초의 편집이 잠긴 채 사라진다.
