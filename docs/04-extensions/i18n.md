## 1. 언어를 정하는 순서

1. **로그인했으면 계정에 저장된 언어** — `users.language` (2026-10-05 P3).
   어느 기기에서 로그인해도 같은 언어로 뜬다
2. 사용자가 고른 값 — `localStorage['emm.lang']` (이 브라우저에 기억)
3. 브라우저 언어(`navigator.languages`) — `ko*`·`ja*`·`zh*`·`en*` 이면 그 언어
4. 그 밖은 **영어**

계정 동기화(`stores/profileStore.ts` 끝): 프로필을 읽을 때 계정 값이 있으면
그것을 적용하고(서버가 이긴다 — 이때는 다시 올리지 않는다), 계정이 비어
있으면 지금 언어를 올린다. 로그인한 채 언어를 바꾸면 `PUT /v1/account/language`.
서버에 열이 없으면(델타 `2026-10-05-user-language.sql` 전) 아무것도 올리지 않고
브라우저에만 기억한다 — 개인 설정 안내문도 그에 맞게 바뀐다. 다른 기기에서
바꾼 언어는 **다음 로그인·새로고침**(프로필을 다시 읽을 때) 따라온다.

`<html lang>` 은 언어가 바뀔 때마다 따라간다 — 중국어·일본어 화면은 그 나라
글꼴을 먼저 세운다(`global.css` 의 `:lang(ja)`·`:lang(zh)`. Pretendard 에는
가나·한자가 없어 그대로 두면 한국어 글꼴로 그려진다).

## 2. 코드 규칙

```ts
// 컴포넌트 안 — 언어가 바뀌면 다시 그린다
const tr = useTr();
tr('shell.toolbar.export');
tr('cloud.savedCount', { n: 3 });        // 사전: '{n}개 저장했습니다'

// 컴포넌트 밖 — 부르는 순간의 언어
import { tr, currentLocale } from '@/i18n';
date.toLocaleString(currentLocale());

// 문장 안의 굵게·코드·줄바꿈·JSX 자리
import { rich } from '@/i18n/rich';
rich(tr('auth.welcome.intro'));                        // '**가입**을 눌러…'
rich(tr('inspector.ai.guide'), { marker: <code>@source</code> });
```

- 이름이 `t` 가 아니라 **`tr`** 이다 — 컴포넌트가 이미 `t` 를 테마 토큰으로 쓴다.
- **모듈 최상위 상수에서 `tr()` 을 부르지 않는다** — 그 순간의 언어로 굳는다.
  라벨 표는 키(`labelKey`)를 들고 그릴 때 번역한다.
- 문장을 조각내 이어 붙이지 않는다 — 어순이 언어마다 다르다. 한 문장을 한
  키로 두고 `{자리}`·`**굵게**` 로 꾸민다.
- 사전은 영역별 파일 `src/i18n/dict/<영역>.ts` 하나에 **네 언어를 함께** 둔다
  (`common`·`auth`·`cloud`·`publish`·`shell`·`panel`·`editor`·`inspector`·`io`).
  한국어 표가 기준이고, **다른 언어에 키가 하나라도 빠지면 타입 검사가 실패**한다
  (`define.ts` 의 `NoInfer`).
- `i18n.test.ts`(test:unit 체인) — 키 접두사 · 빈 값 · `{자리}` 가 네 언어에서
  같은지 · 영·중·일 번역에 **한글이 남지 않았는지**.
- 단위 테스트는 Node 에서 돈다(브라우저 언어 = 보통 영어). 한국어 문장을
  확인하는 테스트는 맨 위에서 `useLangStore.getState().setLang('ko')` 한다.

## 3. 번역하지 않는 것 (데이터·판정용)

| 무엇 | 왜 |
|---|---|
| 서버가 보낸 오류 문장 | 서버가 정한 문장 그대로 보인다(서버 i18n 은 별도) |
| `EMPTY_MAP_TITLE`('문서 없음') | "열린 문서 없음" 판정 표식. 화면의 중심 노드 글만 번역 |
| 검색 결과 종류 값(`노드`/`태그`…) | `data-search-kind` 값. 화면 배지 글만 번역 |
| 달력 노드 해석 패턴(`년`/`월`) | 저장된 맵을 같은 뜻으로 읽기 위해 |
| `koreanHolidays.ts` 공휴일 이름 | 한국 달력 데이터 |
| AI 시스템 프롬프트 본문 | AI 가 읽는 글. 대신 **출력 언어 지시**를 붙인다(§4) |
| 관리자 콘솔(`pages/admin`) | 운영자용 내부 화면 |

**만들 때 맵에 들어가는 글**(새 노드 글, 표 머리 `열 n`, 달력 요일·주 태그
`[36주]`↔`[W36]`, 템플릿 노드, 샘플 맵, 새 맵 제목)은 **만드는 순간의 언어**를
따른다. 이미 만든 맵은 바뀌지 않는다.

## 4. 언어에 따라 동작이 달라지는 곳

- **AI 생성** — 한국어가 아니면 시스템 프롬프트 끝에 `[Output language]` 한
  단락을 붙여 맵 글을 그 언어로 쓰게 한다(API·웹 AI·노드 확장 셋 다).
  한국어는 예전과 한 글자도 다르지 않다.
- **소스 노드 표식** — `@소스` · `@source` · `@资料` · `@ソース` 를 모두 받는다
  (`aiProjectContext.ts` `SOURCE_MARKERS`). 도움말은 지금 언어의 것을 보여 준다.
- **회원탈퇴 확인 문구** — 한국어 화면은 `회원탈퇴`, 그 밖은 `DELETE`.
  서버가 둘 다 받는다(`account.service.ts` `DELETE_CONFIRM_PHRASES`).
- **HTML 내보내기** — 뷰어의 문구를 내보내는 순간의 언어로 파일에 굳힌다
  (`window.__MM_L__`), `<html lang>` 도 그 언어.
- **휴대폰 국가 목록** — 국가 이름은 브라우저의 `Intl.DisplayNames` 로
  (한국어는 기존 이름 그대로).

## 5. 유료 UI(`@pro`)

유료 화면(공유·판매·구매·대시보드)은 비공개 저장소에 있다. 코어가
`registerDict({ ko, en, zh, ja })` 를 내주므로, 유료 UI 가 자기 영역(`pro.*`)
사전을 들고 와 같은 `tr()` 로 쓴다 — 유료 저장소의 후속 작업이다.
