# 암호로 보호된 HTML 내보내기

## 범위

- EMM 맵: 데스크톱/모바일 내보내기의 **암호화 HTML**.
- 내장 Markdown 편집기: 파일 메뉴의 **암호화 md.html로 저장**.
- 기존 평문 HTML/MD 내보내기는 그대로이며, 암호화는 선택 기능이다.
- 서버/IndexedDB에 있는 원본 맵, 공유 권한, 이미 배포된 평문 파일까지 암호화하는 기능이 아니다. 복호화해 불러온 뒤 EMM에 저장한 문서도 별도 보호 범위다.

## 암호 정책과 파일 형식

암호는 Unicode 코드 포인트 기준 8~256자이고 문자·숫자·특수문자 중 두 종류 이상이어야 한다. 대소문자는 한 종류이고 공백은 특수문자 종류로 세지 않는다. 암호를 자동 정규화/trim하지 않는다. 내보낼 때 확인 입력을 받으며 암호/파생 키는 저장하거나 로그에 남기지 않는다. JavaScript 문자열의 물리적 메모리 소거까지 보장하지는 않는다. 잃어버린 암호는 복구할 수 없다.

형식 `emm-protected-html`, 버전 1. PBKDF2-HMAC-SHA-256 600,000회, 16바이트 무작위 salt, AES-256-GCM, 12바이트 무작위 IV, 128비트 인증 태그를 사용한다. format/version/kind/KDF/반복수/cipher를 AAD로 인증한다. 알고리즘·버전·반복수 변경이나 예상 밖 필드, 잘못된 Base64는 거부한다. 같은 문서/암호도 매번 salt/IV가 달라진다.

HTML에는 범용 암호 입력 화면과 암호문 JSON만 평문으로 남는다. 문서 제목·본문·복원 메타데이터·첨부 이름과 원본은 모두 암호문 안에 들어간다. 기본 파일명은 `보호된-맵.html` / `보호된-문서.md.html`이다. 사용자가 직접 선택하거나 바꾼 파일명은 보호 대상이 아니다.

## 맵 첨부파일

첫 중심과 추가 중심의 루트·모든 하위 노드를 검사한다. 파일·음성·동영상 첨부, 노드 사진, 리치 노트의 img src를 수집하고 원본 바이트를 읽어 data URL로 만든 뒤 전체 HTML을 암호화한다. 뷰어 데이터와 편집 복원 JSON 양쪽 모두 같은 원본을 포함한다.

- 따로 평문 `files/`나 ZIP을 만들지 않는다.
- 빠진 URL, 죽은 blob, 읽기 실패, CORS, 시간 초과는 전체 내보내기 실패다. 평문/외부 링크 대체나 조용한 누락은 없다.
- 현재 한도: 고유 리소스 원본 합계 **20MiB**, 리소스 참조 **4096개**, 노드 **50000개**, 최종 평문 HTML **64MiB**, 보호 HTML 파일 **92MiB**. 같은 리소스를 여러 번 삽입하면 최종 HTML 한도에 먼저 도달할 수 있다.
- 네트워크 원본은 응답 스트림을 읽으면서 크기를 제한하며 개별 요청은 30초 제한이다.
- 복호화 뒤 첨부는 sandbox 안에서 일시적인 Blob URL로 열고, 가져오기용 JSON은 원본 바이트를 유지한다. UTF-8 텍스트의 한글 표시를 위해 Blob MIME에 charset을 지정한다.
- 개별 첨부를 열거나 내려받은 뒤의 파일은 평문이다. 화면 복사도 막지 않는다.

일반 하이퍼링크의 URL 자체는 암호문 안에 있지만 링크 목적지의 서버/사이트까지 보호하지 않는다. HTML 코드블록 등 동적 외부 리소스는 보호된 뷰어의 CSP로 차단될 수 있다.

## 복호화와 가져오기

브라우저 열기: 암호 입력 → 인증 복호화 → opaque-origin sandbox iframe에 문서 표시. `allow-same-origin`과 상위 탐색 권한은 없다. CSP는 외부 연결·외부 스크립트·외부 사진을 막는다. 해제된 HTML은 실행 가능한 문서이므로 앱 origin에 `document.write`하지 않는다. 다시 잠그면 iframe을 비우고 암호 입력 상태로 돌아간다.

EMM 불러오기: 암호화 표식을 인식하고 암호를 받은 뒤 복호화된 맵 메타데이터만 기존 파서로 읽는다. HTML 스크립트는 실행하지 않는다. 첨부 인라인 형식/크기/수도 다시 검사한 뒤 맵을 바꾼다. 취소/암호 오류/변조/형식 오류는 기존 맵을 바꾸지 않는다. 암호화 Markdown HTML은 MD 편집기에서 열도록 안내한다. 현재 암호화 파일은 단일 HTML이므로 암호화 HTML을 임의 ZIP에 감싼 경로는 지원하지 않는다.

## Markdown HTML

온라인 편집기에서 저장할 때도 라이브러리까지 넣은 오프라인 HTML을 먼저 만들고 그 전체를 암호화한다. 처음 생성할 때는 라이브러리를 받기 위한 인터넷이 필요할 수 있다. 실패하면 평문으로 대신 저장하지 않는다.

보호된 md.html은 해제 후에도 보호 문서 상태를 유지한다. 저장/Ctrl+S는 다시 암호와 확인을 받아 암호화한다. 평문 MD/온라인 HTML/오프라인 HTML 내보내기는 명시적 노출 경고와 확인이 필요하다. EMM 호스트 첨부에서 암호화 파일을 내보내도 원래 EMM 저장 계약과 saved/handle 상태를 바꾸지 않는다.

기존 raster data 이미지(PNG/JPEG/GIF/WebP/AVIF)는 지원한다. 외부·상대·blob·참조형 이미지와 외부 리소스를 부를 수 있는 SVG/HTML/CSS는 현재 자동 인라인하지 않고 명확한 오류로 중단한다. 코드에 이미지 예제를 적은 경우에도 보수적으로 거부할 수 있다.

상위 원본은 `okpojung/markdown-editor` 커밋 `e4815cb63868932d614c463fa98ad9e073c5f334`이며 EMM에 포함된 파일에는 암호화 보안 패치가 추가되어 있다. 원본 저장소에 이미 반영됐다는 뜻은 아니다. 재동기화할 때 패치를 잃어버리지 않도록 내장 사본 README의 출처/해시와 인계 패치를 확인한다.

## 검증 경계

단위/합성 시험과 실제 Chromium HTTPS 격리 페이지 시험은 구분해서 기록한다. 파일 암호문의 무노출·정확한 복원, 잘못된 암호/변조 거부, 첨부 원본 동일성, sandbox, MD 오프라인 초기화·편집·재암호화 저장을 검사한다. file:// 및 Windows/macOS의 모든 브라우저 조합은 별도 검증이며, 기능 탐지 실패 시 약한 암호화로 대체하지 않는다. 운영 반영은 별도의 배포 확인이 필요하다.
