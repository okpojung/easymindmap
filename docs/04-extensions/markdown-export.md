* 최초 작성: 2026-07 (MVS)
* **위상**: 이 문서는 **EMM(EasyMindMap Markdown) 스펙의 구현 규칙

  `apps/frontend/src/export/exportMarkdown.ts` (맵 → MD)

## 1. MD → 맵 변환 규칙 (importMarkdown.parseMarkdownToMap)

파일을 위에서 아래로 순차 처리한다 — **2레벨 이하 모든 노드는 파일에
적힌 순서 그대로** 배치된다.

### 1.0 블록 배치 옵션 (blockPlacement — 리치 노드 P3, 2026-07)

문단(인용문)·코드 펜스·표·체크리스트 "블록"을 어디에 둘지 선택한다.
불러오기 UI("MD 블록 배치")에서 고르며 선택은 기억된다.

| 옵션 | 동작 |
|---|---|
| **노드로** (앱 기본) | **경계가 확실한 독립 블록은 각각의 자식 노드로 분리한다** (2026-07-31 사용자 결정 — markmap 등과 동일한 변환): 코드 펜스 → 코드 노드, 표 → 표 노드, 이미지 문단 → 사진 노드 — 견출 아래 순서 그대로 형제로. 블록 **바로 뒤의 인용문**은 그 블록 노드의 본문 줄로 이어 붙는다 (표 아래 "※ 첨부 …"가 표와 함께). 인용문·`- [x]` 체크 줄은 현재 노드의 본문에 합쳐지며, 본문이 **A4 분량(2,500자, 이미지 1장=600자 환산)** 을 넘으면 노트로 옮기고 안내한다 (데이터 손실 없음) |
| 노트로 | 아래 1.3~1.6의 기존 규칙 그대로 (문단/코드/표/체크 노트) |

**분리 vs 한 덩어리 — 상호 변환의 기본 원칙 (2026-07-31 확정)**:

- **MD의 독립 블록**(빈 줄로 구분된 코드 펜스·표·이미지)은 경계가
  확실하므로 **각각의 노드**로 변환한다 — markmap 등 다른 마인드맵과
  같은 모양이 되고, 내보내기(각 노드 = 견출/블록)와도 왕복 대칭이다.
- **텍스트 중간에 사진·표가 섞인 콘텐츠**(웹 기사·그룹웨어 결재 문서
  **붙여넣기**)는 경계가 원문 흐름의 일부이므로 **한 노드**에 원문
  순서 그대로 담는다 (images[].afterLine·mdTable 원문 위치 렌더).
- 블록-노드로 분리된 노드는 내보낼 때 견출 제목이 없으므로 종류
  라벨(`표`/`코드`) 견출 + 블록으로 나가고, 메타데이터 enrich가 같은
  라벨 키(nodeHeadingText)로 되찾아 왕복이 안정된다 (e2e76 [2]).

주의사항:

- **파서 API 기본은 `note`** (하위 호환) — 적합성 코퍼스·AI 생성
  (`parseEmm`)·EasyMindMap MD 왕복이 기존 스냅숏과 동일하게 동작한다.
  앱의 불러오기 UI가 기본으로 `node`를 전달한다.
- **EasyMindMap이 내보낸 MD**(메타데이터 있음)는 옵션과 무관하게 항상
  `note`로 파싱한다 — enrich의 텍스트 매칭(스타일·노트·원문 복원)이
  깨지지 않아야 하기 때문. 옵션은 **일반 MD 전용**이다. enrich 매칭
  키는 **견출 제목**(`nodeHeadingText` — 노드 텍스트에서 코드·표·체크
  블록을 뺀 첫 일반 줄들)이 기본이고, 2026-07 이전 내보내기(전체 한 줄
  합침)와의 호환을 위해 한 줄 합침 키도 함께 색인한다.
- 첫 견출 전(머리말)의 블록은 붙일 노드가 없으므로 옵션과 무관하게
  기존처럼 **루트 노트**다.

아래 1.3·1.5·1.6의 "노트" 결과는 **`note` 배치 기준**이다.

### 1.1 견출(heading)

| 입력 | 결과 |
|---|---|
| 파일의 **첫 H1**(`# 제목`) | 루트(중심 주제) 텍스트 + 맵 제목. **중심 노드는 제목만 담는다** — 첫 견출 전의 머리말(문단·인용·표)은 blockPlacement 옵션과 무관하게 항상 **루트의 노트**로 첨부해 중심 노드가 비대해지지 않게 한다 (2026-07 확정 설계) |
| **제목 이후의 H1** (본문 `#`) | 2레벨 견출 노드 — ChatGPT 내보내기처럼 본문 견출에 `#`을 쓰는 파일에서 견출이 사라지지 않는다 |
| `##` ~ `######` | 2~6레벨 노드 |
| **h1Mode** (사전 스캔에서 제목 외 본문 H1 발견 시) | `#`=2레벨, `##`=3레벨 … 한 단계씩 내려 `#`/`##` 계층을 보존 |

### 1.2 리스트

| 입력 | 결과 |
|---|---|
| `-` `*` `+` 불릿 | 마지막 견출(또는 아래 1.4의 기준)의 하위 노드. 들여쓰기 2칸/탭 = 한 단계 |
| `1.` `1)` 순번 | 하위 노드 — **번호("1. ")를 노드 텍스트에 그대로 유지** |
| **들여쓰기 없는 순번 항목 = "절 머리"** | 다음 순번/견출 전까지의 문단이 그 하위로 붙는다 (견출 없이 `1. 제목` + 본문 문단으로 쓰는 문서 — ChatGPT 답변 형식) |
| 리스트 항목의 **들여쓴 연속 줄** | 그 항목 노드의 추가 줄(`\n`)로 병합 (예: `1. 원본 파일 복사` 아래 `   예: 견적서.xlsx → …`) |

### 1.3 문단

| 입력 | 결과 |
|---|---|
| 첫 견출 전의 문단·인용문·표 | **루트의 노트** (머리말 처리 — 문단/표 노트) |
| 일반 문단 (연속 줄) | 한 노드로 합쳐 마지막 견출의 하위 (줄바꿈 유지) |
| **절 머리(1.2) 뒤의 문단** | 그 절 노드의 **자식** |

### 1.4 문단 뒤의 불릿

문단 바로 뒤의 불릿(`-`,`*`)은 **그 문단 노드의 하위**로 붙는다.

```md
Apache 설정 파일 수정 (`/etc/httpd/conf/httpd.conf`)

* DocumentRoot: 웹 문서 루트 디렉터리 설정
* DirectoryIndex: 기본 웹 페이지 파일명 설정
```
→ "Apache 설정 파일 수정 …" 노드의 자식으로 DocumentRoot / DirectoryIndex.

### 1.5 표

| 입력 | 결과 |
|---|---|
| `\| 셀 \| 셀 \|` 연속 행 | **직전 노드의 "표 노트"** (노드 내용이 아님) — 구분선(`\|---\|`)과 앞뒤 파이프를 제거해 "셀 \| 셀" 줄 형식으로 저장. 노트 뷰어(⊞)가 격자 표로 렌더링하며 셀 안 인라인 마커·링크도 서식으로 표시 |
| 첫 견출 전의 표 | 루트의 표 노트 |

### 1.6 인용문·코드

| 입력 | 결과 |
|---|---|
| `> 인용문` | 현재 노드의 **문단 노트** (원문 유지 — 노트 뷰어가 인라인 마커·`[라벨](url)` 링크를 서식/앵커로 렌더링) |
| ``` 코드 펜스 ``` | 현재 노드의 **코드 노트** (언어 표기 유지). 절 머리 뒤의 펜스는 그 절 노드의 코드 노트 |

### 1.7 하이퍼링크·이미지 — 3종 변환 규칙 (중요)

MD의 `[라벨](url)`은 **어디에 놓이느냐**에 따라 세 가지로 변환된다
(2026-07 확정 — ChatGPT 내보내기 실파일 기준):

| # | 위치 | 결과 |
|---|---|---|
| ① | **노트가 되는 텍스트** (인용문→문단 노트, 'note' 배치의 블록, A4 초과로 노트로 이동한 블록) | **원문 유지** — 노트 뷰어가 클릭 가능한 `<a>`로 렌더링 (예: ChatGPT 내보내기 머리말의 `**Link:** [url](url)` → 루트 노트에서 바로 클릭) |
| ② | **노드 본문이 되는 텍스트** (견출·리스트·문단→노드, **그리고 'node' 배치로 노드 본문에 들어간 인용문·표·체크 블록** — 2026-07 수정) | 텍스트에는 **라벨만** 남기고 URL은 **노드의 링크(🔗)로 첨부** (URL 중복 제거). 이전에는 블록 경로에서 `[라벨](url)` 원문이 노드에 그대로 노출됐음 |
| ③ | 노드에 첨부된 링크의 **표시** | 노드 오른쪽 **🔗 인디케이터** — 1개면 클릭 즉시 열기, 여러 개면 목록 팝업에서 선택 (예: AI 브라우징 인용 19개 링크 = 🔗 하나로 정리) |

세부:

| 입력 | 결과 |
|---|---|
| `[![배지](img)](url)` 중첩 | 대체 텍스트만 남기고 바깥 URL을 링크로 추출 |
| `![대체](http URL)` **원격 이미지** (2026-07) | **노드 사진(images)** 으로 첨부 + 대체 텍스트만 본문에. 한 줄 전체가 이미지 확장자 URL(`https://…png` 등)이어도 동일. 앱은 불러온 뒤 **다운로드해 data URL로 내장**(≤2MB, `remoteImages.ts`) — fetch 불가(CORS)면 원격 참조 유지, 그것도 실패하면 이미지를 빼고 **노드 링크(🔗)로 폴백** (URL은 잃지 않는다) |
| **이미지뿐인 문단** (모든 줄이 `![…](…)`/이미지 URL) | 자식 노드를 만들지 않고 **현재 노드의 사진**으로 붙는다 — 내보내기(견출 아래 `![…](…)`)의 왕복이자 기사 붙여넣기 규칙과 동일. 원격이 아닌 경로(`files/…`)는 메타데이터·ZIP이 실제 사진을 복원하므로 본문에서는 무시 |
| **`🔗 [라벨](url)` 문단** (2026-07) | 자식 노드가 아니라 **현재 노드의 링크(🔗)** 로 — 내보내기 형식의 왕복 (이전에는 "🔗 라벨" 잉여 자식 노드가 생겼음) |
| `![대체](상대 경로)` | 대체 텍스트만 남김 (경로가 본문 텍스트로 남지 않음) |
| **코드 펜스 안의 링크 문자열** | 원문 보존 (코드는 어떤 경로든 변형하지 않음) |

### 1.8 기타

| 입력 | 결과 |
|---|---|
| 인라인 강조 `**` `*` `~~` `__` `==` | 노드 텍스트에 그대로 저장 → 에디터가 인라인 마커로 렌더링 (마커 문자 숨김) |
| 백슬래시 이스케이프 (`1\.` `\-` 등) | 원래 문자로 해제 |
| `---` 수평선 | 무시 (절 머리·문단 앵커는 초기화) |

### 1.9 알려진 한계 (규칙 기반)

* 절의 마지막 마무리 문단("이제 … 할 수 있습니다")도 절의 자식이 된다
  — 절 종료 신호가 없음.
* `**굵은 소제목**` 문단은 아직 절 머리로 취급하지 않는다 — 필요 시
  "짧은 전부-굵게 문단 = 소제목" 규칙 추가 검토.

## 2. 맵 → MD 변환 규칙 (exportMarkdown) — 1과 왕복 대칭

| 맵 요소 | 출력 |
|---|---|
| 루트 | `# 제목` |
| 2~6레벨 노드 | `##` ~ `######` (7레벨+는 리스트 들여쓰기) |
| **노드 안 블록** (코드·표·체크 — 리치 노드, 2026-07) | 한 줄로 뭉개지 않는다 — 견출 = 첫 블록 앞의 일반 줄들(제목), 코드는 ``` 펜스, 표는 파이프 표(구분선 포함), 체크는 `- [x]`로 견출 **아래에 원문 순서대로**. 블록 **뒤**의 일반 줄(표 아래 "※ 첨부 …" 등)은 인용문(`>`)으로 — 'node' 배치로 다시 불러오면 노드 본문의 원문 순서가 복원된다 (`splitNodeBody`) |
| 블록 없는 노드의 줄바꿈 | 본문에서는 공백으로 합침 (원본은 메타데이터가 보존) |
| 블록으로 시작하는 노드 (표만 붙여넣은 노드 등) | 견출 제목이 없으므로 종류 라벨(`표`/`코드`/`체크리스트`)을 견출로 쓴다 |
| 노드 링크 | `🔗 [라벨](url)` — 다시 불러오면 노드 링크로 재추출 |
| 문단 노트 | `>` 인용문 |
| 코드 노트 | ``` 펜스 (언어 표기) |
| 표 노트 | 파이프 표 (헤더 다음 `\|---\|` 구분선 포함) |
| 루트 노트 | 제목 바로 아래 인용문·표·펜스 |
| 사진 | `![…](files/…)` + ZIP 패키징 (첨부 있으면 `제목.md + files/` ZIP) |
| 노드 인라인 사진 (`images[]` — 텍스트 중간, 기사 붙여넣기) | 노드 제목 아래 원문 **순서대로** `![…](…)` 나열 — MD에서 노드는 한 줄이라 "텍스트 중간" 위치(afterLine)는 표현하지 못하며, 위치 정보는 맵 메타데이터(easymindmap 주석)로만 복원된다. 사진은 붙여넣기 시점에 다운로드 내장(data URL)되므로 대부분 `files/img-N.*`로 ZIP 패키징된다 (CORS 차단 폴백 URL만 원본 주소 그대로) |
| 맵 메타데이터 | 파일 끝 주석 `easymindmap:v1:BASE64` — 다시 불러오면 스타일·노트·설정까지 복원 (22-map-file-meta.md) |

## 3. 검증 코퍼스 (E2E 상시 회귀)

> 4종 = 11케이스)와 기대 스냅숏(`expected/`), 러너(`npm test`). 파싱
