# Mindmap Markdown 정렬 — 불러오기·표시·내보내기 결정 기록

> **상태:** 결정 완료 (2026-09-15 ~ 2026-09-16), **구현 전**
> **대상 표준:** [mindmapmarkdown/spec](https://github.com/mindmapmarkdown/spec) — Draft, 0.1.0 목표 2026-10-05
> **관련 문서:** [`emm-spec.md`](emm-spec.md) · [`markdown-export.md`](markdown-export.md) · [`rich-node-content.md`](rich-node-content.md) · [`ai/emm-prompt-templates.md`](ai/emm-prompt-templates.md)

easymindmap이 Markdown을 **불러오고, 화면에 보여주고, 내보내는 방식**을 Mindmap
Markdown 표준에 맞추기 위해 항목별로 내린 결정이다. EMM은 표준 위에 올라가는
**프로파일**(맵 설정을 ```` ```emm ```` 블록으로 더하는 방식) 방향으로 정렬한다.

---

## 0. 먼저 읽을 것

### 0.1 표준이 정하는 것과 앱이 정하는 것

| 표준이 정한다 (트리) | 앱이 자유롭게 정한다 (화면) |
|---|---|
| 어떤 줄이 노드가 되는가 | 내용을 노드 본문으로 보일지 노트로 보일지 |
| 부모와 자식, 형제 순서 | 링크를 아이콘으로, 체크박스를 눌리는 상자로 그리기 |
| 노드 레이블의 원문 | 이름 없는 뿌리를 화면에서 어떻게 보일지 |
| 내용이 어느 노드에 붙는가 | 편집 칸에 원문을 보일지 다듬어 보일지 |

표준은 화면을 정하지 않는다(spec §1.1.2). 그래서 아래 결정의 대부분은 **"트리는
표준대로, 화면은 지금 모습을 최대한 유지"** 모양이다. 단, **내보낸 md가 원래 문서와
같은 트리가 되어야 한다**는 조건은 항상 지킨다.

### 0.2 결정 방식과 분석 기준

- 20개 사례를 EMM 파서(`node`·`note` 배치)와 표준 레퍼런스 구현(mindmapmd)에 실제로
  돌려 비교했다. 문서 문장만이 아니라 **실행 결과**를 근거로 했다.
- 항목 하나를 완전히 정한 뒤 다음으로 넘어갔다.
- **분석 기준 커밋은 `810dbef`(2026-09-15)** 다. 그 뒤 #485~#489가 불러오기·내보내기를
  바꿨다. 영향은 [§5](#5-결정-이후-바뀐-easymindmap)에 정리했고, **구현 전에 `origin/main`
  에서 사례를 다시 돌려 확인한다.**

### 0.3 폐기된 공통 원칙

결정 당시에는 "`easymindmap:v1` 메타데이터가 있는 파일은 지금 EMM 규칙으로 읽는다"를
모든 항목의 공통 원칙으로 두었다. **#489에서 메타데이터 주석과 v1 호환이 폐기되어 이
원칙은 더 이상 적용할 대상이 없다.** 아래 결정은 **모든 md에 그대로 적용**한다.

## 2. 트리 구조 (A)

### A-1. `#` 제목이 둘 이상인 문서

| 세부 | 결정 |
|---|---|
| 트리 규칙 | **표준을 따른다.** 대등한 `#`은 형제다. 본문 `#`을 한 단계 내리는 짐작(h1Mode)은 쓰지 않는다 |
| 중심주제 | **뿌리는 그리지 않고, 뿌리의 자식을 각각 중심주제로 표시한다** (ThinkWise 플로팅 노드 방식). `#` 하나뿐인 문서는 지금처럼 중심주제 1개 |
| 순서 | 중심주제 순서 = 문서 순서. 끌어 옮긴 위치는 맵 좌표로만 저장하고, md 순서는 아웃라인 등 **명시적 동작으로만** 바꾼다 |
| 편집 동작 | **"하나의 중심주제로 묶기"** 추가 (제목 없는 긴 목록 문서 대비), **"첫 번째 가지를 중심으로 올리기"** (회의록 모양 문서 대비) |
| 연결 없는 노드 | 어느 중심에도 붙지 않은 노드는 뿌리의 마지막 형제로 내보낸다. 노드 사이 관계선은 md에 쓰지 않는다 |

근거
- 파일 이름 같은 **가상 중심**을 지어내면 내보낼 때 빼는 예외가 필요하다(처음 결정안). 여러
  중심주제 방식은 지어낸 것이 없어 예외도 없다.
- 지금은 둘째 `#`을 첫째 밑으로 넣고 내보낼 때 `## 둘째`로 **파일을 바꿔 쓴다.** 제목 없는
  문서는 중심 "mindmap"을 지어내 `# mindmap`을 써넣는다.
- 회의록 모양(제목 `#` + 본문 `#`)과 대등한 `#` 문서를 파서가 구별하지 못한다. 짐작 대신
  사용자 동작으로 푼다.

알아둘 것: 맵 모델(`SampleMap`)은 지금 중심이 하나로 고정되어 있어 **제품 작업이 크다.**
목록 항목으로 들어온 중심주제 아래에는 `#` 제목 노드를 둘 수 없다(S-1).

### A-2. 헤딩 바로 뒤의 일반 문단

**표준을 따른다.** 문단은 노드가 아니라 그 헤딩의 내용이다. "안내 문장 + 리스트" 모양도
리스트는 헤딩 아래, 안내 문장은 헤딩의 내용이다. 화면(노드 본문·노트)은 A-8을 따른다.

근거: 코퍼스 문단 38개 중 29개를 지금 EMM이 노드로 만들고, 내보낼 때 `### 답변.` 같은
헤딩으로 바꿔 쓴다. AI 생성 문서는 설명을 `>` 인용문으로 쓰므로 영향이 거의 없다.

### A-3. 리스트 뒤에 들여쓰지 않고 쓴 문단

**표준을 따른다.** 바로 앞 노드, 곧 리스트 마지막 항목의 내용이다.

참고: 레퍼런스 구현 mindmapmd는 이 경우를 섹션에 붙이고 있어 사양과 다르다(별도 수정 과제).

### A-4. 체크리스트

- **기본은 표준.** `- [ ] 항목`은 항목마다 노드다(레이블 `[ ] 항목`). 화면은 레이블 앞
  `[ ]`·`[x]`를 눌리는 체크박스로 그린다.
- **사용자가 명시적으로 요청하면 노드 내용으로 붙인다.** 받는 곳은 두 가지이며, 불러오기
  창이 우선한다.
  - MD 불러오기 창: "체크리스트: 항목 노드로(기본) · 노드 내용으로"
  - `emm` 선언 키 `checklist: content` (AI 생성·손글씨·MCP 경로)
- "노드 내용으로" 모드에서 붙일 곳은 **체크리스트가 속한 헤딩(또는 부모 항목)** 하나로 고정한다.

알아둘 것: AI 점검표 맵은 기본이 항목마다 가지라 노드 수가 는다(프롬프트 규칙 8-1 조정 대상).

### A-5. 번호 리스트

- **번호를 목록 속성으로 보존한다.** 번호 항목에 CommonMark가 매기는 번호와 구분 기호
  (`.`·`)`)를 기록하고, 레이블은 번호 없는 글자다.
- 항목마다 쓴 숫자(`1. 1. 1.`)는 CommonMark도 버리므로 내보낼 때 `1. 2. 3.`으로 정리된다.
- 화면은 속성으로 번호를 그리고, 순서를 바꾸면 다시 매긴다.
- 표준 쪽: RFC 0039로 제안했다. **구현은 RFC 결과에 맞춘다.**

근거: 번호를 버리면 `- 2026. 1. 15. 오전 10:00` 같은 날짜 줄의 글자가 트리에서 사라진다.
지금 EMM은 번호 리스트를 헤딩(`## 1. 설치`)으로 바꿔 내보낸다.

### A-6. 번호 항목 뒤의 본문

A-3과 같은 규칙으로 **바로 앞 번호 항목의 내용**이다. 다시 1부터 시작하는 목록이 내보낸 뒤
앞 목록과 합쳐지지 않게 하는 방법은 RFC 0039가 정한다.

### A-7. 빈 헤딩

- **표준을 따른다.** 빈 헤딩(`##`)과 빈 목록 항목(`-`)은 **이름 없는 노드**이고, 하위 구조는
  그 아래에 둔다. 내보낼 때는 뒤 공백 없는 `##`·`-`.
- 화면에는 흐린 **"(제목 없음)"** 만 보여주고 이름으로 저장하지 않는다.

`810dbef` 기준으로 빈 노드가 왕복에서 사라지고 하위가 한 단계 올라가는 버그가 있었다. #485가
이것을 고쳤다(§5).

### A-8. 인용문·코드·표·사진

| 세부 | 결정 |
|---|---|
| 인용문이 제목에 합쳐지는 것 | 고친다. 인용문은 내용 블록이다 |
| 코드·표·사진·문단·인용문 | 자식 노드가 아니라 그 노드의 **내용 블록** |
| 저장 방식 | 노드를 **제목**과 **내용 블록 목록**으로 분리. 블록마다 **종류·원래 글자**(`>`, 표 구분선·정렬, 코드 울타리 포함)·**순서**를 저장. A4 초과로 노트로 옮긴 블록도 원래 순서를 기억 |
| 화면 | **노드 본문 안이 기본**, "노트로" 선택지 유지. 노드에 딸린 별도 블록 상자는 나중 과제 |

근거: 원래 글자를 저장하면 원본과 같게 내보낸다. `810dbef` 기준 "노드로" 모드는 문단과
인용문을 한 글자로 합쳐 자식 노드로 만들고 `### …` 헤딩으로 내보냈으며, 표 정렬(`:---`)을
지웠다.

## 3. 노드 글자 (B)

### B-1. 링크

- 레이블은 원문 `[가이드](https://…)` 그대로 저장·내보내기.
- **링크가 노드 글자 전체 하나뿐일 때**(대부분): 화면은 "가이드" + 링크 아이콘(지금 그대로),
  편집 칸에는 "가이드"만, 주소는 링크 편집 창에서.
- **글자 일부만 링크이거나 링크가 둘 이상일 때**: 해당 단어를 밑줄 링크로 그리고, 편집 칸에는
  원문을 보인다.

근거: 지금은 `[A사](…)와 [B사](…) 비교`가 "A사와 B사 비교" + 주소 2개로 나뉘어, 어느 단어에
어느 주소였는지 사라진다.

### B-2. 이스케이프

- 저장·내보내기는 원문(`1\. 단계`) 그대로.
- 맵 화면에서는 `\`를 숨긴다.
- 편집 칸: **줄 맨 앞 표지**(`1\.`·`\-`·`\#` 등)는 숨기고 저장할 때 앱이 다시 붙인다. **글자
  중간 이스케이프**(`\*`·`\_` 등)는 원문을 보인다 — 숨기면 기울임 명령인지 글자인지 구별할
  수 없다.
- 사용자가 직접 "1. 단계"를 입력하면 저장할 때 `1\. 단계`로 바꾼다.

근거: `810dbef` 기준 불러올 때 `\`를 지우고 내보낼 때 붙이지 않아, 다른 도구에서 `*별표*`가
기울임으로, 깊은 노드의 "1. 단계"가 번호 목록으로 바뀌었다.

표준 쪽: 이 과정에서 "레이블에 어떤 글자가 들어가도 되는가" 규칙이 없다는 빈틈을 찾아
[#42](https://github.com/mindmapmarkdown/spec/issues/42)와 RFC 0043(S-7)으로 올렸다. 앱이 `\`를
붙이는 것이 그 규칙을 지키는 방법이다.

### B-3. 항목 안 들여쓴 문단

A-8 결정으로 해결된다(그 항목의 내용 블록).

## 4. 문서 수준 (C)

### C-3. EMM 선언 형식

**```` ```emm ```` 코드블록을 유지한다.** front matter에 `emm:` 키를 두지 않는다.

| 이유 | 설명 |
|---|---|
| 다른 뷰어 | 코드블록은 어디서나 코드 상자로 깔끔하게 보인다 |
| 다른 도구와 충돌 | front matter는 Obsidian·Hugo가 쓰는 자리라 키가 섞인다 |
| AI 재작성 | 코드블록이 다시 써낸 문서에서 살아남기 쉽다 |
| 해석 범위 | 정해진 키만 읽으면 되고 임의의 YAML을 해석하지 않는다 |

**앱이 만드는 맵은 md에 `emm` 블록 하나만 새로 쓴다.** 머리말·front matter는 만들지 않고,
설명 글은 중심주제의 노트에 쓴다.

### C-1. front matter · C-2. 첫 헤딩 앞 머리말

불러온 파일에 있던 것은 **원래 자리에 원래 모양 그대로 보존하고, 내보낼 때 되돌려 쓴다.**

- `emm` 블록 안으로 옮기지 않는다. 옮기면 Obsidian 태그·Hugo 제목과 날짜가 사라지고, 본문이
  코드 상자로 보이며, 표준 왕복이 깨진다.
- 머리말을 첫 헤딩 노드의 노트로 넣지 않는다. 중심주제 자신의 내용(헤딩 뒤)과 섞이면 어느
  줄을 헤딩 앞에 쓸지 알 수 없고, 중심주제가 여럿이면 어느 것의 것도 아니다.
- 머리말 블록 사이에 `emm` 블록이 있으면 원래 위치를 기억해 그 자리에 다시 쓴다.
- 블록을 알아보는 조건(첫 줄 `---`, 그 뒤 처음 나오는 `---`에서 닫힘)은
  [`frontMatter.ts`](../../packages/emm-parser/src/frontMatter.ts)가 이미 표준 L-10과 같다.
  바꿀 것은 **버리던 원문을 보관하고 다시 쓰는 것**이다.

**문서 속성 패널**
- 평소에는 **"맵 설정(EMM)"만** 보인다.
- 불러온 파일에 머리말·front matter가 있을 때만 "다른 도구의 정보가 보존되어 있습니다" 칸이
  나타나고 **보기만** 가능하다. 편집은 요청이 있을 때 나중에 더한다.
- 맵에는 "머리말 있음" 같은 작은 표시를 둔다.

근거: `810dbef` 기준 front matter는 잘라낸 뒤 버리고, 머리말은 첫 헤딩의 노트가 되어 내보낼 때
**헤딩 아래 `>` 인용문으로** 옮겨졌다.

## 7. 구현 순서 제안

RFC 결과가 모두 나온 뒤(2026-10 초) **한 번에** 반영한다. RFC가 바뀌면 같은 코드를 두 번
고치게 되기 때문이다.

| 단계 | 할 일 | 사용자에게 보이는 변화 |
|---|---|---|
| 1 | 사례 재확인 — §5 이후 `origin/main`에서 20개 사례를 다시 돌리고, 표준 적합성 스위트(`examples.json`)와 불러오기 결과를 비교 | 없음 |
| 2 | 저장 모델 — 제목 + 내용 블록 목록(A-8), 번호 속성(A-5), 문서 수준 보존(C-1·C-2) | 없음 |
| 3 | 불러오기·내보내기를 표준 규칙으로 (A-2·A-3·A-4·A-6·A-7, B-1·B-2 원문 보존) | 파일 모양이 원본대로 돌아온다 |
| 4 | 화면 — 링크 표시, `\` 숨김, 체크박스, "(제목 없음)", 문서 속성 패널 | 작다 |
| 5 | 여러 중심주제(A-1) — 모델·레이아웃·저장 구조 변경 | `#`이 여럿인 문서의 모양 |
| 6 | AI 프롬프트 규칙 8(번호)·8-1(체크리스트) 조정 | AI가 만드는 맵의 모양 |
