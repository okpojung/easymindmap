# 27. Publish / Share (퍼블리싱)

> ✅ **1단계 구현됨** (2026-09-04, PUBL-01~05). 무료 퍼블리싱 — 링크를 가진 사람이 로그인 없이 **읽기 전용**으로 본다.
> 서버는 `apps/api/src/publish/`, 화면은 `apps/frontend/src/pages/PublicMapPage.tsx` 와 `components/cloud/PublishPanel.tsx` 다.
> 비밀번호 보호·임베드는 여전히 2단계다(§12).

> **유료 퍼블리싱**(수수료·정산·미리보기)은 [`27a-paid-publish.md`](27a-paid-publish.md) 다. 이 문서의 `published_maps` 와 공개 URL 을 그대로 쓰고 그 위에 값을 매긴다.

> ★ **용어: "공개" 가 아니라 "퍼블리싱"** (2026-09-05 사용자 결정).
> 이 서비스에서 하는 일은 "친구에게 보여 준다" 가 아니라 **완성된 콘텐츠를
> 세상에 내놓는 것**이다 — 내 홈페이지에 거는 일, 나중에는 파는 일이다.
> 그래서 화면·오류 문장·문서에서 행위와 상태는 모두 **퍼블리싱**으로 쓴다
> (퍼블리싱 등록 · 퍼블리싱 중 · 퍼블리싱 취소 · 퍼블리싱맵 · 퍼블리싱 문서함).
> 결과물의 성질을 가리키는 **공개 URL · 공개 뷰**(로그인 없이 열린다)는
> 그대로 둔다 — 그건 행위가 아니라 그 주소가 어떤 주소인지의 설명이다.

### 1. 기능 목적

* **완성된 맵**을 공개 URL 로 퍼블리싱하여 **로그인 없이 읽기 전용 접근**을 허용하는 기능
* 내 홈페이지 게시, 포트폴리오, 외부 공유 — 나중에는 **콘텐츠 판매**의 앞단(`27a`)
* 언제든 **비공개(보관)** 로 내릴 수 있고(주소는 유지), **등록 취소**로 아주 내릴 수도 있다(주소 소멸, §6.4)

### 4. 기능 정의 (What)

#### 4.1 published_maps 테이블

```sql
CREATE TABLE public.published_maps (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  map_id          UUID NOT NULL REFERENCES public.maps(id) ON DELETE CASCADE,
  publish_id      VARCHAR(20) UNIQUE NOT NULL,   -- URL slug (랜덤 8~12자)
  storage_path    VARCHAR(500),                  -- Supabase Storage 경로 (선택)
  published_at    TIMESTAMPTZ DEFAULT NOW(),
  unpublished_at  TIMESTAMPTZ                    -- NULL = 현재 퍼블리싱 중
);

CREATE INDEX idx_published_maps_publish_id
  ON public.published_maps(publish_id);
```

#### 4.2 공개 URL 구조

```
https://easymindmap.com/p/{publish_id}

예시: https://easymindmap.com/p/xK9mR3qT
```

#### 4.3 퍼블리싱 상태 확인 로직

```typescript
// 유효한 퍼블리싱 여부
const isPublished = (pm: PublishedMap): boolean =>
  pm.unpublished_at === null;
```

#### 4.4 공개 뷰 UI

### 5. 동작 방식 (How)

#### 5.1 사용자 동작

* 툴바 `[퍼블리싱]` > `퍼블리싱하기` 클릭
* `publish_id` 생성 → 공개 URL 표시
* `[링크 복사]` 버튼으로 클립보드 복사
* 잠시 내리기: `[퍼블리싱]` > `🔒 비공개(보관)` → `visibility='private'` → 남에게만 404 (**주소 유지 · 편집 가능**)
* 아주 내리기: `[퍼블리싱]` > `퍼블리싱 취소` → `unpublished_at` 설정 → URL 즉시·영구 차단

#### 5.2 공개 맵 로딩 흐름

```
GET /published/{publishId}  (비인증 접근)
    │
    ▼
published_maps 조회 (publish_id = publishId, unpublished_at IS NULL)
  ├─ NOT FOUND / unpublished → 404 페이지
  └─ FOUND
         │
         ▼
    map + nodes 조회 (RLS: published 맵은 anonymous 읽기 허용)
         │
         ▼
    읽기 전용 뷰 렌더링 (편집 UI 비활성)
```

#### 5.3 퍼블리싱 등록 취소 흐름

```
DELETE /maps/{mapId}/publish
    │
    ▼
published_maps.unpublished_at = NOW()   (활성 행 전부)
    │
    ▼
이후 /published/{publishId} 접근 → 404
       그 맵의 공개 사진 주소도 함께 404
```

이미 취소돼 있어도 **성공(204)** 이다. 취소는 상태를 맞추는 일이지 한 번만
할 수 있는 일이 아니다.

**잠시 내리는 것은 이것이 아니다** — `PATCH …/publish {visibility:'private'}` 다.
둘을 한 버튼에 두면 "고치려고 내렸다가 링크를 잃는" 사고가 생긴다(§6.4).

#### 5.4 공개 화면이 그리는 방식 — **내보내기 뷰어를 그대로 쓴다**

```
GET /published/{publishId}  →  { title, doc, publishedAt }
    │                           doc = 저장 스냅샷 { v, map, editor }
    ▼
map 안의 서버 첨부 주소를 **공개 주소로 바꾼다**
    /v1/attachments/{id}  →  /v1/published/{publishId}/attachments/{id}
    ▼
buildStandaloneHtml(map, …)  — Standalone HTML 내보내기와 **같은 함수**
    ▼
<iframe srcDoc sandbox="allow-scripts allow-popups …">
```

**에디터(`Canvas`)를 읽기 전용 모드로 재사용하지 않았다.** Canvas 는 문서
스토어와 깊게 얽혀 있어 "읽기 전용" 이 플래그 하나로 지켜지는 성질이
아니다 — 저장·자동저장·잠금 경로가 하나라도 남으면 남의 맵을 고칠 수 있게
된다. 뷰어에는 **애초에 그 코드가 실려 있지 않다.**

`sandbox` 에 `allow-same-origin` 을 주지 않는다. 남이 쓴 글이 데이터로
박히는 화면이므로, 무슨 일이 있어도 우리 오리진에 닿지 못하게 한다.

### 6. 규칙 (Rule)

* `publish_id`: 랜덤 영숫자 12자 (URL-safe, 혼동 글자 제외)
* 공개 뷰: 인증 불필요 (Anonymous 접근)
* 공개 뷰: 읽기 전용 — 편집, 노드 추가/수정/삭제 불가
* 비공개 전환·등록 취소 **즉시** 반영 (CDN 캐시 고려 시 최대 5분)
* 한 맵에 활성 링크는 **1개** (§6.1)

#### 6.0 한 문장 — **공개한 맵은 완성본이다** (2026-09-05 사용자 결정)

> 퍼블리싱은 "친구에게 보여 주기" 가 아니라 **내 홈페이지에 콘텐츠를
> 올리는 일**이다. 그 한 문장에서 아래 규칙이 전부 따라 나온다.
>
> | 규칙 | 왜 |
> |---|---|
> | 단독맵만 퍼블리싱한다 (§6.1) | 협업 중 = 아직 완성 전 |
> | **공개 중**에는 못 고친다 (§6.2) | 세상에 걸린 물건은 안 바뀐다 |
> | 퍼블리싱 등록된 맵은 협업맵이 될 수 없다 (§6.3) | 상품은 저자 한 사람의 것 |
> | 상태를 오가도 **주소는 그대로** (§6.4) | 홈페이지에 건 링크가 안 죽는다 |
> | 주소를 죽이는 것은 **등록 취소** 하나 (§6.4) | 내린 것과 잠시 내린 것은 다르다 |

> ★ **등록과 노출은 다른 일이다** (2026-09-05 사용자 결정).
>
> ```
> 완성된 맵          ──[퍼블리싱 등록]──▶   퍼블리싱 문서함
> (내 문서함)                              { 비공개(보관) · 무료공개 · 유료공개 }
>                    ◀──[등록 취소]────    ← 주소가 죽는다
> ```
>
> 쇼핑몰이 상품을 등록해 두고 **아직 노출하지 않을 수 있는** 것과 같고,
> 유튜브의 비공개/공개와도 같다. 주소(`publish_id`)는 **등록**에 붙으므로
> 상태를 오가도 그대로다.

#### 6.1 ★ **단독맵만 퍼블리싱한다**

> 이유가 둘이다.
>
> ⑴ **완성도** — 협업 중이라는 것은 **아직 완료되지 않은 맵**이라는 뜻이다.
> 여럿이 아직 고쳐 가는 문서를 세상에 걸어 두면, 보는 사람은 완성된 글로
> 읽는데 실제로는 매 순간 달라진다.
>
> ⑵ **유료 퍼블리싱의 수익 배분** — 협업맵을 팔 수 있게 두면 **참여자 여럿의
> 몫을 어떻게 나눌지**부터 정해야 한다. 지분·기여도·탈퇴자 처리까지
> 따라온다. 단독맵만 파는 한 그 문제가 **아예 생기지 않는다**
> ([`27a-paid-publish.md`](27a-paid-publish.md) §5.0).
>
> 서버가 막는다(`403`). 화면은 **누르기 전에** 이유를 말한다 —
> 규칙도 문장도 서버가 갖는다(`publishable` · `blockedReason`).
>
> **1단계 정책**: 맵 1개당 활성(active) 공개 링크는 **1개**다. 다중 활성
> 링크는 V2 이후로 분리한다.
>
> ★ **`POST /publish` 는 멱등이다** (2026-09-04). 이미 퍼블리싱 중이면
> **그 링크를 그대로 돌려준다.** 부를 때마다 새 링크를 뽑으면 버튼을 두 번
> 누른 것만으로 **이미 남에게 보낸 링크가 조용히 죽는다.**

#### 6.2 ★ **공개하는 동안에는 고칠 수 없다** (2026-09-05 사용자 결정)

주인이라도 못 고친다. 고치는 순서는 **비공개(보관)로 돌린다 → 고친다 →
다시 공개**다. **주소는 그동안 그대로다.**

> "완전히 편집이 끝난 완성된 맵을 내 홈페이지에 게시하거나, 완성된 맵을
> 콘텐츠로 판매를 위해 온라인에 올려 놓는 개념이다." — 사용자, 2026-09-05

* 잠그는 기준은 **"등록됐다" 가 아니라 "지금 남이 보고 있다"** 이다.
  보관(비공개) 상태에서는 **고칠 수 있다** — 그것이 상태를 나눈 이유다
  (쇼핑몰에서 노출을 내리고 상품을 손보는 것과 같다).
* 서버가 막는다 — `PUT /maps/{id}/document` 가 **403**
  (`maps.service.ts` `saveDocument` → `isPublicallyVisible`). 자동저장도
  같은 문으로 막힌다.
* **그래서 화면이 먼저 잠긴다.** 공개한 그 순간 이 탭도 읽기 전용이
  된다(`PublishPanel.lockThisTab`). 화면이 이것을 모르면 사용자는 계속
  고치다가 **자동저장이 403 을 만날 때에야** 안다 — 그때는 이미 그 편집이
  갈 곳이 없다. 비공개로 되돌리면 자물쇠도 함께 풀린다.
* ★ **읽기 전용이 되어도 `[퍼블리싱]` 버튼은 살아 있다.** 공개하면
  `cloudMapId` 가 비워지는데, 툴바가 그 값만 보고 버튼을 잠그면 **켤 수는
  있고 끌 수는 없는 스위치**가 된다 — 되돌릴 문이 사라진다.
  (`TopToolbar.publishMapId`, e2e205-05 가 이 회귀를 못 박는다.)

#### 6.3 ★ **퍼블리싱 등록된 맵 ↔ 협업맵은 상호 배제** (2026-09-05 사용자 결정)

| 방향 | 결과 | 막는 곳 |
|---|---|---|
| 협업맵 → 퍼블리싱 등록 | 403 | 코어 `publish.service.ts` |
| 등록된 맵 → 협업맵(`PATCH kind`) | 403 | 코어 `maps.service.ts` |
| 등록된 맵에 참가자 초대 · 초대장 수락 | 409 | 유료 `members.service.ts` · `invites.service.ts` |

**양쪽을 다 막아야 규칙이 닫힌다.** 한쪽만 막으면 "퍼블리싱해 두고 초대"
라는 우회로가 남아, 아직 완성되지 않은 문서가 퍼블리싱된 채로 여럿이
고치는 상태가 만들어진다 — 그게 §6.1 이 막으려던 바로 그것이다.

★ **보관(비공개) 중이어도 막는다.** 여기가 지키는 것은 §6.2 와 달리
"지금 남이 보고 있는가" 가 아니라 **"이것은 상품인가"** 다 — 퍼블리싱
문서함에 든 맵은 **저자 한 사람의 것**이라야 수익 배분 문제가 아예 생기지
않는다([`27a`](27a-paid-publish.md) §5.0). 그래서 상태가 아니라
**등록 여부**(`isRegistered`)를 본다.

되돌릴 길은 열려 있다: **등록을 취소하면** 협업맵으로 바꿀 수 있다.
그래서 안내가 "먼저 퍼블리싱을 취소해 주세요" 로 끝난다.

#### 6.4 ★ **주소는 등록에 붙는다 — 상태를 오가도 그대로** (2026-09-05 사용자 결정)

| 하는 일 | 주소 | 남에게 | 편집 |
|---|---|---|---|
| 퍼블리싱 등록 (비공개) | 생긴다 | 404 | **된다** |
| 무료공개 | **그대로** | 열린다 | 안 된다 |
| 다시 비공개(보관) | **그대로** | 404 | **된다** |
| 등록 취소 | **죽는다(영구)** | 404 | 된다 |
| 다시 등록 | **새 주소** | — | — |

**한 번 개정한 규칙이다.** 처음에는 "중단하면 주소가 영구히 죽는다" 로
정했고, 이유는 하나였다:

> **중단이 "잠시 고치려고" 인지 "이제 그만" 인지 시스템은 알 수 없다.**

상태를 셋으로 나눈 지금은 **사용자가 직접 말해 준다** — 잠시 내리는 것은
`비공개(보관)`, 그만두는 것은 `등록 취소`다. 알 수 없던 것이 알 수 있게
됐으므로 추측할 일이 없어졌고, 그래서 규칙을 바꿨다. 홈페이지에 걸어 둔
링크가 **오탈자 하나 고치는 동안 죽지 않는다.**

* 미리보기 실루엣과 **사진·첨부도 같은 문으로** 열리고 닫힌다 — 보관으로
  돌리면 본문과 **같은 순간에** 사진도 닫힌다. 한쪽만 닫으면 주소를 아는
  사람이 사진으로 내용을 짐작한다.
* 보관 중인 주소의 404 문장은 **없는 링크와 같다** — 구분하면 "그런 주소가
  있긴 하다" 는 사실을 알려 주는 셈이다.
* `유료공개`는 칸에는 있지만 **아직 준비 중**이다(400 + 이유). 값·결제·
  정산이 없는데 "유료공개" 라고 표시해 두면 **저자가 팔았다고 믿는** 상태가
  된다 ([`27a`](27a-paid-publish.md) §3·§6).
* `visibility` 칸이 없는 서버(델타 미적용)에서는 **모두 무료공개**로 돌고
  전환만 꺼진다 — 지금까지의 동작 그대로다. 화면은 `canSetVisibility:false`
  를 보고 전환 단추를 아예 그리지 않는다.

### 7. 예외 / 경계 (Edge Case)

* **닫힌 URL 접근**: 404 "페이지를 찾을 수 없습니다" 안내. **보관(비공개)** 도,
  **등록 취소** 도, 없는 링크도 **같은 화면**이다 (§6.4)
* **없는 링크 / 취소된 링크 / 지워진 맵**: 셋을 **구분하지 않는다.**
  구분하면 "그런 링크가 있었다"는 사실을 알려 주는 셈이다.
* **슬러그 모양이 아닌 요청**: DB 에 묻지도 않고 400. 공개 경로라 아무나
  두드릴 수 있다.
* **맵 삭제 시**: 우리 삭제는 **soft-delete**(`deleted_at`)라 CASCADE 가
  돌지 않는다 — 조회에서 `m.deleted_at IS NULL` 로 **직접 막는다.**
  이걸 빠뜨리면 휴지통에 있는 맵이 계속 공개된다.
* **퍼블리싱 표가 없는 서버**(델타 미적용): 퍼블리싱 기능만 꺼진다.
  상태 조회는 **오류가 아니라 값**(`available:false`)으로 답하고, 화면은
  그 값을 보고 버튼 대신 안내를 보여 준다 — 눌러 보고 나서야 실패를
  만나지 않게. 맵 열기·저장은 그대로 동작한다.
* **대형 맵 공개 뷰**: 스냅샷 하나를 통째로 준다(뷰어가 그린다).
* **공개 중 저장 시도**: 403 — 자동저장까지 막힌다. 그래서 화면은
  공개한 **그 순간** 읽기 전용으로 바뀐다(§6.2). **보관 중에는 막지 않는다.**
* **`visibility` 칸이 없는 서버**: 퍼블리싱은 그대로 돌고 **전환만** 꺼진다.
  전환 요청은 **503 + 어느 칸인지**를 말한다(500 이 아니다).
  `GET /publish-status` 가 `canSetVisibility:false` 로 미리 알려 준다.

### 10. API 영향

* `POST /maps/{mapId}/publish` — 퍼블리싱 **등록** (**멱등** — 이미 등록돼
  있으면 그 링크). 몸체에 `{"visibility":"private"}` 을 주면 보관으로
  등록한다(기본은 `public`). 등록을 취소한 뒤 다시 부르면 **새 주소**다
* `PATCH /maps/{mapId}/publish` — **상태 전환** `{"visibility":"private|public"}`.
  **주소는 그대로다** (§6.4). 등록돼 있지 않으면 404,
  `paid` 는 400(준비 중), 칸이 없는 서버는 503
* `DELETE /maps/{mapId}/publish` — 퍼블리싱 **등록 취소** (unpublished_at 설정,
  멱등). **이것만이 주소를 죽인다**
* `GET /maps/{mapId}/publish-status` — 퍼블리싱 상태 조회 (`publishable`·`blockedReason` 포함)
* `GET /published/{publishId}` — 공개 맵 데이터 조회 (**비인증**)
* `PUT /maps/{mapId}/publish/preview` — 미리보기 실루엣 올리기 (맵 주인만).
  그림은 **저자의 브라우저가 만든다** — `27a-paid-publish.md` §2
* `GET /published/{publishId}/preview.png` — 미리보기 실루엣 (**비인증**).
  링크 카드·목록 썸네일이 이 주소를 쓴다
* `GET /published/{publishId}/attachments/{attachmentId}` — 공개된 맵의
  사진·첨부 (**비인증**). 이 문이 없으면 공개된 맵은 **사진 자리마다 깨진
  채로** 열린다 — 사진은 대부분 서버 저장소에 있고 원래 주소는 인증을
  요구한다. 여는 조건은 좁다: 그 첨부가 **그 맵의 것**이고, 그 맵이
  **지금 그 링크로 퍼블리싱 중**이며, 휴지통에 있지 않아야 한다.

> **경로 정리**: 라우팅 레벨에서는 `/p/{publishId}` 단축 형태를 사용할 수 있으나, **API 엔드포인트 기준은 `GET /published/{publishId}`로 통일**한다. (`api-spec.md` v2.3 §8 기준)

| 탭 잠금 | `PublishPanel.lockThisTab()` · `TopToolbar.publishMapId` |

남은 제약 — **지금은 이렇게 동작한다**는 사실이지 버그가 아니다.

* **검색엔진 대비가 없다.** `<meta>` · Open Graph · `robots.txt` 를 넣지
  않았다. 링크를 붙여넣어도 미리보기 카드가 뜨지 않고, 크롤러가 본문을
  읽지도 못한다(내용은 브라우저가 그린다).
  **카드에 넣을 이미지는 준비됐다**(`preview.png`, 2026-09-05) — 남은 것은
  `/p/*` 에 맵마다 다른 `<head>` 를 내주는 자리다. 지금은 nginx 가 모든
  주소에 `index.html` 하나를 준다(실측: 크롤러가 받는 `<title>` 이 모든
  맵에서 `EasyMindMap · Editor` 다). 네이버는 자바스크립트를 실행해 제목을
  읽어 가지만, 카카오톡·슬랙 등 대부분은 원본 HTML 만 읽는다.
* **조회수·방문자 통계가 없다.**
* **유효기간이 없다.** 링크는 저자가 [퍼블리싱 취소] 를 누를 때까지 산다.
  기간을 두는 대신 **문서함이 퍼블리싱 중인 맵을 늘 보여 주는 쪽**을 골랐다
  (PUBL-05) — "잊고 퍼블리싱해 둔다" 는 문제는 만료가 아니라 **보이지 않음**
  에서 왔기 때문이다. 필요해지면 `expires_at` 한 칸을 더하고 조회에
  조건 하나를 붙이면 된다(워커 없이 된다).
* **공개 화면에 "이 맵 복제하기" 가 없다.** 보는 것뿐이다.
* **퍼블리싱한 맵을 모아 보는 자리가 아직 없다.** 지금은 문서함 목록에
  `🌐 퍼블리싱맵`(공개 중) · `🔒 보관중` 배지로 섞여 보인다. 쇼핑몰처럼
  **따로 관리하는 화면**(퍼블리싱 문서함)은 다음 작업이다 —
  `27a-paid-publish.md` §0.3.
* **유료공개는 아직 못 고른다.** 칸에는 있고 API 는 400 + 이유를 준다.
  값·결제·정산이 붙는 자리는 `27a` §3·§5·§6 이다.
* **CDN 캐시를 쓰지 않는다** — 중단이 곧바로 반영된다(§6 의 "최대
  5분" 은 CDN 을 끼웠을 때의 이야기다).
