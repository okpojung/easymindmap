## 1. 현재 노드가 이미 담을 수 있는 것

| 콘텐츠 | 노드 본문 | 비고 |
|---|---|---|
| 여러 줄 텍스트 | ✅ | 자동 줄바꿈 + 수동 \n |
| 인라인 강조 | ✅ | 굵게·기울임·취소선·밑줄·하이라이트·**코드**(2026-07) |
| 사진 | ✅ | 텍스트 중간 인라인 포함, data URL 내장 |
| **표** | ✅ | Markdown 표를 노드 안에 격자로 렌더(mdTable) |
| 코드 블록(여러 줄) | ❌ | 노트로만 |
| 체크박스 | ❌ | 노트로만 |
| 문단(장문) | △ | 텍스트로 가능하나 붙여넣기 시 정책에 따라 노트로 감 |

→ 격차는 **코드 블록**과 **체크박스** 두 가지다. 표는 이미 되고,
문단은 "배치 정책"의 문제다.

## 2. 제안 설계

### 2.1 노드 본문 블록 (에디터·뷰어 파리티)

- **코드 블록**: 노드 텍스트 안 ``` 펜스 구간을 모노스페이스 + 회색
  패널로 렌더(표(mdTable)와 같은 방식의 블록 레이아웃).

> **글자 격자 배치 (2026-08-05, `utils/monoGrid.ts`)** — 코드 줄은
> 글자마다 x 를 계산해 **격자 칸**에 앉힌다(한글·한자·가나·전각기호
> 2칸, 나머지 1칸 — 터미널 wcwidth 관례). `ui-monospace` 계열에는
> 한글 글리프가 없어 시스템 한글 폰트로 폴백되는데 그 폭이 ASCII 칸의
> 정수배가 아니라서, 한글이 섞인 줄만 짧아져 상자 도식이 어긋났다.
> 격자 배치는 **폰트를 내려받지 않고** 이 문제를 없애고, 폰트가 없는
> 다른 PC에서 내보낸 HTML 을 열어도 결과가 같다. 에디터 SVG·HTML
> 뷰어는 x 리스트로, 아웃라인·칸반·노트 팝오버는 글자별 inline-block
> 폭으로 같은 격자를 만든다. 검증 e2e98(오른쪽 끝 x 실측).
- **체크박스 줄**: 노드 텍스트의 `- [x] …` 줄을 체크박스 글리프로 렌더,
  클릭 시 토글(에디터) / 뷰어는 읽기 전용.
- 기존 표 렌더(mdTable) 프레임을 재사용해 "노드 내 블록" 공통 레이아웃
  으로 일반화한다.

### 2.2 MD 불러오기 배치 옵션

불러오기 대화상자에 선택 추가 (기억됨):

| 옵션 | 동작 |
|---|---|
| **노드로 (기본)** | **경계가 확실한 블록(코드 펜스·표·이미지)은 각각의 자식 노드로 분리** (2026-07-31 개정 — markmap 파리티). 인용문·체크는 현재(또는 직전 블록) 노드의 본문 줄로 |
| 노트로 | 현재와 동일 — 문단=문단 노트, ```=코드 노트, 표=표 노트, `- [x]`=체크 노트 |

파서에는 `blockPlacement: 'node' | 'note'` 옵션으로 전달 — **파서 API
기본은 `note`(하위 호환), 앱 불러오기 UI 기본은 `node`** (§3 P3 와 동일).
EMM 왕복: 블록 노드는 종류 라벨 견출(`표`/`코드`) + MD 블록으로
직렬화되고 enrich가 같은 키로 복원하므로 손실 없음. 규칙 상세와
"분리 vs 한 덩어리" 원칙: markdown-export.md §1.0.

**AI 생성 5개 경로도 2026-08-04부터 `'node'` 로 통일**됐다 — EMM
프롬프트 템플릿 v4 규칙 4(블록 출력)와 한 쌍이다.

### 2.3 노드 분량 제한 — "A4 한 장"

노드가 문서화되는 것을 막는 안전선. 근사 기준:

- 텍스트: **2,500자** (A4 1장 분량 근사) — 이미지 1장 = 600자로 환산
- 초과 시: 넘치는 블록부터 **자동으로 노트로 이동** + "A4 분량을 넘어
  노트로 옮겼습니다" 안내 (데이터는 잃지 않는다)
- 편집 중 실시간 카운트는 두지 않는다(소음) — 불러오기·붙여넣기 시점만 적용
